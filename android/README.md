# 안드로이드 셸

TeamFlow 화면을 감싸는 **얇은 껍데기**입니다. 화면 코드는 하나도 여기
없습니다 — `frontend/public` 을 그대로 띄웁니다.

## 왜 이게 있는가

이 프로젝트의 1순위 위험은 **폰이 회의 끝까지 녹음을 유지하지 못하는
것**입니다 (`docs/09` 실험 5). 모드 A(멀티트랙)는 팀원 각자의 트랙이
살아 있어야 성립하는데, 브라우저 탭은 그 보장을 주지 않습니다.

    안드로이드 크롬 탭   화면이 꺼지거나 다른 앱으로 넘어가면
                       타이머·미디어가 조여집니다. `MediaRecorder` 가
                       멈추는 시점은 기기·제조사 설정마다 다릅니다.

    포그라운드 서비스    알림이 계속 떠 있는 대신 **시스템이 죽이지
                       않습니다.** `microphone` 타입을 선언하면
                       화면이 꺼져도 마이크가 살아 있습니다.

셸이 하는 일은 그것 하나입니다. WebView 를 포그라운드 서비스가 있는
프로세스 안에서 돌려서, **이미 테스트된 `src/lib/recording/` 코드를
그대로 쓰면서** 녹음이 끊기지 않게 합니다. 녹음 로직을 코틀린으로
다시 쓰지 않습니다 — 그러면 시계 동기화·타임라인·공백 판정 160개
테스트를 두 벌 유지해야 합니다.

## 비용

**0원입니다.** APK 를 직접 만들어 폰에 넣습니다(사이드로드).
Google Play 등록($25)은 하지 않습니다 — 팀원 서너 명이 쓰는 데
스토어가 필요 없습니다.

아이폰은 이 셸을 못 씁니다. Apple Developer Program 이 연 $99 이고,
무료 프로비저닝은 7일마다 재설치해야 해서 발표 당일에 위험합니다.
**아이폰 팀원은 PWA 로 참여합니다** — 홈 화면에 추가하면 화면 꺼짐
방지가 브라우저 탭보다 잘 듣습니다(iOS 18.4+). 다만 화면을 켜 둬야
하고, 그 제약은 로비 화면이 말해 줍니다.

## 만들기

이 개발 환경에는 안드로이드 SDK 가 없어 **APK 를 빌드해 보지
못했습니다.** 처음 만들 때 아래를 그대로 따라가세요.

```sh
# Android Studio 없이도 됩니다 (JDK 17 + 커맨드라인 도구).
cd android
./gradlew assembleDebug
# → app/build/outputs/apk/debug/app-debug.apk

# 폰에 넣기 (USB 디버깅 켜고)
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

## 서버 주소

셸은 `res/values/config.xml` 의 `server_url` 을 엽니다. 기본값은
`http://10.0.2.2:8000` (에뮬레이터에서 보는 호스트 PC)입니다.

실제 폰에서 쓰려면 Cloudflare Tunnel 주소로 바꾸세요. **`https://` 를
쓰세요** — `http://` 로 두면 안드로이드가 평문 트래픽을 막고, 막히는
것이 회의 음성입니다.

## 이 셸이 하지 않는 것

- 화면을 그리지 않습니다. 전부 웹입니다.
- 오디오를 직접 다루지 않습니다. WebView 의 `MediaRecorder` 가 합니다.
- 자기 캐시를 두지 않습니다. 그래서 웹에서 서비스 워커도 끕니다
  (`window.TeamFlowShell` 표식으로 알립니다) — 둘이 겹치면 지금 어느
  쪽 화면을 보고 있는지 알 수 없습니다.
- 로그인 상태를 따로 갖지 않습니다. 쿠키는 WebView 가 관리합니다.
