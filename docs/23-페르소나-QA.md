# 23. 페르소나 QA — 사람인 척하고 끝까지 써 보기

지금까지의 검사는 전부 **부분**을 봤습니다. 단위 테스트는 함수를, 감사
도구는 색과 표적을, 가드는 규칙을 봤습니다. 그런데 이 저장소가 반복해서
당한 실패는 **"각각은 맞는데 이어 놓으면 안 되는 것"** 이었습니다.

그래서 이번에는 **사람**을 흉내 냈습니다. 여섯 명이 각자의 사정과 목표를
가지고 들어와, 하려던 일을 **끝까지** 합니다. 화면을 보는 게 아니라
**과업을 끝내는가**를 봅니다.

⚠️ 이 문서의 결함 번호는 `docs/17` 과 같은 번호입니다.

---

## 왜 이게 다른 것을 잡았나

앞선 감사들이 못 본 것을 일곱 개 잡았고, 그중 **넷은 사람이 하려던 일을
아예 못 하게 막는 것**이었습니다. 이유는 하나입니다 —

> **데모 데이터가 있는 계정으로만 보면, 새 사용자가 보는 화면을 한 번도
> 안 봅니다.**

프로젝트를 새로 만들어 보고서야 `0%` 가 나왔고(191), 새로고침을 눌러
보고서야 `{"detail":"Not Found"}` 가 나왔습니다(190).

## 페르소나 여섯

| | 누구 | 사정 | 하려는 일 |
|---|---|---|---|
| P1 | **처음 온 사람** | 계정도 프로젝트도 없음 | 가입해서 팀에 들어가기 |
| P2 | **팀장 김민수** | 어제 회의를 녹음함 | 후보를 칸반에 올리기 |
| P3 | **디자이너 박지원** | 코드를 거의 안 씀 | 내 기여가 0으로 나올까 확인 |
| P4 | **손목을 다친 사람** | 마우스를 못 씀 | 키보드만으로 후보 등록 |
| P5 | **평가자** | 성적에 쓰려 함 | 누가 1등인지 찾기 |

P5·P6 는 앞선 감사(`docs/22` ⑤~⑧)와 겹치는 부분이 커서, 여기서는 P1~P4 를
중심으로 적습니다.

## P1 「처음 온 사람」 — 가입하고 팀을 만든다

### ⛔ 190. 홈에서 **F5 를 누르면 앱이 죽습니다**

로그인하면 주소가 `/app` 이 됩니다. 거기서 새로고침하면 —

```
{"detail":"Not Found"}
```

`mount("/app", …)` 이 잡는 것은 `^/app(/.*)$` 라, 끝에 슬래시가 없는
**정확히 `/app`** 은 그 뒤의 `mount("/", …)` 이 삼켜 404 를 냅니다. 하필
React Router 의 `basename: "/app"` 이 홈 경로를 `/app` 으로 만들기 때문에,
**사람이 제일 오래 머무는 주소가 그 하나**입니다.

프로젝트를 만든 직후에도 같은 자리로 갑니다(`navigate(0)` 가 통째로
새로고침합니다) — **새 사용자가 제일 먼저 하는 일**입니다.

→ `/app` 에 SPA 를 직접 물렸습니다. 검사가 `/app`·`/app/`·깊은 주소 셋을
다 잽니다.

### ⛔ 191. 새 팀의 첫 기여도 화면이 **"너희 다 0%"**

프로젝트를 막 만들면 회의도 저장소도 없습니다. 그런데 화면은 —

```
한소희 · 개발    0%  기여 구간      0%p 모름     0 회의 · 0 업무 · 0 코드
```

**`0%` 는 가장 확신에 찬 단일 점수입니다.** 실제로는 아직 아무것도 안
쟀습니다. `AGENTS.md` 불변식 ③(측정 불가 ≠ 0점)이 깨지는 자리이고, 하필
**새 팀이 이 제품에서 처음 보는 기여도 화면**입니다.

서버는 정직했습니다 — `categories: []`, `skipped_categories: [여섯 전부]`,
`confidence_reasons: ["수집된 활동 데이터가 없습니다"]`. **화면이 그걸
버리고 0 을 그렸습니다.**

원인은 `adjustment_range` 의 폭이 `share` 에 비례한다는 것입니다 —
`share` 가 0 이면 폭도 0 이라, 신뢰도가 0 이어도 구간이 `0~0` 이 됩니다.

→ `nothingMeasured()` 를 `lib` 에 두고, 잰 것이 없으면 구간은 `—`,
모르는 폭은 **100%p**, 고리 셋은 **빈 고리**로 그립니다.

```
한소희 · 개발    —  기여 구간      100%p 모름    — 회의 · — 업무 · — 코드
                 ▨▨▨▨▨▨▨▨▨▨ (흙빛 빗금 = 모르는 폭)
```

⚠️ **`0건`과 헷갈리면 안 됩니다.** 활동 중인 팀에서 아직 아무것도 안 한
사람은 서버가 칸을 만들어 주고 개수가 0 입니다 — 그건 **쟀는데 0건**이라
`0%` 가 맞습니다. 가르는 물음은 `categories` 가 비었는가 하나뿐입니다.

### 195. favicon 이 없어 404 (조용한 것)

탭에 이름 없는 회색 종이가 떴습니다. 레거시 화면들이 쓰는 **같은 아이콘**을
물렸습니다.

### 잘 되고 있던 것

- 빈 홈이 무엇을 하라고 말하고, `+ 새 프로젝트` 대화상자에 **만들기와 초대
  코드 참가가 둘 다** 있습니다
- 없는 초대 코드는 조용히 실패하지 않고 답을 줍니다

## P2 「팀장」 — 회의 → 후보 → 칸반

### ⛔ 192. 막힌 `등록` 이 **아무 데도 안 데려갔습니다**

이 저장소의 규칙은 "비활성 버튼을 누르면 못 채운 칸으로 데려간다" 입니다.
주석에도 그렇게 적혀 있었습니다. 그런데 —

```ts
document.getElementById(`cand-fields-${id}`)?.querySelector('select, input')?.focus();
```

v2 F7·F8 에서 담당자를 **Radix Select** 로, 마감을 **커스텀 DatePicker** 로
바꾸면서 둘 다 `<button>` 이 됐습니다. `select, input` 은 **0개**입니다.
초점은 버튼에 그대로 머물렀습니다.

→ 칸마다 id 를 주고, **비어 있는 칸**으로 보냅니다(담당자가 찼으면 마감으로).

### ⛔ 193. 칩은 `●●●` 인데 버튼은 막히고, 툴팁은 **"등록할 수 있습니다"**

지난 날짜를 마감으로 고르면 이렇게 됐습니다.

```
조건 칩    ● 근거 1   ● 담당자   ● 마감        ← 다 됐다고 말하고
툴팁       "등록할 수 있습니다"                ← 대놓고 거짓말이고
실제       aria-disabled=true, 눌러도 무반응
```

화면이 칩을 **따로** 만들고 있었기 때문입니다 — "비었나" 만 봤는데,
승인을 막는 쪽은 **마감이 과거인 것도** 막습니다. 두 벌이 갈라진 것입니다.

→ 칩을 **막는 목록에서 파생**시킵니다(`approvalConditions`). 이제 `○마감
지남` 이라고 말하고, 툴팁은 `아직 안 된 것 — 마감 지남` 입니다. 검사가
"칩이 전부 ● 인데 막히는 상태" 를 **구조적으로 불가능**하게 못 박습니다.

### 194. 「나중에」 는 나중으로 미루지 않았습니다

하는 일은 `decision: 'pending'` 입니다. 그런데 아직 아무것도 안 정한
카드는 **이미** `pending` 이라 **아무 일도 안 일어납니다** — 레인 개수도
그대로입니다. 그리고 미룬 채로는 검토를 끝낼 수 없습니다(모든 후보를
사람이 판단해야 열리는 마무리 버튼입니다).

실제로 쓸모 있는 자리는 하나뿐입니다 — **잘못 누른 것을 되돌리기.**

→ 이름을 `되돌리기` 로 바꾸고, **되돌릴 것이 있을 때만** 보입니다.

### ✅ 사슬이 끝까지 이어집니다

셋을 처리하고 제출하면 칸반에 카드가 생깁니다.

```
배포 방식 결정 · 이하늘 · 2026-09-10 · TASK-5 · 근거 1
```

회의에서 한 말 → 후보 → 사람의 판단 → 칸반 카드 → 근거. **이 제품이
하겠다고 한 일**입니다.

## P3 「디자이너」 — 내 기여가 0으로 나오나

**이 화면은 제 역할을 정확히 했습니다.** 고칠 것이 없었습니다.

| 물음 | 답 |
|---|---|
| 목록이 점수 순인가 | ❌ **이름 순** (김민수 · 박지원 · 이하늘) |
| 못 잰 것이 0으로 보이나 | ❌ 박지원의 회의 고리가 **`—`**(빈 고리) |
| 왜 이 숫자인지 알 수 있나 | ✅ 「왜」 가 사유를 **원문 그대로** |
| 순위·등수 표현이 있나 | ❌ 없음 |

「왜」 팝오버가 이렇게 말합니다.

> 회의 기여를 측정하지 못했습니다 — 녹음 1건 중 1건이 끊겼습니다.
> 발언량을 측정할 수 없어 회의 기여도를 계산에서 제외했습니다.
> **0으로 계산하지 않고** 나머지 활동으로 추정했습니다.

## P4 「마우스를 못 쓰는 사람」

### ⛔ 196. 달력이 `role="grid"` 라면서 화살표가 안 먹었습니다

달력은 `<button>` 42개입니다. 화살표 이동도 roving tabindex 도 없어서,
키보드로 날짜를 고르려면 **Tab 을 마흔 번 넘게** 눌러야 했습니다. 그리고
마감은 등록의 **필수 조건**이라, 마우스를 못 쓰는 사람은 이 제품의 핵심
흐름을 **끝낼 수 없었습니다.**

ARIA 는 `role="grid"` 를 붙였으면 격자 키보드 모델을 **구현해야 한다**고
못 박습니다. 안 하면 역할을 안 붙인 것보다 나쁩니다 — 낭독기가 "격자입니다,
화살표로 이동하세요" 라고 안내하는데 안 움직입니다.

→ `moveInCalendar()` 를 `lib` 에 두고(순수 계산, 검사 6개) 격자에
붙였습니다. 좌우 하루 · 위아래 한 주 · Home/End 그 주의 양 끝 ·
PageUp/Down 달 넘기기(**날짜 유지**, 1월 31일 → 2월 말일).

⚠️ **Radix 가 여는 순간 첫 초점을 가져갑니다**(`‹` 버튼). 거기서는 화살표를
눌러도 아무 일이 없습니다. `useEffect` 로 나중에 옮겨 봤지만 Radix 의 자동
초점이 **뒤에** 와서 도로 뺏어 갔습니다 — `onOpenAutoFocus` 를 막고 **고른
날 칸**으로 직접 보냅니다.

### ✅ 이제 마우스를 한 번도 안 쓰고 완주합니다

```
로그인(Tab·타이핑) → 검토 화면 → 13번째 Tab 에 담당자 칸
→ Enter·↓·Enter 로 이하늘 → Tab → Enter 로 달력
→ PageDown(다음 달) → →→→ → Enter → 마감 2026-09-22
→ Tab → Enter → 등록  ✅ 검토 필요 2 · 등록 1
```

## ⚠️ 이번에도 자가 네 번 틀렸습니다

| 무엇 | 어떻게 알았나 |
|---|---|
| **페르소나가 데이터를 바꿉니다** | 키보드 페르소나가 "60번 눌러도 담당자 칸에 못 닿는다" 고 했습니다. 앞 페르소나가 후보 셋을 **다 처리해 버려서** 카드가 0개였던 것입니다. 없는 결함을 크게 적을 뻔했습니다 — **페르소나마다 데이터를 다시 심으십시오** |
| **Radix 의 자동 초점** | 격자 키보드를 붙였는데 여전히 `‹` 에 서 있었습니다. 내 코드가 아니라 **순서** 문제였습니다 |
| **`input[type=text]` 로 이름 칸을 못 집음** | 그 칸에는 `type` 이 없습니다(브라우저 기본이 text). 사람은 라벨을 보고 누르므로 아무 문제 없습니다 |
| **낱말을 짐작해 오류를 찾음** | 로그인 실패를 `/실패|틀|다시/` 로 찾았는데 실제 문구는 "이메일 또는 비밀번호가 올바르지 않습니다" 였습니다. 그대로 뒀으면 **잘 되고 있는 자리를 결함으로** 적었을 것입니다 |

## 아직 안 고친 것 (알고 두는 것)

- **달력이 지난 날짜를 고르게 둡니다.** 골라도 등록이 막히고 칩이 이유를
  말하지만, 애초에 못 고르게 하는 편이 낫습니다. 다만 "지난 마감을 기록해
  두고 싶다" 는 쓰임이 있을 수 있어 제품 결정으로 남깁니다.
- **검토를 다 끝낸 뒤에도 `검토 끝내기` 버튼이 남습니다.** 처리할 것이 0건
  이면 어수선합니다.
- **「나중에」 를 진짜 미룸으로 만들려면** 서버에 상태가 하나 더 필요합니다
  (`review_status` 어휘 확장 + 마이그레이션). 지금은 되돌리기로만 씁니다.
