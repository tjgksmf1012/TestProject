### 실험 0. 환경 구축 + VRAM 실측 ⭐ 최우선

**질문**: 이 PC에서 전체 스택이 공존하는가? 각 모델이 실제로 VRAM을 얼마 쓰는가?

**먼저 진단 스크립트를 돌리세요.** GPU 모델·VRAM·아키텍처·RAM을 읽어 티어별 구성을 추천합니다.

```bash
python3 scripts/check_env.py
```

> 📌 **2026-08-05**: 원래 이 실험은 RTX 5080(Blackwell) 기준이었으나 실제 개발 머신이
> **중급 GPU 10~16GB + RAM 32GB**로 확인되어 다시 썼습니다.
> Blackwell 전용 함정(`cu128` 휠 강제, `libnvptxcompiler.so` 누락, PTX JIT 파손)은
> **해당 없음**입니다. Ampere/Ada 세대는 생태계 지원이 가장 성숙한 구간이라
> 이 실험의 리스크가 🔴 → 🟡 로 내려갔습니다.

```bash
# CUDA 12.x 계열이면 됩니다. 특정 인덱스 강제 불필요.
pip install torch torchaudio --index-url https://download.pytorch.org/whl/cu124
python -c "import torch; print(torch.__version__, torch.cuda.get_device_capability())"
```

측정할 것:
```python
import torch
torch.cuda.reset_peak_memory_stats()
# ... 모델 로드 + 1회 추론 ...
print(torch.cuda.max_memory_allocated() / 1e9, "GB")
```

| 측정 대상 | 예상 ([`02`](02-모델-선정과-VRAM-예산.md)) | 실측 |
|---|---|---|
| Qwen3-ASR-1.7B (10분 오디오) | 5~6 GB | |
| Qwen3-ASR-0.6B | 2~3 GB | |
| pyannote community-1 (10분) | 1~2 GB | |
| ECAPA-TDNN | < 1 GB | |
| LLM 4bit + 16K 컨텍스트 | 9 GB 내외 | |
| LLM 4bit + 32K 컨텍스트 | 11 GB 내외 | |
| **LLM CPU (llama.cpp Q4)** | **RAM 6~10 GB** | |

**결과에 따라 결정되는 것**: LLM CPU 이관(전략 C, RAM 32GB면 유력) vs 순차 적재(전략 A).

⚠️ vLLM은 **사전빌드 휠**을 쓰고 소스 빌드는 피하세요. 빌드 시간이 매우 길고 자주 실패합니다.

**같은 주에 반드시 확인할 것 — HTTPS 마이크 권한**

멀티트랙 녹음의 전제 조건입니다. 여기서 막히면 [`04`](04-회의-처리-파이프라인.md) 설계 전체가 무너집니다.

### 실험 1. 한국어 ASR 실측 비교

**질문**: Qwen3-ASR-1.7B가 정말 우리 환경에서 Whisper보다 나은가?

검증된 사실은 "Qwen3-ASR-1.7B가 Whisper-large-v3를 상회한다"까지입니다.
**한국어 단독 수치, 특히 회의 환경 수치는 확인하지 못했습니다.**

```
데이터: 팀원들이 실제로 회의 30분 녹음 + 수동 전사 (정답)
모델:   Qwen3-ASR-1.7B / Qwen3-ASR-0.6B / whisper-large-v3 / whisper-large-v3-turbo
지표:   CER (WER 아님 — 한국어는 교착어)
조건:   조용한 방 / 카페 소음 / 노트북 마이크 거리 1m
```

먼저 [OpenKoASR 리더보드](https://gt-kim.github.io/open-korean-automatic-speech-recognition/)를
확인하세요. KsponSpeech·AIHub 기준 CER/RTFx가 이미 정리돼 있습니다.
다만 **"대학생 팀플 회의"라는 도메인은 없으므로** 자체 측정이 필요합니다.

**소요**: 3~4일 (전사 작업 포함). **발표 슬라이드 1장이 여기서 나옵니다.**

### 실험 2. 멀티트랙 vs 단일 마이크 ⭐ 설계 결정용

**질문**: 멀티트랙이 정말 화자 정확도를 해결하는가? 구현 비용은?

```
같은 회의를 두 방식으로 동시 녹음:
  A: 팀원 각자 폰으로 개별 트랙
  B: 테이블 중앙 노트북 1대

측정:
  - B의 DER (pyannote community-1)
  - A의 트랙 간 누출(cross-talk) 정도, 에너지 기반 주화자 판정 정확도
  - 동시 발언 구간에서 각각의 동작
  - A의 시간 동기화 오차
```

**결과에 따라**: A가 잘 되면 모드 A를 1순위로, 화자 자동 식별(ECAPA-TDNN + 성문 등록)을
범위에서 아예 뺄 수 있습니다. → 일정 1~2주 절약 + [`07`](07-법적-윤리-요구사항.md) 성문 저장 동의 문제도 소멸.

**소요**: 1주 (프런트 프로토타입 포함). **가장 투자 대비 효과가 큰 실험입니다.**

### 실험 3. 소형 LLM + guided decoding 실용성

**질문**: 1.2B~8B급 모델이 한국어 회의록에서 업무를 제대로 뽑는가?

```
입력: 실험 1에서 만든 전사 텍스트 (정답 전사 사용 — ASR 오류 영향 배제)
정답: 사람이 뽑은 업무/담당자/마감일/결정사항
모델: EXAONE-4.0-1.2B / Qwen3 소형 / (가능하면) EXAONE-4.0-32B Q3
방식: vLLM + xgrammar guided decoding, 고정 JSON 스키마
지표: 업무 recall ⭐ / precision / 담당자 정확도 / 마감일 정확도
```

**핵심 관찰점**: guided decoding을 켰을 때와 껐을 때 **파싱 실패율**을 비교하세요.
소형 모델일수록 차이가 극적일 것이고, 이게 "왜 우리는 디코딩 강제를 썼는가"의 근거가 됩니다.

⚠️ **EXAONE 4.0은 NC 라이선스**입니다. 실험·연구는 허용되지만, 상업화 계획이 있으면
최종 스택에는 Qwen3를 쓰세요. → [`01`](01-사실검증-2026-08.md) §D-2

### 실험 4. 조작 저항성 테스트 ⭐ 발표용

**질문**: 기여도 산식이 뻔한 조작에 견디는가?

정답 라벨 없이 검증 가능한 유일한 방법이고, **발표에서 가장 인상적입니다.**

| 조작 시나리오 | 기대 결과 |
|---|---|
| 커밋 1개를 30개로 쪼개기 | 점수 변화 **없음** (PR 기준이므로) |
| 오타 수정 커밋 대량 생성 | 점수 거의 **없음** (유의미 diff 필터) |
| `package-lock.json` 수정 커밋 | 점수 **0** (생성 파일 제외) |
| 코드 전체 재포맷 후 커밋 | 점수 **0** (포맷팅 hunk 제외) |
| 회의에서 "네", "맞아요"만 반복 | 회의 점수 **0** (단순 동의 = 0점) |
| 회의에서 혼자 30분 떠들기 | 발언 시간은 늘지만 **점수 안 오름** |
| 마감일을 계속 뒤로 미루기 | 준수율은 유지되나 **변경 횟수 표시됨** |
| 초기 스캐폴딩 커밋 1개 | 커밋당 상한(cap)에 걸림 |

**소요**: 2~3일. 산식 구현 직후에 바로 돌리세요.

### ✅ 실험 4 실행 완료 (2026-08-05)

`backend/tests/test_anti_gaming.py` 로 구현했습니다. **24개 시나리오 전부 통과.**
`pytest backend/tests/test_anti_gaming.py` 로 언제든 재실행할 수 있습니다.

**실행 중 실제 설계 결함을 하나 잡았습니다.**

초기 산식은 병합 PR마다 고정 기본점 8점을 줬습니다. 그랬더니:

```
오타 PR 30개  →  250.9점
실제 기능 구현 PR 1개  →   44.3점     ❌ 스팸이 5배 이겼음
```

커밋 단위 조작 문제를 **PR 단위로 옮겨놨을 뿐**이었습니다.
이벤트 '개수'에 비례하는 보상은 무엇이든 개수 늘리기로 뚫립니다.

**수정 3가지**
1. PR 고정 기본점 **제거** — 점수가 개수가 아니라 실질 분량만 따라가게
2. 사소 변경 감쇠 — 파일당 2줄 이하 변경은 가중치 0.25배 (`TRIVIAL_WEIGHT`)
3. 카테고리 천장 — `raw = S·(1−e^(−points/S))`. 정상 범위는 거의 선형, 극단 물량만 포화

**수정 후 실측**

| 시나리오 | 점수 | 실제 구현 1건(31.6) 대비 |
|---|---|---|
| 오타 PR 30개 | 2.97 | ✅ 억제됨 |
| 오타 PR 100개 | 9.74 | ✅ 억제됨 |
| 오타 PR 200개 | 19.00 | ✅ 억제됨 |
| 오타 PR 500개 | 44.18 | ⚠️ **역전됨** |
| 오타 PR 2000개 | 126.30 | ⚠️ 역전됨 |

### ⚠️ 알려진 한계 — 발표에서 먼저 말하세요

**500건을 넘기면 물량이 이깁니다.** 그리고 이건 고칠 수 없습니다.

500번의 오타 수정은 **실제로 500번 작업한 것**이고, 그것이 저가치라는 판단은
정량 신호만으로 내릴 수 없습니다. 가치 판단을 하려면 AI가 코드의 의미를 평가해야 하는데,
그건 이 프로젝트가 명시적으로 **하지 않기로 한 것**입니다
(docs/05 §5 "커밋 코드의 실질적 가치 단독 평가" 금지).

그래서 시스템은 **판정하지 않고 표시합니다.** 이 규모의 조작은 무결성 플래그로 드러납니다:

```python
IntegrityFlag(code="trivial_pr_spam",
              message="병합된 PR 대부분이 사소한 변경만 담고 있습니다.")
IntegrityFlag(code="no_external_review",
              message="병합된 PR이 모두 외부 리뷰 없이 처리되었습니다.")
```

`test_extreme_typo_spam_is_detected_even_when_it_wins` 가 이걸 검증합니다.

> 💡 **발표 전략**: 심사위원은 반드시 "조작하면 어떻게 되냐"고 묻습니다.
> "완벽히 막습니다"라고 답하면 반례 하나에 무너집니다.
> **"200건까지 막고, 그 이상은 탐지해서 표시합니다. 정량 지표로 가치 판단은 원리적으로 불가능해서
> 최종 확정은 사람이 합니다"** 가 훨씬 강한 답입니다. 그리고 이건 사실입니다.

### 구현된 무결성 플래그

점수를 깎지 않고 **맥락만 표시**합니다 (docs/07 E1: 시스템이 사람을 판정하지 않는다).

| 코드 | 조건 |
|---|---|
| `frequent_deadline_change` | 마감일 변경 3회 이상 & 마감 건수의 50% 초과 ⚠️ **아직 뜰 수 없습니다** — 아래 |
| `mostly_social_utterances` | 발언 20건 이상 & 맞장구 비중 70% 이상 |
| `no_external_review` | PR 3건 이상 & 전부 외부 리뷰 없음 |
| `trivial_pr_spam` | PR 10건 이상 & 사소 변경 PR 비중 80% 이상 |

⚠️ **`frequent_deadline_change` 는 탐지기만 살아 있습니다** (결함 386).
그 플래그가 세는 `DEADLINE_CHANGED` 는 `task_service._change_deadline` 이
만들고, 그 함수는 `PATCH /api/projects/{id}/tasks/{id}` 에 `deadline` 이
실려 와야 돕니다. **그 요청을 보내는 화면이 두 뿌리 다 0곳**입니다 —
마감일은 후보를 승인할 때 한 번 정해지고 그 뒤로 바꿀 자리가 없습니다.

즉 지금은 **미룰 수 없으니 미루기 조작도 없습니다.** 앞뒤가 맞는 상태이고,
틀린 것은 이 표가 「구현된」이라고만 적어 둔 것이었습니다. 마감일을 고치는
자리를 만들면 이 단서를 지워야 하고, **짝 가드가 양방향으로 잽니다**
(`test_repo_integrity.py`).

⚠️ **마감일을 고치는 자리를 만들 것인가는 「결정이 필요한 자리」입니다.**
`docs/05` §2.4 는 「마감일 변경 이력을 이벤트로 남기고, 변경 횟수를 함께
표시하세요」를 요구하고 서버는 그 요구대로 다 만들어 두었습니다. 만들지
않는 쪽을 택한다면 그 이유를 여기 적어야 합니다 — 지금은 **아무도 정한
적이 없어서** 서버만 앞서 있는 상태입니다.

### 실험 5. 실기기 녹음 생존율 — **배치 1(같은 방, 폰) 한정**

> ⚠️ **2026-08-07 — 이 실험의 지위가 내려갔습니다.**
>
> 원래 "이 실험이 실패하면 모드 A 자체가 성립하지 않는다" 였습니다. 방향이
> PC 우선으로 바뀌면서(`docs/15`) **주력 배치가 폰이 아니라 PC 브라우저**가
> 됐고, 거기서는 화면 보호기가 켜져도 탭이 죽지 않고 배터리 세이버가
> 마이크를 끄지 않습니다.
>
> 즉 이 실험은 이제 **배치 1(같은 방에 모여 폰으로 녹음)에만** 적용됩니다.
> 그 배치를 지원할 것인지가 이 실험에 달려 있고, 프로젝트 전체가 달려 있지는
> 않습니다. 순서도 실험 2보다 뒤로 갑니다.

**질문**: 팀원 폰이 한 시간짜리 회의를 끝까지 녹음하는가?

멀티트랙은 "트랙 = 사람"이라 화자 정확도가 100%입니다 — **트랙이 살아 있다면.**
[`04`](04-회의-처리-파이프라인.md) §2.6 에 적었듯 iOS 는 화면이 잠기면 마이크를 끕니다.

```
기기: 팀원 실제 폰 (iOS / 안드로이드 섞어서)
조건: ① 화면 켜둠  ② 화면 잠금  ③ 다른 앱 전환  ④ 통화 수신
      각 조건 × 10분, Wake Lock 있음/없음
지표: 커버리지(%), 최장 공백(초), 공백 원인 분포, 배터리 소모(%)
```

**측정은 이미 구현돼 있습니다** — `frontend/src/lib/recording/timeline.ts` 의
`buildTimeline()` 이 공백을 원인별로 뱉습니다. 실기기에서 돌리고 결과를 표로
채우기만 하면 됩니다.

| 조건 | 기기 | Wake Lock | 커버리지 | 최장 공백 | 주 원인 |
|---|---|---|---|---|---|
| 화면 켜둠 | | | | | |
| 화면 잠금 | | | | | |
| 앱 전환 | | | | | |
| 통화 수신 | | | | | |

**판단 기준**

- 화면 켜둠 + Wake Lock 에서 커버리지 **95% 미만**이면 모드 A 를 주력에서 내려야 합니다.
- 앱 전환에서 심하게 깨지면 UI 에 "녹음 중에는 화면을 유지해 주세요" 경고가
  필수입니다. 안내 없이 놔두면 발표 시연에서 터집니다.
- 배터리 소모가 시간당 30% 를 넘으면 2시간 회의를 못 버팁니다.

**소요**: 1~2일 (기기만 있으면 됩니다. 비용 0원)

### 실험 6. 브라우저 통화가 회의만큼 버티는가 ⭐ 새 주력 배치의 성패

> 방향 전환(`docs/15`)으로 **생긴** 실험입니다. 실험 5 가 폰에 대해 묻던 것을
> PC 통화에 대해 다시 묻습니다.

**질문**: 4명이 WebRTC 메시로 한 시간을 통화하면서, 각자 트랙이 끝까지
녹음되는가?

```
        A ────── B      3명: 연결 3개
        │  ╲  ╱  │      4명: 연결 6개   ← 팀플 기본
        │   ╳    │      5명: 연결 10개
        C ────── D
```

메시는 인원이 늘면 각자의 업로드가 (n−1)배가 됩니다. 서버 대역폭이 0 이라
비용 0원 제약에는 맞지만, **가정용 업로드 대역이 먼저 무너질 수 있습니다.**

```
조건: ① 3명  ② 4명  ③ 5명       각 30분
      각 조건에서 헤드폰 / 스피커 두 번
지표: 트랙 커버리지(%), 통화 끊김 횟수, 업로드 대역(kbps),
      CPU(%), TURN 경유 비율,
      ⭐ 스피커 조건에서 **남의 목소리가 내 트랙에 섞인 비율**
```

**판단 기준**

- 4명에서 커버리지 **95% 미만**이면 메시를 접고 SFU(자체 호스팅)를 봐야 합니다.
- 스피커 조건에서 누설이 유의미하면 **헤드폰을 요건으로 강제**합니다
  (로비에서 확인하고 안 쓰면 못 들어가게). `docs/15` §2.3 의 근거가 여기서
  숫자로 확인됩니다.
- TURN 경유가 20% 를 크게 넘으면 coturn 자체 호스팅이 필수가 됩니다.

⚠️ **이 개발 환경에서는 실행할 수 없습니다** — 네트워크가 없습니다. 코드는
만들 수 있지만 이 표는 실기기·실네트워크에서만 채워집니다. 지어내지 않고
비워 둡니다.

**소요**: 1일 (사람 4명과 각자의 PC 가 있으면 됩니다. 비용 0원)
