# 24. 베타 체험 QA — 배포된 것을 처음 받은 사람처럼

`docs/23` 의 페르소나 QA 는 **여섯 사람의 과업**을 끝까지 따라갔습니다.
이번은 다릅니다 — **베타 참가자**를 흉내 냅니다. 목표를 정해 두고 가는
것이 아니라, 받아 든 프로그램의 **버튼을 하나하나 눌러 보고 기능을 하나씩
써 봅니다.** 그리고 무엇이 남는지 봅니다 — 화면에, 그리고 **로그에.**

⚠️ 결함 번호는 `docs/17` 과 같은 번호입니다.

---

## 왜 또 다른 것이 나왔나

과업을 따라가면 **그 과업에 필요한 화면만** 지납니다. 베타 참가자는 그렇게
안 씁니다 — 눌러 보고, 만들어 보고, 둘째 것을 만들어 보고, 새로고침하고,
잘못된 것을 넣어 봅니다. 그 결과 이번에 나온 것은 전부 **"처음 한 번은
되는데 두 번째부터 안 되는 것"** 이었습니다.

| | 처음 한 번 | 두 번째부터 |
|---|---|---|
| 프로젝트 | 만들면 홈이 그것을 보여 줍니다 ✅ | **만든 것으로 갈 길이 없습니다** (197) |
| 팀 참가 | — | **내가 만든 프로젝트가 사라집니다** (197) |
| 회의 목록 | 다섯 개면 요청 7건 | 서른 개면 **33건** (200) |

그리고 **터졌을 때**가 통째로 비어 있었습니다 (199).

### 격리부터 — 앞사람이 바꾼 세계를 다음 사람이 재지 않게

`docs/23` 에서 "페르소나가 데이터를 바꿔 다음 페르소나가 없는 결함을
크게 적었다" 를 겪었습니다. 그래서 이번에는 체험하는 사람마다 **자기 포트 ·
자기 DB · 자기 로그**를 줬습니다 (`scratchpad/qa2/env.sh`).

## ⛔ 197. 프로젝트가 둘이 되는 순간 **하나가 사라집니다**

### 재현

1. 새로 가입한다.
2. `+ 새 프로젝트` 로 `내가 만든 프로젝트` 를 만든다 → 홈 제목이 그 이름. 정상.
3. 팀에게 받은 초대 코드로 `참가` 한다.

**기대** 두 프로젝트 사이를 오갈 수 있다.
**실제** 홈 제목이 팀 프로젝트로 바뀌고 **내가 만든 것은 화면에서
사라집니다.** 서버는 둘 다 알고 있습니다 (`#1`, `#6`). 그런데 홈의 링크가
전부 `/project/1/…` 이고 **`#6` 으로 가는 링크가 하나도 없습니다.**

```
서버가 아는 내 프로젝트: #1 TeamFlow 시연 프로젝트 · #6 내가 만든 프로젝트
화면의 링크: /app/project/1/kanban /app/project/1/contributions
             /app/project/1/settings/role …
#6 으로 가는 길: ❌ 없음
```

같은 뿌리의 다른 얼굴: **새 프로젝트를 만들면 그 프로젝트는 언제나 목록
끝**이라(`orderProjects` 는 검토거리 있는 것을 앞으로, 그다음 id 순)
**만들자마자 못 들어갑니다.** `+ 새 프로젝트` 는 모든 화면 상단에 늘
떠 있습니다. 이 저장소가 기록한 실패 ③ **"할 일을 알려 주고 그 일을 할
자리를 안 줌"** 그대로입니다.

프로젝트가 하나뿐일 때는 멀쩡합니다(가입 → 빈 홈 안내 → 만들기 → 레일이
그 프로젝트로 붙음). **그래서 여태 안 보였습니다.**

### ⚠️ 판단은 처음부터 있었습니다 — 부르는 곳만 없었습니다

`frontend/src/lib/nav/rail.ts` 는 이 문제를 위해 쓰인 파일입니다. 하나면
안 그린다(`railIsWorthIt`) · 자리는 id 로 고정한다 · 할 일은 자리가 아니라
점으로 말한다 · 이모지 이름의 머리글자를 안 깨뜨린다(`railInitial`) —
검사까지 붙어 있습니다.

**리디자인 SPA 가 그걸 안 부릅니다.** 옛 화면(`demo/nav.ts`)이 부르고
있어서 "아무도 안 쓰는 export" 가드도 조용히 통과했습니다. 렌더해서 옛
화면과 새 화면을 나란히 재 보고서야 나왔습니다:

```
[옛 화면 /home.html] #2·#3 으로 가는 길: 6개
[새 화면 /app/    ] #2·#3 으로 가는 길: ❌ 없음
```

AGENTS.md 가 적어 둔 그대로입니다 — **화면을 옮기면 가드가 눈을 감습니다.**

### 고친 것

- 셸 왼쪽 레일 위에 **프로젝트 네모**를 세웠습니다. 판단은 `rail.ts` 한 벌을
  그대로 쓰고, 주소 형식만 `appRailHref` 로 갈아 끼웁니다 — 옛 셸은
  `/kanban.html?project=7`, SPA 는 `/project/7/kanban`.
- 홈이 **주소가 가리키는** 프로젝트를 그립니다 (`?project=`).
  `homeProject(projects, requestedId)` 가 정하고, 내 목록에 없는 id 는
  **조용히 첫 번째로** 돌아갑니다(남의 프로젝트 이름을 넘겨다볼 수 없어야
  하고, 오타 하나에 "없습니다" 를 띄우면 사람은 자기가 망가뜨린 줄 압니다).
- 만들거나 참가하면 **그 프로젝트로 데려갑니다.**

⚠️ 고쳐 놓고 렌더해 보니 **「지금 보는 프로젝트」 표시가 거짓말**을 하고
있었습니다 — 홈 주소에는 `:projectId` 가 없어 셸이 목록 첫 번째로
떨어졌습니다. 코드만 봤을 때는 안 보였습니다.

## ⛔ 199. 화면이 터지면 **영문 스택**이 뜨고 **아무 데도 안 남았습니다**

서버가 계약과 다른 모양을 주는 상황을 만들어 봤습니다(베타에서 흔합니다).
사람이 본 것:

```
Unexpected Application Error!
e.filter is not a function
TypeError: e.filter is not a function
  at ls (http://…/app/assets/index-DskNXvnA.js:12:42055)
  at …
```

넷이 한꺼번에 잘못돼 있었습니다.

1. **영문**입니다.
2. **압축된 스택**입니다 — 사람이 할 수 있는 것이 없습니다.
3. **나가는 문이 없습니다** — 홈으로도, 다시 시도도.
4. **서버 로그에 한 줄도 안 남습니다.** 요청은 200 이었으니까요.

4번이 가장 나쁩니다. 베타 참가자가 "그냥 안 되던데요" 라고 말하면 그걸로
끝입니다. `uvicorn.access` 는 **브라우저 안에서 난 일을 볼 수 없습니다.**

### 고친 것

- 라우터 바깥 한 겹에 우리 오류 화면(`Crashed.tsx`)을 답니다. 한국어로,
  **지금 할 수 있는 것**을 말하고, 나가는 문을 둘 줍니다. 원래 오류 문구는
  **작게 아래에** 남깁니다 — 참가자가 그 한 줄을 옮겨 적어 주면 고치는
  시간이 크게 줍니다.
- `POST /api/client-errors` 로 **서버 로그에 한 줄** 남깁니다 (WARNING).
- ErrorBoundary 는 렌더 중에 던진 것만 잡습니다. `setTimeout` 안, 거절된
  `await` 은 `window.onerror`·`unhandledrejection` 으로 줍습니다.

### ⚠️ 무엇을 보내지 **않는가**

이 제품은 회의 내용을 다룹니다 (docs/07 P4).

- **주소는 `pathname` 만** — `?…`·`#…` 는 뗍니다. 지금은 `?project=3`
  뿐이지만, 나중에 누가 검색어를 주소에 실으면 그날부터 샙니다.
- **사람이 친 글자는 안 보냅니다.** 오류 메시지와 스택뿐입니다.
- 길이 상한(500·4000·200)과 **분당 60줄** 상한이 있습니다. 넘치면 조용히
  204 입니다 — 429 를 주면 화면의 오류 보고가 **또 오류**를 만듭니다.
- 인증은 **일부러 안 겁니다.** 로그인 화면에서 터진 것이 가장 알고 싶은
  것인데, 인증을 걸면 그건 영영 안 들어옵니다. `test_auth.py` 의 `PUBLIC`
  목록에 이유와 함께 적었습니다.

⚠️ 상한이 **두 벌**입니다(TypeScript · Pydantic). 갈라지면 화면은 보냈다고
믿는데 서버가 422 로 버리고, **오류 보고가 사라지는 것은 아무도 못
알아챕니다.** 그래서 숫자를 맞대 보는 검사를 붙였습니다.

## 200. 홈이 **회의 수만큼** 요청을 쏘고 있었습니다 (N+1)

로그를 읽다 나왔습니다. 홈 한 번에:

```
GET /api/auth/me
GET /api/projects
GET /api/projects/1/meetings
GET /api/meetings/1/tracks      ← 줄마다 하나씩
GET /api/meetings/3/tracks
GET /api/meetings/4/tracks
GET /api/meetings/5/tracks
```

회의 다섯이면 7건, **회의 서른인 팀이면 33건**입니다. 브라우저는 호스트당
여섯 개씩만 동시에 여니 나머지는 줄을 섭니다 — 목록이 길수록 홈이 느려지는
구조였습니다.

### 고친 것

목록 응답이 `coverage` 를 함께 싣습니다. 재서 확인: **7건 → 3건.**

⚠️ **못 잰 것은 `None` 입니다. 0.0 이 아닙니다.** 이 제품의 불변식
셋째(`docs/05`)이고, 0.0 으로 채우면 화면은 "녹음이 하나도 안 됐다" 를
그리는데 실제로는 **아직 회의가 안 끝나서 잰 적이 없는** 것입니다.
평균을 낼 때도 `coverage IS NULL` 인 트랙은 빼고 셉니다 — 넣으면 아직 안
끝낸 사람 하나가 회의 전체의 커버리지를 끌어내립니다. 검사 둘이 지킵니다.

## 로그에 대해 — 이번에 실제로 남겨 본 것

`logging_config.py` 는 제대로 돕니다. 확인한 것:

- 틀린 비밀번호(401)·없는 회의(404)·없는 프로젝트(404)가 전부
  `uvicorn.access` 한 줄로 남습니다.
- 데모 DB 가 낡아 로그인이 500 이 났을 때, **트레이스백이 통째로**
  남아 있었습니다 (`no such column: users.bio`) — 원인을 로그만 보고
  찾았습니다. 이 저장소의 로그 설정이 하려던 일 그 자체입니다.
- `sqlalchemy.engine` 이 WARNING 으로 눌려 있어 쿼리 파라미터(회의 내용·
  사람 이름)가 안 새어 나갑니다.

**비어 있던 절반이 브라우저 쪽**이었고, 그것이 199 입니다.

## 201·202. 열리기까지 — 사람이 흰 화면을 보는 시간

베타 참가자는 링크를 받아 **처음** 엽니다. 그 첫 몇 초를 아무도 안 재고
있었습니다. 400kbps(느린 3G 정도)로 스로틀을 걸고 캐시를 비워 재 봤습니다.

### 201. 서버가 번들을 압축 없이 보내고 있었습니다

    GET /app/assets/index-*.js  →  526,215 바이트 (content-encoding 없음)
    gzip 하면                        161KB          (3.2배)

**흰 화면 12.5초 → 4.8초.** 같은 계측기, 같은 조건에서 압축만 껐다 켜서
잰 값입니다(추정이 아닙니다).

⚠️ **소리는 제외**합니다 — webm 은 이미 압축돼 있어 줄어드는 양이 0에
가까운데, 회의 한 시간짜리 트랙을 매 재생마다 다시 압축하면 재생이
끊깁니다.

### 202. 그 4.8초가 **아무것도 없는 백지**였습니다

사람은 5초짜리 흰 화면을 "고장" 으로 읽고 새로고침을 누릅니다. 그러면
처음부터 다시입니다.

그리고 번들이 다 와도 끝이 아니었습니다 — `RequireAuth` 가 로그인 판별
중에 `null` 을 그리므로, 서버가 느리면 **레일도 appbar 도 없이** 계속
백지였습니다. `/api/auth/me` 를 3초 지연시켜 재 보니 7.4초.

`index.html` 안에 HTML 만으로 그려지는 껍데기를 뒀습니다.

| | 완전한 흰 화면 |
|---|---|
| 껍데기 없음 | 4,446ms |
| 껍데기 있음 | **523ms** |
| 서버 느릴 때 · 껍데기 없음 | 7,322ms |
| 서버 느릴 때 · 껍데기 있음 | **525ms** |

## 203. 둘이 같이 쓸 때 — 여태 전부 **혼자** 써 봤습니다

체험도, 페르소나 QA 도, 도는 검사도 전부 한 사람이었습니다. 베타는 늘
여럿이 같이 씁니다. 브라우저 둘(김민수 · 이하늘)로 같은 프로젝트를 열어
봤습니다.

| 해 본 것 | 결과 |
|---|---|
| 같은 후보를 둘이 승인 | ✅ 서버가 멱등 — 업무 하나만 생깁니다 (4개 → 5개, 겹치는 제목 없음) |
| 같은 카드를 둘이 다른 칸으로 | 마지막 쓰기가 이깁니다 (칸반에서 흔한 선택) |
| **A 가 바꾼 것을 B 가 보는가** | ❌ **20초가 지나도 그대로.** 새로고침하거나 다른 화면 갔다 와야 |
| 뒤에 승인한 사람이 듣는 말 | ⚠️ "칸반에 등록된 업무는 없습니다" — **거절했을 때와 같은 문장** |

세 번째가 문제입니다. B 는 옛 화면을 보고 A 의 결정을 조용히 덮을 수
있고, 이 제품에서 업무 완료는 **기여도로 들어갑니다.**

`refetchOnWindowFocus: true` 로 고쳤습니다 — 설명을 더하는 것보다 그
상황이 **안 생기게** 하는 쪽입니다.

⚠️ 승인의 멱등성은 `apply_approval` 에 이유까지 적힌 **의도된 결정**이라
손대지 않았습니다.

## 결함 197 이 알려 준 것 — 같은 모양을 다 훑었습니다 (204~209)

197(프로젝트 레일)은 하나짜리 실수가 아니라 **부류**였습니다. 그래서
저장소 전체를 같은 눈으로 훑었습니다: *판단은 `lib/` 에 있는데 SPA 만
안 부르는 곳.* 여섯 개가 더 나왔습니다.

| | 무엇 | 사람이 못 하던 것 |
|---|---|---|
| ⛔ 204 | **로그아웃이 `/app` 에 없음** | 한 번 들어오면 못 나가고 계정도 못 바꿈 |
| ⛔ 205 | 프로젝트 없는 사람의 레일 셋이 `/` 를 가리킴 | 눌러도 아무 일이 없음 |
| ⛔ 206 | 권한 3단계 UI 없음 + **시드에 소유자 0명** | 등급 변경·내보내기·설정 저장이 전부 막힘 |
| 207 | 지울 것이 없어도 "지웠습니다" | 지워진 줄 앎 (개인정보보호법 §36 결과 보고) |
