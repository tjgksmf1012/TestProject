# 22 · 리디자인 「계측기」 — Vite SPA 전환

2026-08-18. 팀이 준 리디자인 패키지(`design/redesign/`)를 그대로 실행한
기록입니다. 패키지의 진단은 "지난 개편은 리스킨이었다 — 색만 바뀌고
배치가 그대로였다"였고, 처방은 **배치부터 다시**였습니다.

## 무엇이 어떻게 바뀌었나

| | 전 | 후 |
|---|---|---|

시그니처는 **트랙 리본**입니다 — LG 30px(로비·녹음, 시간축),

## 구조 결정

- **SPA 는 `/app` 아래에 삽니다.** 기존 `index.html`(녹음)과 자리가
  겹치지 않고, FastAPI 는 `_SpaStaticFiles` 로 없는 경로를 index.html 에
  돌려 React Router 가 라우팅합니다 (`api/main.py`).
- **녹음(`index.html`)·통화(`call.html`)는 SPA 밖입니다.** 장치 수명을
  React 로 옮기지 않는 결정(docs/19 §24.9)은 리디자인에서도 유지됩니다.
  패키지가 요구한 것(제목·문구·리본·한 카드 4단계)은 그 자리에서
  해결했습니다. Electron smoke(녹음 생존율)로 재검증했습니다.
- **판단은 여전히 `frontend/src/lib` 한 벌입니다.** webapp 은
  `@lib` 별칭으로 같은 파일을 import 합니다 (`webapp/vite.config.ts`).
  복사해 오면 두 벌이 되고, 두 벌이 되면 한쪽만 고쳐집니다.
- **레거시 6화면(보고서·채팅·달력·알림·활동·검색)은 라우트만 유지**(R8).
  `frontend/public/tokens.css` 의 Layer 1 팔레트를 통째로 바꿔 새 정체를
  입혔고(청록 전멸), 내비에 새로 노출하지 않았습니다.

## 텍스트 최소화 리모델링 — 「계기판 문법」 (2026-08-18)

"글자가 너무 많아 지저분하다" 는 지적을 받고, 시장 제품·표준을 조사한
뒤 다섯 화면을 다시 썼습니다. **조사와 근거 전문은
`design/redesign/06-텍스트-최소화-조사.md`** — 여기에는 결과만 적습니다.

### 처방 네 줄

1. **같은 말은 한 번만** — 항목마다 반복되던 안내는 그릇으로 올립니다
   (열 머리말·헤더).
2. **값은 크게, 뜻은 작게** — 값 28px 고정폭 / 라벨 11px (`Stat`).
3. **이유는 부르면 온다** — 문장을 지우지 않고 `?` 한 겹 아래로 (`Why`).
   요약하지 않고 **원문 그대로** 넣습니다.
4. **빈 칸이 문장을 대신한다** — 회의→업무→코드 사슬을 그리고 안 이어진
   고리를 비워 둡니다 (`Chain`). 비활성 사유는 조건 칩 (`Conditions`).

새 컴포넌트 넷은 `webapp/src/components/{Stat,Why,Chain,Conditions}.tsx`,
스타일은 `app.css` 「계기판 문법」 절.

### 잰 값 (1280×800, 라이트/다크 동일)

| 화면 | 글자 전→후 | 설명 문장 전→후 | `scrollHeight` |
|---|---:|---:|---:|
| 홈 | 185 → 164 | 1 → 0 | 800 |
| 칸반 | 271 → 169 | 4 → 0 | 800 |
| 기여도 | 423 → 260 | 5 → 2 | 800 |
| 검토 (발화 원문 제외) | 330 → 240 | 7 → 1 | 800 |
| 로비 | 257 → 205 | 10 → 5 | 800 |
| **합 (껍데기만)** | **1,466 → 1,038 (−29%)** | **27 → 8 (−70%)** | — |

검토 화면 전체는 878 → 756 자입니다. 남은 것의 대부분이 **회의 발화
원문**이라 그렇습니다 — 껍데기가 아니라 읽으러 온 콘텐츠입니다.

### 실측으로 확인한 것

- **대비** — `.stat__label`·`.chain__label`·`.why`·`.cond--met` 는 처음에
  `--c-ink-faint`(3.28:1)로 만들었다가 본문 하한 4.5:1 미달로 잡혀
  `--c-ink-muted` 로 바꿨습니다 (라이트 6.18/6.18/5.51, 다크
  6.73/6.73/5.55). ⚠️ **뜻을 나르는 라벨을 장식색으로 쓰면 안 됩니다.**
- **`Why` 는 WCAG 1.4.13 세 조건을 다 지킵니다** — ESC 로 닫히고
  (dismissible), 내용 위로 옮겨도 안 사라지고(hoverable), 2.5초 뒤에도
  떠 있습니다(persistent). 키보드로도 열립니다. 보이는 크기는 18px 이지만
  `::after { inset: -13px }` 로 실제 표적은 44px 입니다.
- **`aria-disabled` 버튼** — 막힌 카드를 눌러도 승인되지 않고 첫 빈 칸
  (SELECT)으로 포커스가 갑니다. 충족된 카드는 눌리면 `등록 표시됨`.
  ⚠️ Playwright 는 `aria-disabled` 를 "비활성" 으로 보고 클릭을 거부합니다 —
  **도구가 틀린 것**이라 `force: true` 로 다시 쟀습니다(사람은 누를 수
  있습니다).
- **조건 칩이 실제 입력값과 맞는가** — 눈으로는 셋째 카드의 `마감` 칩이
  빈 원으로 보였는데, 재 보니 `● ● ●` 에 버튼도 활성이었습니다.
  **눈이 틀리고 잰 것이 맞았습니다.**
- **되풀이 문장 0건** (10자 이상이 한 화면에 두 번 이상, SPA 열두 화면).
  ⚠️ 이 0건은 되풀이를 **심어서 검사가 잡는 것을 본 뒤**에 적었습니다
  (심은 뒤 `3× 아직 아무도 참가하지 않았습니다`, 되돌린 뒤 0건).
- **JetBrains Mono 의 0 은 가운데 점이 있습니다.** 28px 축소 캡처에서
  취소선처럼 보여 결함으로 적을 뻔했고, 5배로 확대해 보니 폰트였습니다.

### ③ 「아직 안 됨」을 한 문법으로

다섯 자리가 제각각이었습니다 — 검토(`aria-disabled`+흐림) · 기여도(HTML
`disabled`) · 로비(`aria-disabled`+`pointer-events:none`+흐림) ·
녹음(HTML `disabled`) · 설정 연결(HTML `disabled`). 레거시 `app.css` 도
`.btn[aria-disabled="true"]` 를 0.45 로 흐리고 있었습니다.

경계를 **"보기에 흐린가" 가 아니라 "누를 수 있는가"** 로 다시 그었습니다.

| | 어떻게 |
|---|---|
| 사유가 있는 것 | `aria-disabled` + `aria-describedby` + 누르면 그 자리로 + **덜 채운 모양** |
| 해당 없는 것 | HTML `disabled` 그대로 (`정지`·`마이크 끄기`) |

⚠️ 레거시에서는 `button.primary` **뒤에** 둬야 합니다 — 특성도가 같아서
앞에 두면 집니다. 앞에 뒀다가 `녹음 시작` 이 꽉 찬 파란 버튼으로 그려졌고,
**렌더해서** 잡았습니다 (결함 184).

### ④ 이름과 초점 — 열두 화면을 훑었습니다

낭독기가 읽을 이름이 없는 것 **0건** · 초점 표시가 없거나 약한 것
**0건**. 둘 다 심어 보고 잡히는 것과 되돌린 뒤 다시 0 인 것을 확인했습니다.

⚠️ 초점 표시를 재는 도구가 HTML `disabled` 버튼에서 **없는 결함 셋**을
만들 뻔했습니다 — 초점을 못 받으니 `.focus()` 가 아무 일도 안 하고, 그
상태에는 당연히 테두리가 없습니다. `document.activeElement` 를 먼저
보게 고쳤습니다 (결함 183).

### ⑦ 글자 간격 (WCAG 1.4.12) — 잰 결과 **0건**

줄 높이 1.5 · 자간 0.12em · 어간 0.16em · 문단 간격 2em 을 강제해도
**새로 잘리거나 넘치는 것이 없습니다** (열두 화면). 고칠 것이 없어
그대로 둡니다 — 잰 것을 적어 둡니다.

⚠️ 이 자도 두 번 손봤습니다. `overflow: hidden` 만 보면 **넘쳐서 이웃을
덮는 것**을 못 보고, **인라인 요소는 `clientHeight` 가 0** 이라 글이 든
`<span>` 이 전부 "넘쳤다" 로 잡힙니다(칸반에서 4건이 그랬습니다).

### ⑧ 「안 됩니다」 를 아무도 안 듣고 있었습니다

`.disabled-reason` 스물세 곳 중 **둘만** 라이브 영역이었습니다 (결함 188).
자리 자체를 `components/Problem.tsx` 한 벌로 올리고 전부 그리로 보냈습니다.

⚠️ **전부 `alert` 로 하면 안 됩니다** — 저장소 주소 오류는 글자를 칠 때마다
바뀌는데 `alert` 는 끼어들어 읽으므로 타자를 칠 수 없게 됩니다. 두 톤:
`failed`(끼어들기) · `incomplete`(기다리기).

⚠️ 라이브 영역은 **내용이 바뀌기 전에 DOM 에 있어야** 읽힙니다 — 껍데기는
항상 두고 안쪽 글자만 바꿉니다.

### ⑨ `display: flex` 가 또 문장을 흩어 놓았습니다

`app.css` **맨 끝 줄**의 `.notice { display: flex; … }` 가 위쪽 §안내 박스의
블록 정의를 덮고 있었습니다. 상자 안 문장과 `<strong>` 이 각각 flex 항목이
되어 좁은 세로 기둥으로 접혔습니다 — 설정·저장소의 진단 상자가 다섯 기둥으로
그려졌습니다 (결함 189). **렌더해서** 잡았습니다.

  | 프로젝트 레일 (결함 197) | 나옵니다 (`T 옆 🚀`) |
  | 라우터 이동 | 셸의 이동 잠금에 안 걸립니다 (`/app/project/1/kanban`) |
  | 로비 → 녹음(`/index.html`) | 링크 살아 있음 — 조건 미충족일 때만 `aria-disabled` |
  | 페이지 오류 | 0 |

  ⚠️ 처음엔 "로비에 녹음으로 가는 링크가 없다" 고 적을 뻔했습니다. 탐침이
  `a[href]` 만 세는데 그 버튼은 조건이 안 차면 `href` 가 없기 때문입니다 —
  **없는 결함을 만들 뻔했습니다.** 실제로는 `aria-disabled` + 조건 칩 +
  사유(`Why`)까지 이 저장소의 「아직 안 됨」 규칙대로 돼 있습니다.
- 수정 지시서 v2 의 P1(빈 레인 안 그리기 · 홈 그룹 정리 · 하단 여백)과
  P2(정렬·DatePicker·Select·primary 하나·일괄 제출 라벨·설정 탭·로그인
  중앙 정렬)가 대기 중입니다 — P0 보고 뒤 순서대로.

## UI 패스 v3 — **눈으로 보고 고친 것** (2026-08-21)

사용자 지적: *"텍스트들의 폰트나 레이아웃이 너무 어색하고 글씨가 너무 많아서
디자인이랑 가독성을 해침. 직접 눈으로 보면서 맞춰야 해."*

여섯 화면을 1440px 로 렌더해 **보고** 고쳤습니다. 코드로 위치를 재지
않았습니다.

### ① 칸반 — 값 없는 고리가 카드의 절반이었습니다

사슬(`Chain`)의 빈 고리가 **값 있는 고리와 같은 크기**였습니다. 칸반 카드는
대부분 아직 안 이어져 있어서, 카드 넷 중 셋이 「빈 상자 둘」로 보였습니다.

```
고치기 전  [ — 근거 ] — [ — PR ]     ← 값 있는 고리와 같은 크기
고친 뒤    [— 근거] — [— PR]         ← 한 단 작게 (min-width 3.25rem → 2.5rem)
```

뜻(점선 · 흙빛 `—` · 라벨)은 그대로 두고 **크기만** 줄였습니다. F3
「값 없는 레인은 안 그린다」와 같은 정신인데, 여기서는 안 그리면 사슬이
끊기므로 **작게** 그립니다.

### ② 검토 — 근거 칩 열둘이 회의 내용보다 먼저 보였습니다

반복 논의 하나에 `#1 #2 #3 … #14` 가 두 줄로 깔렸습니다. 숫자 열둘은
아무것도 말하지 않는데 자리는 제일 넓게 썼습니다.

```
고치기 전  #1 #2 #3 #4 #5 #6 #7 #8 #12
           #13 #14
고친 뒤    #1 #2 #3 #4 #5 +6
```

⚠️ **감추는 것이 아니라 접는 것**입니다. 「+6」을 누르면 폅니다 — 근거를
감추면 이 저장소가 세 번째로 적어 둔 실패(「근거 #5 라고 적어 놓고 원문을
볼 방법이 없던 것」)로 되돌아갑니다. 몇 개까지 펼칠지는 `@lib` 의
`splitEvidenceChips` 가 정합니다(하나 남는 것은 안 접습니다 — 접는 쪽이
더 넓습니다).

### ⚠️ 가드가 또 **구현을 요구**하고 있었습니다

`row.view.evidence.map(` 이라는 글자 그대로를 찾고 있어서, 칩을 접는
컴포넌트로 옮기자 요구는 그대로인데 가드만 실패했습니다. 요구는
「근거 id 가 **칩으로 그려진다**」 이므로 그렇게 고쳐 다시 쟀습니다.
이번 회차에 **두 번째**입니다(결함 220 가드 · 이것).

### 다음 (아직 안 고침)

- **홈의 「녹음 전 · 녹음 중」** — 한 상태 칸에 두 낱말. 서버의 `pending`
  이 두 국면을 함께 뜻하는데, 화면이 둘 다 적어 어느 쪽인지 모릅니다.

  `computed_at` 은 `Z` 를 붙입니다 — 한 API 안에 규약이 둘입니다.
  다른 시간대의 팀원은 같은 회의를 다른 날짜로 봅니다.
