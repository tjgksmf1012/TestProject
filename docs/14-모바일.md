# 14. 모바일 — 왜 앱이어야 하고, 어디까지 앱인가

> ⚠️ **순서가 바뀌었습니다.** `docs/15` 를 먼저 보세요. 이 시스템은
> PC 브라우저에서 통화하며 회의하는 쪽으로 방향을 잡았고, 모바일은
> 그 뒤로 미뤄졌습니다. 아래 판단(왜 하이브리드인지, iOS 비용, 폰 UI
> 규칙)은 여전히 맞고 나중에 다시 씁니다 — 그래서 지우지 않았습니다.

> 관련 문서: `docs/09` 실험 5(녹음 생존율), `docs/07` §1(녹음 고지)·P4~P6,
> `docs/13` 화면 구조

---

## 1. 이건 원래 모바일 시스템이었다

이 시스템의 핵심 동작은 **팀원 각자가 자기 폰으로 녹음하는 것**입니다.
멀티트랙(모드 A)이 그렇게 생겼습니다 — 한 사람당 한 트랙이고, 그 트랙이
그 사람의 발화량·발언 종류·회의 기여의 유일한 근거입니다.

그러면 실제 사용 흐름은 이렇습니다.

| 단계 | 어디서 | 무엇으로 |
|---|---|---|
| 회의 열기 | 회의실 | 노트북 또는 폰 |
| **동의** | 회의실 | **각자 폰** |
| **녹음** | 회의실 | **각자 폰, 1~2시간** |
| 처리 대기 | — | (서버) |
| 승인 검토 | 아무 데나 | 폰이 편함 |
| 칸반·기여도 | 아무 데나 | 폰이 편함 |

여섯 중 넷이 폰입니다. 그런데 화면들은 데스크톱에서 만들어졌습니다 —
위쪽 링크 줄, 26px 버튼, `max-width: 64rem`. **폰에서 열면 되기는 되는데
쓰기 어렵습니다.**

## 2. 그래서 무엇을 만드는가

```
    ┌──────────────────────────────────────────────┐
    │  frontend/public  ← 화면은 여기 하나뿐        │
    └────────┬─────────────────────┬───────────────┘
             │                     │
    ┌────────▼────────┐   ┌────────▼─────────────┐
    │  PWA            │   │  안드로이드 셸        │
    │  (아이폰·PC·    │   │  (WebView +          │
    │   안드로이드)    │   │   포그라운드 서비스)  │
    │                 │   │                      │
    │  0원            │   │  0원 (사이드로드)     │
    │  설치 가능       │   │  화면 꺼도 녹음 유지  │
    └─────────────────┘   └──────────────────────┘
```

**화면 코드는 한 벌입니다.** 셸은 껍데기이고, 웹이 혼자 할 수 없는 것
두 가지만 대신합니다 — 마이크 권한 위임, 그리고 프로세스를 살려 두기.

녹음 로직을 코틀린으로 다시 쓰지 않습니다. 그러면 시계 동기화·타임라인·
공백 판정의 177개 테스트가 가리키는 코드가 **실제로 도는 코드가 아니게**
됩니다.

## 3. 왜 셸이 필요한가 — 실험 5와 같은 문제

`docs/09` 실험 5의 질문은 이것입니다.

> 팀원 폰이 한 시간짜리 회의를 끝까지 녹음하는가?
> **이 실험이 실패하면 모드 A 자체를 재검토해야 한다.**

브라우저 탭은 그 보장을 주지 않습니다.

| 환경 | 화면 꺼짐 | 다른 앱 전환 | 근거 |
|---|---|---|---|
| 안드로이드 크롬 탭 | ⚠️ 조여짐 | ⚠️ 조여짐 | 백그라운드 타이머·미디어 제한. 멈추는 시점은 제조사 배터리 설정마다 다름 |
| 설치한 PWA (안드로이드) | ⚠️ 나아짐 | ⚠️ 나아짐 | Wake Lock 이 더 잘 듣지만 보장은 아님 |
| 설치한 PWA (iOS 18.4+) | ⚠️ 나아짐 | ❌ 끊김 | Wake Lock 이 설치형 PWA 에서만 동작 |
| **안드로이드 셸** | ✅ **유지** | ✅ **유지** | 포그라운드 서비스 + `microphone` 타입 |

셸이 하는 일은 단 하나입니다 — **WebView 를 포그라운드 서비스가 있는
프로세스 안에서 돌립니다.** 그러면 시스템이 죽이지 않습니다.

### 왜 이게 중요한가: 끊긴 녹음은 조용하다

30분 회의에서 트랙이 10분에 끊기면 그 사람의 커버리지는 0.33 입니다.
그런데 **커버리지 숫자만으로는 "말을 적게 했다" 와 구분되지 않습니다.**

이 프로젝트는 그 구분을 위해 이미 장치를 갖고 있습니다 —
"측정 불가 ≠ 0점" (`docs/05` §5). 커버리지가 낮은 트랙은 회의 카테고리에서
**빠집니다.** 즉 녹음이 끊기면 그 사람의 회의 기여는 계산되지 않습니다.

그건 오답보다는 낫지만, 좋은 결과도 아닙니다. 매 회의 한 명씩 빠지면
기여도 화면은 "이 팀은 회의 기여를 잴 수 없습니다" 만 반복합니다.
**셸은 그 상태를 줄이려는 것입니다.**

## 4. 왜 안드로이드만인가 — 비용

| 방법 | 비용 | 판단 |
|---|---|---|
| PWA | **0원** | 채택 |
| 안드로이드 APK 사이드로드 | **0원** | 채택 |
| Google Play 등록 | $25 (1회) | 안 함 — 팀원 서너 명에게 스토어가 필요 없음 |
| Apple Developer Program | **$99/년** | **비용 0원 제약 위반** |
| iOS 무료 프로비저닝 | 0원 | **7일마다 재설치.** 발표 당일에 만료되면 그날 시연이 없음 |

이 프로젝트의 제약은 "나 거지야 — 반복 비용은 전기요금뿐" 입니다.
연 $99 는 그 제약을 깹니다. 무료 프로비저닝은 비용은 0이지만 **7일
만료**가 졸업작품 발표에서 감당할 위험이 아닙니다.

### 아이폰 팀원은 어떻게 하는가

PWA 로 참여합니다. 홈 화면에 추가하면 전체화면으로 뜨고, Wake Lock 이
브라우저 탭보다 잘 듣습니다(iOS 18.4+). 대신 **화면을 켜 둬야 하고,
그 제약을 화면이 미리 말합니다.**

```
    화면을 켜 두세요. 앱으로 설치돼 있어 꺼짐 방지가 동작하지만,
    화면이 잠기면 녹음이 끊길 수 있습니다.
```

⭐ **회의가 끝난 뒤에 알려 주면 소용없습니다.** "그 폰은 화면을 켜 뒀어야
했다" 를 나중에 알게 되면 그 회의는 다시 못 합니다. 그래서 녹음 화면이
**시작 전에** 이 환경이 얼마나 안전한지 말합니다
(`src/lib/shell/bridge.ts`, 15개 테스트).

## 5. UI/UX — 폰 기준으로 다시 정한 것

### 5.1 엄지 영역

폰을 한 손으로 쥐면 화면 위쪽 3분의 1은 엄지가 안 닿습니다.

```
    ┌─────────────┐
    │  ✗ 안 닿음   │  ← 예전에는 여기에 이동 링크가 있었다
    │             │
    │  △ 겨우      │
    │             │
    │  ○ 편함      │  ← 주요 동작을 여기로
    │  ● 아주 편함  │  ← 탭바를 여기로
    └─────────────┘
```

- 이동 → **아래 탭바**
- 각 화면의 주요 동작 → **아래 고정 막대**(`.actionbar`)

### 5.2 탭은 언제나 같은 순서로 넷

```
    🏠 홈    📋 칸반    📊 기여도    ⚙️ 설정
```

상황에 따라 탭이 사라지면 같은 자리에 다른 것이 오고, **사람은 자리를
기억해서 누르므로** 엉뚱한 화면으로 갑니다. 못 가는 탭은 숨기지 않고
흐리게 둡니다 — 숨기면 그 화면이 *없는 줄* 압니다.

회의 화면(로비·검토·녹음)은 탭이 **아닙니다.** "지금 이 회의" 안에서만
뜻이 있어서, 늘 보이는 자리에 두면 어느 회의인지 모르는 채로 눌립니다.

### 5.3 터치 타깃 44px

손가락 끝 접촉면이 대략 10mm ≈ 44px 입니다.

칸반의 열 옮기기 버튼이 **높이 26px** 이었습니다. 그보다 작으면 옆 것을
누르는데, 칸반에서 그건 **엉뚱한 업무를 완료 처리하는 것**이고, 완료는
기여 이벤트를 만듭니다.

### 5.4 입력 칸 글자는 16px 이상

iOS Safari 는 글자가 16px 보다 작은 입력 칸에 포커스가 가면 화면을
확대하고 **확대된 채로 돌아오지 않습니다.** 사람은 앱이 깨졌다고
느낍니다.

승인 화면이 14px 이었습니다 — 담당자 고르기·마감일 넣기가 전부 입력인
화면입니다.

### 5.5 safe-area

노치와 홈 인디케이터 뒤로 내용이 들어가면 아래 고정 버튼이 **안 눌립니다.**
전체화면(PWA·셸)으로 띄우면 브라우저 크롬이 없어져 더 심해집니다.

```css
padding-bottom: calc(3.5rem + env(safe-area-inset-bottom, 0px) + 1rem);
```

### 5.6 hover 를 쓰지 않는다

폰에는 hover 가 없습니다. 눌린 상태(`:active`)로 피드백을 주고,
마우스가 있는 환경에서만 `@media (hover: hover)` 로 hover 를 얹습니다.

### 5.7 본문은 가로로 밀리지 않는다

표와 코드 블록만 **자기 안에서** 가로로 넘깁니다(`.scroll-x`).
본문이 가로로 밀리면 사람은 화면이 깨졌다고 읽습니다.

## 6. 한국 모바일 앱에서 가져온 것

토스 같은 앱을 보면 공통된 형태가 있습니다. 그중 **이 앱에 뜻이 있는
것만** 가져왔습니다.

| 패턴 | 가져왔는가 | 왜 |
|---|---|---|
| 하단 고정 CTA | ✅ | 목록이 길어져도 주요 동작이 엄지 아래 있다 |
| 큰 본문 제목(상단 바 대신) | ✅ | 상단 바는 세로 공간을 먹는데 폰에서는 그게 제일 아깝다 |
| 하단 탭바 | ✅ | 전체화면에는 주소창도 뒤로가기도 없다 |
| 둥근 카드 + 배경 구분 | ✅ | 1px 선이 겹치면 폰에서 빽빽해 보인다 |
| 한 화면 한 결정 | 부분 | 승인 화면은 한 번에 여러 후보를 봐야 한다 — 서로 비교해야 판단이 된다 |
| 바텀 시트 | ❌ | 지금은 필요한 자리가 없다. 애니메이션과 포커스 관리가 붙는데 얻는 게 없다 |
| 화려한 전환 애니메이션 | ❌ | `prefers-reduced-motion` 을 존중해야 하고, 녹음 중에는 CPU 를 쓰면 안 된다 |
| 스켈레톤 로딩 | ❌ | 목록이 짧다. "불러오는 중…" 이 정직하다 |

⭐ **가져오지 않은 것에 이유가 있는 게 중요합니다.** 형태를 따라하는 것이
목적이 아니라, 이 앱이 하는 일에 맞는 것만 씁니다.

## 7. 서비스 워커 — 무엇을 캐시하지 않는가

앱 껍데기(HTML·JS·CSS·아이콘)만 캐시합니다. **`/api/*` 는 전부
지나갑니다.** 이건 성능 판단이 아니라 안전 판단입니다.

| 캐시하면 | 무슨 일이 | 근거 |
|---|---|---|
| 회의 녹취·회의록 | 동의를 철회해 서버가 지워도 **폰에서 계속 보인다** | `docs/07` P6 |
| 기여도 | 지난 값을 지금 값처럼 보여준다 | 성적에 반영될 수 있는 값 |
| 로그인 상태 | 서버에서 세션을 끊어도 화면이 계속 뜬다 | `user_sessions` 는 취소 가능해야 한다 |

오프라인이면 API 요청이 **실패하고, 화면이 그 실패를 말합니다.**
그게 맞습니다.

## 8. 아이콘을 손으로 굽는 이유

PNG 가 **필요합니다.** iOS 의 `apple-touch-icon` 은 SVG 를 받지 않고,
안드로이드 적응형 아이콘도 maskable PNG 를 원합니다. 없으면 홈 화면에
추가했을 때 **화면 캡처가 아이콘이 됩니다.**

그런데 아이콘 하나 만들자고 `cairosvg`/`Pillow` 를 넣으면 빌드 환경마다
네이티브 라이브러리를 맞춰야 합니다. `zlib` 은 표준 라이브러리이고 PNG 는
그 위에 얇게 얹힌 형식이며, 그림도 원·둥근 사각형·굵은 선분 셋뿐입니다.

`scripts/make_icons.py` 가 **결정적으로** 굽습니다 — 다시 돌려도 같은
바이트가 나와서 저장소에 커밋해도 매번 diff 가 생기지 않습니다. 웹의
PWA 아이콘과 안드로이드 런처 아이콘을 **같은 소스에서** 만듭니다.

## 9. 그물 — 두 언어에 걸친 규약

셸(코틀린)과 웹(TypeScript)이 어긋나면 **조용히 아무 일도 일어나지
않습니다.** 오류가 안 나므로 사람이 알 방법이 없습니다.

한 번 실제로 어긋나 있었습니다 — 웹은 `window.TeamFlowShell` 을 봤고
셸은 `TeamFlowShellBridge` 를 심었습니다. 그 결과는 셸 안인데 "셸이
아니다" 로 판정되어 **포그라운드 서비스가 안 올라가는 것**이었습니다.
즉 셸을 만들어 놓고 셸의 존재 이유가 동작하지 않는 상태입니다.

`backend/tests/test_repo_integrity.py` 가 대조합니다.

- 브리지 이름이 양쪽에서 같은가
- 웹이 부르는 브리지 함수가 셸에 전부 있는가
- 코드가 쓰는 권한을 매니페스트가 선언하는가
- 셸이 평문 HTTP 를 막는가 (회의 음성과 세션 쿠키가 나갑니다)
- 녹음 화면이 **실제로** 셸에게 알리는가

`frontend/src/lib/guards.test.ts` 는 화면 쪽을 봅니다.

- 모든 화면이 공통 스타일을 가져오고 `viewport-fit=cover` 인가
- 모든 진입점이 `bootApp()` 을 부르는가 (안 부르면 서비스 워커가
  등록되지 않고 `sw.js` 는 그냥 놓인 파일이 된다)
- 서비스 워커가 캐시하는 파일이 실재하는가 / API 를 캐시하지 않는가
- manifest 의 아이콘·`start_url` 이 실재하는가
- 입력 칸 글자가 16px 밑으로 안 내려가는가
- 탭바와 겹치는 `position: fixed; bottom: 0` 이 없는가
