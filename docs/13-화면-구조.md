# 13. 화면 구조 (IA)

> 화면이 열여섯 장인데 서로 어떻게 이어지는지가 어디에도 적혀 있지 않았습니다.
> 그래서 만들 때마다 하나씩 늘었고, **넷이 막다른 길**이 됐습니다.

---

## 1. 전체 그림

```
                    ┌─────────────┐
                    │ login.html  │  신원이 없는 유일한 화면
                    └──────┬──────┘
                           │ 성공 → next(같은 오리진만) 또는 /home.html
                           ▼
                    ┌─────────────┐
                    │  home.html  │  ★ 시작점. 어떤 id 도 필요 없다
                    └──────┬──────┘

     │ 프로젝트마다│ 회의마다        │ 프로젝트마다     │
```

⚠️ **`chat` 도 `reports` 도 탭이 아닙니다.** 채팅은 셸의 왼쪽 채널 열에서
늘 닿을 수 있고, 위쪽 링크 줄(`navLinks`)의 `채팅` 은 **텍스트 채널이 아직
하나도 없는 팀**이 채널을 만들러 가는 문입니다. 왼쪽 열이 세우는 것은
**회의**(음성 채널)이므로, 그것만으로는 텍스트 채널에 닿을 수 없습니다.

⚠️ **`reports` 는 탭이 아닙니다.** 탭은 넷 그대로입니다(홈·칸반·기여도·설정) —
사람은 자리를 기억해서 누르므로 다섯째가 끼면 그때까지 넷째였던 것을 누르려던
손이 엉뚱한 화면으로 갑니다. 보고서는 자주 가는 곳이 아니라 **다 끝나고 한 번
가는 곳**이라 위쪽 링크 줄(`navLinks`)에 있습니다.

⚠️ 이 그림이 오랫동안 **일곱 개**에서 멈춰 있었습니다. `project.html` 은
왼쪽 열의 `설정` 탭이 가리키는 상시 노출 화면이고 `call.html` 은 로비에서
여는 통화 화면인데, 둘 다 그림에도 아래 표에도 없었습니다. IA 문서가 실제
IA 를 안 담으면 다음 사람은 화면을 또 하나 늘리고, 이 문서가 경고하는
바로 그 일("만들 때마다 하나씩 늘어 막다른 길이 됨")이 반복됩니다.

**모든 화면에 `<nav id="tabs">` 가 있습니다.** 무엇을 채울지는
`frontend/src/lib/nav/links.ts` 가 정하고 29개 테스트가 붙습니다.
예외는 둘뿐입니다 — `login.html`(아직 신원이 없음)과 `offline.html`(연결이
없어 어디로도 못 감). `home.html` 은 예외가 아닙니다 — 탭바를 갖고 있습니다. `test_demo_path.py::test_no_screen_is_a_dead_end` 가 고정합니다.

## 2. 화면마다 책임지는 것

| 화면 | 필요한 id | 이 화면만 할 수 있는 것 | 여기서 하면 안 되는 것 |
|---|---|---|---|
| `login` | 없음 | 신원 확보 | 그 외 전부 |
| `home` | 없음 | **내 프로젝트·회의를 찾는다.** 각 회의에서 다음에 할 일을 말한다 | 회의 내용을 보여주는 것 |
| `lobby` | meeting | 동의를 받는다 · 회의 **중에** 트랙이 끊기는 걸 보여준다 · 강제 종료 | 녹음 자체 |
| `index`(녹음) | meeting(선택) | 마이크를 잡고 청크를 올린다 | 동의 판정 |
| `review` | meeting | AI 후보를 사람이 승인·거절한다 | 업무 상태 변경 |
| `kanban` | project | 업무 상태를 옮긴다 · **회의 근거를 보여준다** | 후보 승인 |
| `contributions` | project | 기여도를 **구간·근거와 함께** 보여준다 | 순위·점수 조정 |
| `reports` | project | 회의록·주간·최종 보고서를 만들고 **글자로 내보낸다** | 기여도 계산·확정 |
| `chat` | project | 텍스트 채널을 만들고 대화한다 · 답글·멘션·반응·검색 | **기여도로 세는 것** — 정의서 §7 이 금지합니다. 도배가 점수를 올리는 길이 되면 안 됩니다 |
| `calendar` | project | 업무 마감일·회의·프로젝트 마감일을 한 달로 본다 · 회의 일정을 잡는다 | **일정을 따로 저장하는 것** — 달력은 읽어서 만듭니다. 베끼면 칸반에서 마감일을 고쳐도 달력만 옛 날짜를 말합니다 |
| `notifications` | project | 나를 부른 대화·맡은 업무·다가오는 마감과 회의 | **마감을 행으로 쌓는 것** — 미루면 "곧 마감" 이, 끝내면 "지연" 이 남습니다 |
| `activity` | project | 누가 언제 무엇을 바꿨나 (`audit_logs` 를 **읽는** 유일한 화면) | **고치거나 지우는 것** — 감사 기록이 고쳐지면 목적이 사라집니다. 이 화면에는 보내는 요청이 0개입니다 |
| `search` | project | 업무·회의·회의 내용·GitHub 을 한 자리에서 찾는다 | **사람별로 세는 것** — 그 순간 "검색 결과 기준 발언 순위" 가 됩니다 |
| `project`(=설정) | project | 이름·역할·GitHub 계정/저장소·초대 코드·**회의 열기** | 업무·기여도 조작 |
| `call` | meeting | 브라우저 통화 (메시 5명) | 녹음 판정 |
| `offline` | 없음 | 연결이 없다고 알린다 | 그 외 전부 |

`?meeting` 없이 `index.html` 을 열면 서버 없이 도는 **실험 5 모드**입니다.
폰이 한 시간을 버티는지만 보는 것이라 네트워크가 없어도 끝까지 돕니다.

⚠️ 이 모드의 동의 상태는 `all_confirmed` 가 아니라 **`solo`** 입니다 —
"전원이 동의했다" 가 아니라 **"물을 상대가 없다"** 입니다. 회의가 없으니
남의 목소리도, 올릴 트랙도 없습니다. 회의 id 가 있으면 이 값은 절대
안 나옵니다(`consentForEntry` — 결함 229·238). 한동안 여기가 `pending`
이라 **첫 걸음에서 막혀 있었습니다.**

## 3. 결정 셋과 그 이유

### 3.1 홈은 어떤 id 도 요구하지 않는다

`POST /api/projects` 는 있는데 **목록이 없었습니다.** 그래서 화면을 열려면
`?project=1&meeting=1` 을 주소에 직접 적어야 했고, 그 숫자를 알 방법은
`seed_demo.py` 의 출력뿐이었습니다. 만들 수는 있는데 다시 찾을 수 없었습니다.

지금은 로그인하면 홈으로 오고, 홈이 `GET /api/projects` 로 시작점을 만듭니다.
**목록 자체가 권한 경계입니다** — 남의 프로젝트는 403 을 받는 게 아니라
존재 자체가 보이지 않습니다.

### 3.2 id 가 없으면 링크를 만들지 않는다

링크를 다 붙이면 편해 보이지만, id 가 없는데 링크를 만들면 눌렀을 때
**기본값(대개 1)인 엉뚱한 프로젝트**로 갑니다. `navLinks` 는 가진 id 로 갈
수 있는 곳만 줍니다.

대신 **왜 못 가는지는 말합니다.** 조용히 빼기만 하면 사용자는 그 화면이
없는 줄 압니다 — 대개는 주소에 id 가 빠진 것이고, 그건 고칠 수 있는
문제입니다.

`0` · 음수 · `NaN` 은 id 가 아닙니다. `Number(null)` 은 0 이고
`Number('abc')` 는 NaN 인데, 그대로 링크에 넣으면 `?project=0` ·
`?project=NaN` 같은 주소가 만들어지고 서버는 404 를 줍니다.

### 3.3 이름은 프로젝트 속성이다

명단 API 가 회의 단위뿐이던 동안, 칸반·기여도를 `?project=N` 만으로 열면
명단을 받을 길이 없어 **모든 이름이 `사용자 #3`** 으로 떴습니다. 기여도
화면에서는 이름 순 정렬까지 그 문자열 순으로 바뀌었습니다 — 사람별 기여를
보여주는 화면에서 가장 나쁜 실패입니다.

`GET /api/projects/{id}/members` 를 만들고, 회의 단위 조회는 거기에
위임합니다. 같은 쿼리를 두 곳에 두면 반드시 갈라지고, 갈라지면 승인
화면에서 고른 담당자가 칸반에서는 "알 수 없는 사용자" 로 보입니다.

## 4. 사람이 실제로 지나는 경로

```
① 처음        가입 → 홈("속한 프로젝트가 없습니다 — 팀원이 넣어야 합니다")
② 회의 전     홈 → 로비 → 각자 동의 → 녹음 화면
③ 회의 중     로비를 열어 둔다 (누구 폰이 끊기는지 여기 뜬다)
④ 회의 후     홈("업무 후보 3건 검토") → 승인 화면 → 칸반에 등록
⑤ 평소        칸반에서 업무를 옮긴다 → 완료하면 기여 이벤트가 생긴다
⑥ 마무리      기여도 화면 — 구간·근거·측정 불가 표시
```

④ 에서 홈이 **후보가 0건이면 승인 화면으로 보내지 않습니다.** 보내면 빈
목록이 뜨고 사용자는 고장으로 읽는데, 실제로는 "AI 가 업무로 뽑을 만한 게
없었다" 이고 그건 정상적인 결과입니다.
