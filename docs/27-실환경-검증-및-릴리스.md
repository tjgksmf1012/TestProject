기존 사용자 DB·녹음은 합성 검사 데이터와 분리합니다.

1. 실제 ASR·LLM → 근거 검증 → 후보 승인 → 칸반·기여도 흐름.
2. 동시 사용자·장시간 녹음·끊김·복귀·데스크톱 생존 검사.
3. 실제 Google 인증·GitHub 읽기/웹훅 처리의 검증 범위 확인.
4. 서버 재시작·작업 복구·백업 복원·보존 정책 검사.
5. 많은 데이터·키보드·좁은 화면·오류 상태 사용성 검사.
6. 전체 회귀 검사·생성물 일치·배포/되돌림 절차와 운영 반영.

## 실제 모델과 수정한 원인

RTX 4090에서 Qwen3-ASR-1.7B-hf와 Qwen2.5-3B-Instruct를 실행했습니다.
한국어 합성 음성 두 건을 실제 HTTP API로 청크 업로드하고, 실제 모델로
전사·업무 추출한 뒤 검토 API에서 승인했습니다. 검사 DB와 음성은 임시 폴더에 분리했습니다.

| 발언 | 업무 후보 | 담당자 | 마감 (회의일 2026-11-02) |
| --- | --- | --- | --- |
| 로그인 API 구현을 맡겠습니다. 마감은 이번 주 금요일입니다. | 로그인 API 구현 | 김민수 | 2026-11-06 |
| 회원가입 화면 구현을 맡겠습니다. 마감은 다음 주 화요일입니다. | 회원가입 화면 구현 | 이하늘 | 2026-11-10 |

검사는 제목·담당자·마감을 모두 대조하고, 원문에 이름과 업무가 있는지 확인합니다.
승인 전 업무 0건, 승인 후 후보에서 유래한 업무 2건과 기여도 응답을 확인했습니다.
단순 키워드 일치나 HTTP 200만으로 성공을 판단하지 않습니다.

- 서로 겹치지 않는 녹음을 음절 유사도만으로 원점에 겹치던 정렬을 수정했습니다.
  서버 시각으로 겹치는 구간을 먼저 찾고 그 구간에서만 미세 정렬합니다.
- 누출 제거가 작은 자음과 동시 발화까지 감쇠시키던 문제를 수정했습니다.
  다른 사람의 단독 발화로 확인된 구간만 감쇠합니다.
- ASR 앞뒤 무음 패딩을 제거하되 회의 시간축의 시작·종료 시각을 보존합니다.
- LLM이 마감을 생략하거나 '다음 주'를 줄여도 인용 발화의 명시적 마감을
  확인합니다. 여러 날짜가 있거나 근거를 확인하지 못하면 미정으로 남깁니다.
- 1.5B 모델은 실제 파이프라인에서 후보 0건을 반환했습니다. 이번 PC의 기존
  설정은 위 검사에 통과한 3B 모델로 연결했습니다. 모델 품질을 일반화하지 않습니다.

재현: `scripts/verify_ai_pipeline.py --workspace <새 폴더> --audio <한국어 음성 두 파일>`.
고정된 합성 대본을 검증하는 전용 도구이며 임의 회의의 품질을 점수화하지 않습니다.

## 사용자 흐름과 복구

- 22개 화면을 보통·고대비로 확인했습니다.
- Chromium의 실제 MediaRecorder로 3인이 120초 동시 녹음했습니다. 한 사용자의
  청크 업로드만 8초 차단한 뒤 복귀했고, 세 트랙 모두 서버 커버리지 99% 이상,
  완료 상태와 청크 24개 이상을 확인했습니다. 서로 다른 물리 기기 검사는 아닙니다.
- 실제 2인 WebRTC 연결, 동의 거부·미응답 보존, 가입 시 프로젝트 격리,
  회의 창 최소화·화면 이동 중 녹음 유지, 필터 선택·복귀를 확인했습니다.
- 설정의 마이크 종료·Escape·초점 복귀, 마이크 거부와 API 연결 실패를 확인했습니다.
- 업무 200개와 긴 제목으로 1440·720·390px 화면을 검사했습니다.
  390px에서는 터치 입력도 활성화했습니다. 기여도 숫자와 확정 입력칸이
  잘리는 것을 캡처로 발견해 좁은 창에서 줄을 접도록 수정하고 다시 확인했습니다.
- Electron에서 실제 격리·청크 저장/조회/삭제·경로 탈출 거부·절전 방지 해제,
  녹음 중 닫기 확인·창 숨김 중 녹음 생존율 100%·외부 이동 차단을 확인했습니다.
- 회의 처리는 API와 별도 직렬 로컬 워커로 분리했습니다. OS 잠금으로 중복
  실행을 막고, 워커 재기동 시 중단된 처리만 실패 상태로 전환해 재시도하게 합니다.
  대기·완료 결과는 유지합니다. 실제 자식 프로세스 강제 종료 후 잠금 회수를 검사했습니다.
- Windows venv 실행기의 자식 Python까지 종료하도록 감시·화면 검사 도구를
  수정했습니다. 화면 검사는 새 임시 폴더를 쓰며 기존 검사 자료를 재귀 삭제하지 않습니다.

장시간 검사의 재현은 `SMOKE_RECORD_SECONDS=120 npm --prefix frontend run smoke:screens`입니다.
기본 검사는 짧게 실행합니다. OS 화면 잠금·절전·NAT/TURN·여러 물리 기기에서
수 시간 녹음은 이번 검사로 보증하지 않습니다.

## 실제 계정 연동 완료

2026-11-03 사용자의 설치 승인과 Google 계정 선택을 받은 뒤 다음을 확인했습니다.

- **Google:** 운영 도메인 → 실제 Google 계정 선택 → 콜백 → 인증된 홈 화면까지
  성공했습니다. 신규 계정의 프로젝트 목록은 비어 있었고, 실제 사용할 TeamFlow AI
  프로젝트(3번)를 만들었습니다. 기존 두 프로젝트에는 자동 참가하지 않았습니다.
- **GitHub:** TestProject 한 저장소에 코드·이슈·메타데이터·PR 읽기 권한만 설치했습니다.
  설치 ID는 178138327입니다. 새 프로젝트에 저장소와 사용자 본인의 GitHub 계정을 연결했습니다.
- **웹훅:** 최초 실제 배달의 401로 양쪽 서명 설정 불일치를 확인했습니다.
  서버에 이미 있던 비밀값을 GitHub App 설정에 맞췄습니다. 새 비밀값은 만들지 않았습니다.
  GitHub API에서 실제 설치 이벤트를 재전송하고 운영 서버의 서명 검증 통과·202 응답,
  프로젝트의 설치 ID·연결 확인 시각 저장을 확인했습니다.
- **PR 수집:** 실제 UI에서 '지난 활동 가져오기'를 실행했습니다. 기존 병합 PR 12건의
  상세 수집과 기여 근거 12건 저장, 화면의 코드 근거 12건을 확인했습니다.
  범위는 2026-08-06 이후입니다. 재실행은 이미 있는 12건을 건너뛰었고 중복은 없었습니다.
  기존 PR의 상세 수집 작업도 다시 실행해 신규 기여 이벤트가 0건임을 확인했습니다.
- 새 PR 병합 이벤트는 향후 정상적인 PR 병합 시 확인할 범위입니다. 검사만을 위한
  PR·이슈·댓글을 공개 저장소에 만들거나 테스트 활동을 실제 기여로 꾸미지 않았습니다.

실제 설치 과정에서 드러난 추가 결함도 수정했습니다.

1. 설치 이벤트는 `repository` 하나 대신 `repositories` 목록을 보냅니다.
   서명 검증 뒤 선택된 저장소의 설치 상태를 반영하고, 접근 회수 시 연결 확인 상태를 해제합니다.
2. 첫 PR이 있어야만 과거 PR 가져오기 단추가 나타나던 순환 조건을 제거했습니다.
   서명된 설치를 확인하면 첫 활동 전에도 백필을 시작할 수 있습니다.
3. 로컬 실행의 GitHub 수집·백필이 Redis에만 기대던 문제를 수정했습니다.
   기존 저장소의 `.github-jobs`에 작업을 원자적으로 기록하고 별도 워커가 처리합니다.
   중단된 작업은 기동 시 복구하고, 실패는 120초 뒤 재시도합니다. 새 DB 스키마·패키지는 없습니다.
4. GitHub 계정 저장 뒤 연결 진단·기여도 조회를 무효화해 예전 경고가 남지 않게 했습니다.
5. 첫 프로젝트 안내의 성문 자동 분리·툴바의 영상 통화 문구를 실제 개별 녹음·음성 통화에 맞췄습니다.
6. 테스트가 로컬 운영 자격 증명·오디오 경로를 물려받지 않도록 공통 API 픽스처를 격리했습니다.
   설정 객체의 문자열 표현에서도 비밀 필드를 제외했습니다.

설치 목록 구조와 실제 이벤트 재전송은 [GitHub 웹훅 문서](https://docs.github.com/en/webhooks/webhook-events-and-payloads#installation)와
[App 웹훅 REST API](https://docs.github.com/en/rest/apps/webhooks)를 기준으로 확인했습니다.

연결 완료 뒤 `%LOCALAPPDATA%/TeamFlow/backups/20261103-linked-ready`에 다시 백업하고
무결성을 검증했습니다. 현재 실행 로그는 `%LOCALAPPDATA%/TeamFlow/logs/ready-20261103.*.log`입니다.
API·터널·회의·GitHub·보존기간 실행기를 다시 기동하고 운영 도메인의 200 응답을 확인했습니다.

## 남은 실환경 범위

- **Docker:** Desktop의 Windows AF_UNIX 소켓 초기화가 실패합니다.
  실행 중이던 작업용 프로세스와 임시 소켓 폴더만 정리·별도 보존했습니다.
  공장 초기화·VHDX 삭제·사용자 컨테이너 데이터 삭제는 하지 않았습니다.
  GPU 컨테이너 빌드/실행은 미검증이며 현재 서비스는 Windows 네이티브로 실행됩니다.
- **인증정보 관리:** 기존 PEM은 운영 환경이 참조하는 경로에 유지해야 합니다.
  개인키·환경 파일·실제 비밀값은 저장소 반영 대상에 포함하지 않습니다.
- **실기기:** 수 시간 녹음·OS 절전·외부 NAT/TURN은 별도 검증이 필요합니다.

기여도 확정은 팀의 판단이므로 대신 입력하지 않았습니다.

전체 초기 검토와 앞선 17개 결함 수정은 [사용자 흐름 개선](26-사용자-흐름-개선.md)에 있습니다.

나면 원본을 남깁니다. 워커는 다음 회차에도 중단 파일을 복구하므로
디스크 오류가 풀린 뒤 프로세스를 다시 시작하지 않아도 처리할 수 있습니다.
원자적 쓰기의 중간 오류로 생긴 임시 파일도 정리합니다.
