# TeamFlow AI — 실제 회의 흐름 확인 가이드

현재 기능과 검사 결과는 [실환경 검증 기록](27-실환경-검증-및-릴리스.md)을 기준으로 합니다.
운영 자료를 초기화하거나 검사 자료를 실제 기여 기록에 섞지 마세요.

## 1. 접속과 참가

- [운영 서비스](https://teamflow-ai.stream/app/)에서 Google 또는 이메일 계정으로 로그인합니다.
- 새 계정은 프로젝트가 없습니다. 새로 만들거나 팀원에게 받은 초대 코드로 참가합니다.
- PC 브라우저와 Electron을 지원합니다. 좁은 창과 확대 레이아웃도 유지합니다.
- 이미 켜진 운영 서버에 `start_live.bat`를 다시 실행하지 않습니다.
  이 실행기는 기존 DB와 모델·Cloudflare 터널 설정이 준비된 환경에서 사용합니다.
- 로컬 시연 서버는 `.venv/Scripts/python.exe scripts/run_app.py`로 실행합니다.
  DB가 없으면 시연 자료를 생성하므로 운영 DB와 구분하세요.

## 2. 회의 준비·개별 동의

1. 홈에서 회의를 열고 팀원들이 각자 로그인해 같은 회의에 참가합니다.
2. 각자가 본인의 **회의 녹음과 전사 동의**를 선택합니다. 전원의 동의가 필요합니다.
3. 전사 후 원본 보관은 별도 선택입니다. 동료의 동의를 대신 입력하지 않습니다.
4. 통화 화면에서 실제 연결 상태를 확인하고 헤드폰을 사용합니다.
   음성 통화와 녹음은 별도 기능입니다. 성문 등록·영상 통화는 제공하지 않습니다.

## 3. 각자 녹음하고 종료하기

1. 녹음 탭에서 마이크 권한과 장치를 확인한 뒤 **녹음 시작**을 누릅니다.
2. 본인이 맡을 일과 기한을 명확히 말합니다. 예: "로그인 API 구현을 맡겠습니다. 마감은 이번 주 금요일입니다."
3. 회의 창을 작게 두고 칸반으로 이동해도 녹음이 유지되는지 확인합니다.
4. 각자가 녹음을 종료하고 서버 완료 메시지·청크 수·커버리지를 읽습니다.
5. 완료 통지가 실패하면 **다시 시도**, Electron에 남은 청크가 있으면 **남은 청크 다시 올리기**를 사용합니다.
   처리에 들어간 뒤에는 녹음 원문과 분석 결과가 갈라지지 않도록 조각 추가가 제한됩니다.
6. 회의 로비에서 상태가 처리 중 → 검토 필요로 바뀌는지 확인합니다. 실패하면 원인을 확인하고 재시도합니다.

## 4. AI 후보 검토·승인

1. 회의의 검토 화면에서 전사 원문과 각 후보의 근거를 비교합니다.
2. 담당자·마감·업무 내용을 확인합니다. 발언자 배정 단추가 있더라도 실제 담당자인지 판단합니다.
3. 근거 없는 후보는 거절하고, 등록할 후보의 누락된 정보를 채웁니다.
4. 등록·거절 선택 후 **검토 끝내기**로 서버에 최종 저장합니다.
   선택만 해 둔 상태에서는 칸반에 업무가 생기지 않습니다.
5. 칸반에서 승인한 업무와 원문 근거·담당자·마감이 일치하는지 읽습니다.

## 5. GitHub 연결·기여 근거

1. 프로젝트 설정에서 저장소와 본인의 GitHub 아이디를 등록합니다.
2. 해당 GitHub App을 대상 저장소에 읽기 권한으로 설치하고 연결 진단을 확인합니다.
   먼저 저장소를 등록한 뒤 설치하면 서명된 설치 배달이 프로젝트에 연결됩니다.
3. **지난 활동 가져오기**로 설치 전의 병합 PR 이력을 수집합니다. 잠시 뒤 진단 화면을 새로 고쳐 범위를 확인합니다.
4. 실제 업무 PR의 제목·본문에 `TASK-업무번호`를 적으면 업무와 PR을 연결할 수 있습니다.
5. 정상적인 PR이 병합된 뒤 업무 카드의 PR 근거와 기여도 화면의 코드 근거를 확인합니다.
   검사를 위해 공개 이슈·PR·댓글이나 가짜 기여를 만들 필요는 없습니다.

## 6. 기여도와 보고서

- 이름 순 목록에서 구간·모르는 폭·사유·근거를 확인합니다. 결측은 0점이 아닙니다.
- 시스템 값을 그대로 확정하지 말고 팀이 합의합니다. 다르게 정하면 이유를 적습니다.
- 최종 합계·미입력 안내를 확인한 뒤 권한이 있는 팀원이 확정합니다.
- 보고서를 만들었다면 문서의 회의·업무·근거 수와 화면이 일치하는지 읽습니다.

## 예시 체험관은 별도입니다

`/app/demo`는 마이크의 192개 주파수 값 비교와 입력 문장의 키워드 규칙을 보여 줍니다.
성문 식별·실시간 ASR·LLM 추론이 아니며 결과는 칸반·기여도에 반영하지 않습니다.
실제 AI 처리는 위의 녹음 → 처리 → 검토 흐름에서 확인합니다.

## 이미 확인한 것과 남은 검사

- 실제 한국어 합성 음성 2건 → 실제 GPU 모델 → 후보 2건 → 승인 → 칸반·기여도.
- 실제 Google 로그인과 GitHub 설치 웹훅·과거 PR 12건 수집·재수집 중복 방지.
- 같은 PC의 3인 120초 동시 녹음과 8초 업로드 차단 뒤 복귀, 서버 커버리지 99% 이상.
- Electron 창 숨김 중 녹음, 디스크 보관·복구와 녹음 중 닫기 확인.
- 별도 검사: 여러 물리 기기·외부 NAT/TURN·수 시간 녹음·실제 OS 절전·Docker GPU 실행.

다른 PC에서 검사할 때는 각자 다른 계정으로 참가하고, 종료 후 각 트랙의 길이·커버리지와
전사 원문을 비교하세요. 결과는 날짜·기기·네트워크·발생 시각과 함께 남기되 음성·인증정보를 저장소에 올리지 않습니다.
