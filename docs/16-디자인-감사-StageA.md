## 0. 먼저 — 지시서와 이 저장소가 어긋나는 곳 넷

지시서를 그대로 적용할 수 없는 지점이 넷 있습니다. 임의로 판단하지
않고 여기 적어 결정을 받습니다.

### (1) 스택이 다르다 — §10 의 grep 6종이 이 저장소에서 0건을 반환한다

지시서는 React + Tailwind 를 전제합니다(`*.tsx`, `bg-gradient-to`,
`text-gray-500`). 이 저장소의 프런트엔드는:

```
런타임 의존성        0개
프레임워크           없음 (순수 HTML + <script type="module">)
CSS                  public/app.css 664줄 + 화면별 <style> 316줄
빌드                 esbuild 로 TS 번들만
```

**Tailwind 클래스가 존재하지 않으므로 §10 의 grep 은 전부 0건을
반환합니다.** 그건 "통과" 가 아니라 **검사가 성립하지 않는다**는 뜻
입니다. 같은 금지를 이 저장소에서 검사하려면 CSS 속성 기준으로
번역해야 합니다(§4 에 번역안을 적었습니다).

이 구조는 비용 0원 제약에서 나온 의도적 선택입니다
(`docs/11-비용-제로-구성.md`). **바꿀 것인지가 첫 결정입니다.**

### (2) 브랜드 면이 0개다

지시서 §2 는 화면을 브랜드 면과 제품 면으로 나누고, 브랜드 면에
시그니처를 요구합니다. 그런데:

| 라우트 | 분류 |
|---|---|
| home · project · lobby · call · index(녹음) · review · kanban · contributions | **제품 면** |
| login | 경계 지대 |
| offline | 경계 지대 |
| — | **브랜드 면 0개** |

랜딩·소개·가격 페이지가 없습니다. 졸업작품이고 가입 경로가 초대
코드뿐이라 **필요한 적이 없었습니다.**

지시서 §11-B 의 1·5번(히어로 스크린샷 구분, 제목:본문 3배)은 브랜드
면 전제입니다. **브랜드 면을 새로 만들 것인지**가 두 번째 결정입니다.
만들지 않으면 시그니처는 제품 면 안에서 찾아야 합니다.

### (3) 이모지 금지 vs 아이콘 파일 0개

지시서 §4.6: **UI 에 이모지 금지.** §10 은 검색 목록까지 둡니다.

이 저장소는 탭바 아이콘에 이모지를 씁니다.

```ts
const TAB_ICON = { home: '🏠', kanban: '📋', contributions: '📊', project: '⚙️' };
// 이모지를 쓰는 이유는 아이콘 파일이 0개이기 때문.
```

지시서는 아이콘 세트 1개(lucide 등)를 요구하는데, 그건 의존성
추가입니다. **인라인 SVG 를 직접 그려 넣는 방법**이 있고 비용은 0
입니다. 다만 지시서 §4.6 은 "코딩 에이전트가 그리는 인라인 SVG 가
AI 티의 대표 원인" 이라고도 적었습니다 — 그건 *일러스트* 이야기이고
20px 아이콘 4개는 다른 문제라고 봅니다.

**제안**: lucide 아이콘 4개의 path 만 뽑아 인라인으로 넣습니다.
의존성 0, 라이선스 ISC, stroke-width 1.5 고정.

### (4) 다크 모드는 이미 있다

지시서 §1: "미지원이면 만들지 말 것", §10: "요청하지 않은 다크모드
토글" 금지.

이 저장소는 `prefers-color-scheme` 기반 다크 모드를 **이미
지원합니다**(토글 버튼은 없음 — OS 설정만 따름). 지우는 것은 기능
축소이므로 §0-3("기능 변경 금지")에 걸립니다. **유지**로 봅니다.

### A-1-4. 하드코딩 값

**색상**

```
토큰 정의            20개  (--bg, --surface, --text, --dim, --line,
                            --accent, --on-accent, --ok, --warn, --bad,
                            --bar, --radius, --radius-sm, --tap,
                            --tabbar, --topnav, --safe-*)
고유 hex             21개
  · app.css 안        19개  ← 토큰 정의 자체. 정상
  · 화면 <style> 안    4개  ← **토큰 우회**
  · <meta theme-color>  2개  ← CSS 변수를 못 쓰는 자리. 정상
```

토큰을 우회하는 곳 (§11-A 2번 = 0 이어야 함, **현재 4건**):

| 파일:줄 | 값 | 무엇 |
|---|---|---|
| `login.html:20` | `#2563eb` ×2 | 주 버튼 배경·테두리. `--accent` 와 같은 값을 손으로 적음 |
| `index.html:35-37` | `#fff` ×3 | 상태 배지 전경색 |
| `review.html:76-77` | `#fff` ×2 | 승인·거절 버튼 전경색 |

`#fff` 는 `--on-accent` 가 이미 있는데 안 씁니다. 다크 모드에서
`--on-accent` 는 `#0b1220` 인데 이 다섯 곳은 계속 흰색이라
**다크 모드에서 대비가 달라집니다.**

**간격** — 지시서 §4.3 은 4px 배수만 허용합니다. 현재:

```
app.css       15종
화면 <style>  20종
```

4px 배수가 아닌 값 (실측):

| 값 | px | 어디 |
|---|---|---|
| `.15rem` | 2.4 | 화면 |
| `.2rem` | 3.2 | 화면 |
| `.3rem` | 4.8 | 화면 |
| `.35rem` | 5.6 | 화면 |
| `.4375rem` | 7.0 | app.css |
| `.45rem` | 7.2 | 화면 |
| `.6rem` | 9.6 | 양쪽 |
| `.7rem` | 11.2 | 화면 |
| `.85rem` | 13.6 | 화면 |
| `.9rem` | 14.4 | 화면 |

**10종이 격자 밖**입니다.

**radius** — 지시서 §4.4 는 12px 초과를 금지합니다.

```
사용 중: .2rem(3.2) .25rem(4) .35rem(5.6) .4rem(6.4) .5rem(8)
         .625rem(10) .75rem(12) 1rem(16) 50% 999px
```

- `1rem`(16px) — `call.html:40 .badge`. **§4.4 위반 1건**
- `50%` · `999px` — 아바타·상태점. 허용

**그림자** — `box-shadow` **0건**.

지시서 §4.4 는 "카드·버튼·입력창·배지·표는 그림자 0" 을 요구하므로
**이건 이미 통과**입니다. 다만 진짜로 떠 있는 것(드롭다운·모달·툴팁)
도 0개라, 그림자가 필요한 자리 자체가 아직 없습니다.

### A-1-5. 서체 — 가장 큰 결함

```
body font-family     지정 없음
```

**한국어 제품인데 본문 서체를 지정하지 않았습니다.** 브라우저·OS
기본값에 맡겨져 있어 Windows 는 맑은 고딕, macOS 는 Apple SD 산돌고딕,
안드로이드는 Roboto→Noto Sans KR 폴백으로 **기기마다 다르게 보입니다.**

모노스페이스만 두 곳에 지정돼 있습니다(`app.css:491`,
`index.html:42`).

지시서 §4.2 가 요구하는 3역할(디스플레이 / 본문 / 데이터) 중
**데이터만 있고 나머지 둘이 없습니다.**

**한글 필수 CSS 도 전무합니다** (§4.2):

| 속성 | 지시서 | 현재 |
|---|---|---|
| `word-break: keep-all` | 필수 — "한글 가독성의 핵심" | **0건** |
| `overflow-wrap: break-word` | 필수 | **0건** |
| `text-wrap: balance` | 제목 | **0건** |
| `text-wrap: pretty` | 본문 | **0건** |
| `font-variant-numeric: tabular-nums` | 표·숫자 | 1건 |

`keep-all` 이 없으면 한글이 **단어 중간에서 줄바꿈**됩니다. 기여도
화면의 "측정하지 못했습니다" 같은 문장이 아무 데서나 끊깁니다.

### A-1-8. 접근성

| 항목 | 현재 |
|---|---|
| `:focus-visible` | ✅ 전역 1규칙, `outline: 2px solid var(--accent)` — 지시서 §4.7 통과 |
| `prefers-reduced-motion` | ✅ 존재. `*{animation-duration:.01ms; transition-duration:.01ms}` |
| `aria-label` | 8건 |
| `<img>` | **0개** (따라서 `alt` 누락 0) |
| `.visually-hidden` | 정의만 있고 **사용 0** — 스크린리더 전용 텍스트 없음 |

reduced-motion 블록은 지시서 §5.6 이 경고한 `*{animation:none}` 형태가
**아닙니다**(duration 축소라 콘텐츠가 사라지지 않음). 다만 §5.6 이
요구하는 "최종 상태 명시" 는 없습니다. 현재는 애니메이션이 거의
없어 문제가 안 되지만, Stage E 에서 모션을 넣으면 그때 필요합니다.

**대비 — 실측** (브라우저에서 계산)

| 쌍 | light | dark | 필요 | 판정 |
|---|---|---|---|---|
| 본문 `--text`/`--bg` | 17.76 | 15.04 | 4.5 | ✅ |
| 보조 `--dim`/`--bg` | 4.83 | 7.03 | 4.5 | ✅ |
| 보조 `--dim`/`--surface` | **4.51** | 6.40 | 4.5 | ⚠️ 여유 0.01 |
| 강조 `--accent`/`--bg` | 5.17 | 7.12 | 4.5 | ✅ |
| 버튼 `--on-accent`/`--accent` | 5.17 | 7.36 | 4.5 | ✅ |
| 경고 `--warn`/`--bg` | 5.02 | 10.85 | 4.5 | ✅ |
| 오류 `--bad`/`--bg` | 6.47 | 9.54 | 4.5 | ✅ |
| 성공 `--ok`/`--bg` | 5.02 | 10.39 | 4.5 | ✅ |
| **경계선 `--line`/`--bg`** | **1.25** | **1.45** | **3.0** | ❌ **미달** |

**`--line` 이 유일한 실패입니다.** 지시서 §4.1 은 "입력창·버튼
경계선 3:1" 을 요구하는데 1.25:1 입니다.

이게 중요한 이유: 이 저장소는 **그림자가 0건**이라 카드·입력창·
버튼의 경계를 **전적으로 `--line` 하나에 의존**합니다. 그 선이 거의
안 보이면 입력창이 어디서 시작하는지 알 수 없습니다.

`--dim`/`--surface` 4.51 도 사실상 경계선입니다 — 폰트가 바뀌거나
표면색이 한 단계만 움직여도 미달로 떨어집니다.

## A-2. 레퍼런스 해부

⚠️ **이 환경은 외부 사이트를 직접 열 수 없습니다.** 에이전트 프록시가
일반 웹 CONNECT 를 정책상 거부합니다(403). Chromium 으로 `linear.app`
등에 접속을 시도했고 전부 `ERR_TUNNEL_CONNECTION_FAILED` 였습니다.

그래서 **직접 측정 대신 공개된 디자인 분석 자료를 인용**했습니다.
지시서가 요구한 "측정 가능한 속성" 은 확보했지만 제 눈으로 확인한
것은 아닙니다. 이 한계를 여기 적어 둡니다.

### 1. Linear (linear.app) — 업계 안 · **방법**을 가져온다

| 속성 | 값 |
|---|---|
| 배경 | `#010102` 바닥, 표면 사다리 4단 (`#0f1011` → `#191a1b`) |
| 액센트 | `#5e6ad2` **하나뿐**. 브랜드 마크·포커스 링·섹션당 CTA 1개 |
| 액센트 면적 | 극히 일부 (버튼 하나, 활성 표시 하나) |
| 서체 | Inter Variable, 굵기 대역 **400~510 만** |
| 자간 | 음수, 크기가 커질수록 더 조임 |
| 간격 | 4px 기반 9단계, 섹션 패딩 96px 에서 끝 |
| radius | 4 / 6 / 12 **셋만** |

**딱 하나 기억나는 것**: 절제가 어디까지 확장되는가. 액센트 1개 ·
디스플레이 서체 1개 · 표면 4단으로 마케팅 페이지를 *소프트웨어 장인
문서*처럼 읽히게 만듭니다.

**의도적으로 하지 않은 것**: 쓰지 않는 굵기, 드리우지 않는 그림자,
도입하지 않는 두 번째 액센트. 정체성이 **금지 목록으로** 유지됩니다.

> ⚠️ **가져올 것: 방법. 버릴 것: 어두움.**
> Linear 를 그대로 베끼면 지시서 §3 의 금지 기본값 2번
> ("근검정 배경 + 단일 액센트") 에 정확히 걸립니다. 인용한 분석도
> 같은 말을 합니다 — *"색조만 복사하고 일반적인 SaaS 밀도로 쓰면
> 팔레트만 같고 성격은 하나도 없는 것이 나온다."*

### 2. Marey 열차 운행도표 (1885) — **업계 밖** · **형태**를 가져온다

Tufte 『The Visual Display of Quantitative Information』 표지 그림.

| 속성 | 값 |
|---|---|
| 축 | 가로 = 시간 24시간, 세로 = 역(거리에 비례) |
| 선 | 열차 한 대 = 사선 하나 |
| **기울기** | 속도. 가파를수록 빠름 |
| **수평 구간** | 정차. 길수록 오래 섬 |
| 격자 | 시간 세로선 + 역 가로선 |

**딱 하나 기억나는 것**: **빈 곳이 정보다.** 선이 없는 구간은 "데이터가
없다" 가 아니라 "그 시간에 그 열차는 거기 없었다" 입니다.

**의도적으로 하지 않은 것**: 색. 범례. 강조. 잉크 한 색과 격자뿐입니다.

> 이게 우리 물질세계입니다. `docs/16` §1 초안의 *고유_형태* 항목
> — "타임라인 위의 트랙, 말한 구간은 차 있고 안 말한 구간은 비어
> 있고, 녹음이 끊긴 구간은 구멍" — 과 **같은 구조**입니다.

### 3. The Pudding (pudding.cool) — **업계 밖** · **톤**을 가져온다

| 속성 | 값 |
|---|---|
| 형식 | 비주얼 에세이. 데이터와 디자인이 서사를 옮김 |
| 글 | **말수가 적음** — 일반 기사보다 훨씬 |
| 홈 | 채도 높은 단색 블록 카드(초록·노랑·마젠타·파랑), 번호 + 제목 |

**딱 하나 기억나는 것**: 데이터를 *일반 독자에게 설명한다*는 자세.
분석가용 대시보드가 아닙니다.

> **가져올 것: 말수를 줄이고 그림이 설명하게 하는 것.**
> **버릴 것: 채도.** 우리 화면은 기여도 분쟁 상황에서 읽힙니다.
> 알록달록하면 경박해 보이고, 그건 이 제품이 가장 피해야 할 인상입니다.

### 셋의 공통점 · 차이점

**공통점** — 셋 다 **덜어냄으로** 성립합니다. Linear 는 색을, Marey 는
장식을, Pudding 은 말을 덜었습니다.

**차이점** — Linear 는 *제품 표면*의 절제, Marey 는 *데이터 구조*의
정직, Pudding 은 *독자와의 거리*.

**가져올 것 / 버릴 것**

```
가져온다  Linear  → 액센트 1개 · 표면 사다리 · 4px 격자 · 좁은 굵기 대역
          Marey   → 시간축 위의 평행 트랙 · 빈 곳이 정보 · 잉크 한 색
          Pudding → 말수 줄이기 · 그림이 설명하게 하기

버린다    Linear  → 어두움 (금지 기본값 2번)
          Marey   → 사선(우리는 사람이 이동하지 않으므로 가로선)
          Pudding → 채도 · 유쾌함
```

## ⚠️ 정정 — A-1-5 의 "서체 미지정" 은 틀렸습니다

`font-family` 로 grep 했는데 **`font:` 축약형**에 들어 있었습니다.

```css
body {

    "Noto Sans KR", "Segoe UI", sans-serif;
}
```

**시스템 폰트 스택은 있습니다.** 한글 폰트(`Apple SD Gothic Neo`,

### 그래서 진짜 문제는 무엇인가

| 감사에 적었던 것 | 실제 |
|---|---|
| 서체 미지정 · 심각도 **높음** | 시스템 스택 있음 · 심각도 **중간** |

남는 문제 둘:

1. **기기마다 다른 폰트로 렌더됩니다.** macOS 는 Apple SD Gothic Neo,

   빈약해 맑은 고딕으로 폴백**합니다. 세 폰트의 자폭·획 굵기가 달라
   같은 화면이 기기마다 다른 밀도로 보입니다.
2. **디스플레이 역할이 없습니다.** 지시서 §4.2 는 3역할(디스플레이 /

   대역**을 씁니다. 개성이 생길 자리가 없습니다.

`word-break: keep-all` 이 0건이라는 감사 2번은 **그대로 맞습니다.**
그쪽이 더 큰 문제였습니다.

grep 한 번으로 "없다" 를 단정한 것이 원인입니다. 이 저장소가 반복해서
당한 부류 — **확인한 것과 확인했다고 믿은 것을 구분하지 않은 것** —
와 같습니다. 감사 표의 심각도를 고쳤습니다.

# Stage F — 상태 화면 (지시서 §7)

시작할 때 **로딩 스켈레톤은 0개**였습니다. 대신 정적 문구 다섯 개가
HTML 에 박혀 있었고, 그 문구들은 **화면을 열 때마다 한 번씩 깜빡였습니다.**

## F-1. 무엇이 없었나 — 시작 시점의 실측

| 화면 | 로딩 | 빈 | 오류 |
|---|---|---|---|
| 홈 | ❌ `"불러오는 중…"` 정적 | ✅ | ⚠️ 문구만 |
| 로비 | ❌ `"불러오는 중…"` 정적 | ✅ | ⚠️ `#sub` 한 줄 |
| 프로젝트 설정 | ❌ `"연결 상태를 확인하는 중…"` 정적 | n/a | ✅ |
| 칸반 | ❌ 없음 (빈 화면) | ⚠️ 열별 `"비어 있음"` 만 | ⚠️ 화면 맨 아래 |
| 기여도 | ❌ 없음 | ⚠️ 사람별만 | ⚠️ 위쪽 경고 줄 |
| 승인 | ❌ 없음 | ❌ **아무것도 안 나옴** | ⚠️ 화면 맨 아래 |

`⚠️` 는 전부 같은 모양입니다 — **오류가 나도 목록 자리는 텅 빈 채**로
있습니다. 그러면 실패와 0건이 화면에서 구분되지 않습니다. 이 저장소가
반복해 당한 부류 그대로입니다.

## F-2. 지연 200ms — 안 뜨는 것이 기본값

지시서 §4.7: *200ms 안에 끝나면 로딩 표시를 아예 띄우지 않는다.*

`src/lib/ui/pending.ts` 의 `whileLoading` 이 그 판단을 혼자 합니다.
타이머를 주입받으므로 테스트가 실제로 200ms 를 기다리지 않습니다.

```
0ms ─────────── 200ms ─────────────────────▶
│                 │
└ 요청 시작        └ 여기서도 안 끝났으면 그때 스켈레톤
```

**실제 브라우저 확인** — 화면 넷을 20ms 간격으로 들여다봤을 때
스켈레톤이 목격된 횟수 **0**. 1.2초 지연을 걸면 정상적으로 뜹니다.

### 최소 노출 시간은 두지 않았습니다

205ms 에 끝나면 스켈레톤이 5ms 만 보입니다 — 여전히 깜빡임입니다.
흔한 해법은 "한 번 보였으면 최소 N ms 유지" 인데 **지시서에 그 N 이
없습니다.** `track/bar.ts` 에서 근거 없는 상수를 만들 뻔한 적이 있어
(§Stage E), 이번에는 관찰되기 전에는 안 만들기로 했습니다.

## F-3. 스켈레톤 — 스피너 단독 금지

`src/lib/ui/skeleton.ts`. 실제 레이아웃 클래스(`card`·`col`)를 **그대로**
씁니다. 따로 잡으면 공용 CSS 가 바뀔 때 스켈레톤만 옛 모양으로 남습니다.

### ⚠️ 격자 안의 격자 — 실제로 밟은 것

`#board` 는 이미 `class="board"` 이고 `#members` 는 이미
`class="score-grid"` 입니다. 스켈레톤이 그 클래스를 **또** 달면 격자
항목 하나로 들어가 카드 셋이 한 칸에 우겨넣어집니다.

→ 겉껍질 `.sk-wrap` 을 `display: contents` 로. 레이아웃에서 사라지고
안의 카드가 그릇의 격자에 직접 놓입니다.
**브라우저 확인**: 1088px 폭에서 칸반 열 셋 352/324px, 기여도 카드 셋 352px.

### ⚠️ 낭독기에게 거짓말하지 않기

스켈레톤은 **아직 없는 것을 그리는 그림**입니다. 그대로 두면 사람이
있지도 않은 카드 셋을 듣게 됩니다.

- 안에 **글자가 한 자도 없음**
- 통째로 `aria-hidden="true"`
- 그릇에 `aria-busy="true"`, 지울 때 **같이 뗌**

`#roster` 는 `<ul>` 이라 `<div>` 겉껍질을 못 씁니다 — `rowItems()` 가
`<li>` 를 내고 항목마다 `aria-hidden` 을 답니다.

### ⚠️ 폴링 화면은 첫 번째만

로비는 3초마다 갱신합니다. 스켈레톤을 매번 켜면 **살아 있는 참가자
목록이 주기적으로 회색 막대로 바뀝니다.** `roster.length === 0` 일 때만
켭니다.

## F-4. 빈 상태 — 셋을 반드시 말한다

```
what   이 자리에 원래 무엇이 오는가
why    지금 왜 비어 있는가          ← 빠지면 고장으로 읽힌다
how    채우려면 무엇을 하는가
```

`why` 를 선택 항목으로 두지 않았습니다. **타입이 강제하므로 빠뜨릴 수
없습니다.**

### 승인 화면은 상태에 따라 다른 말을 합니다

후보 0건에는 네 가지 뜻이 있고, **사람이 할 일이 각각 다릅니다.**

| 회의 상태 | 왜 비었나 | 사람이 할 일 |
|---|---|---|
| `queued`·`processing` | 아직 처리 중 | 기다린다 |
| `needs_review` + 0건 | 뽑을 게 없었다 — **고장이 아니다** | 기다려도 안 바뀐다 |
| `confirmed` | 다 검토했다 | 칸반으로 |
| `failed` | 처리가 실패했다 | 트랙을 본다 |

하나로 덮으면 사람은 영원히 새로고침합니다.

## F-5. 오류 상태 — 코드를 감추지 않는다

`HTTP 403` 과 `HTTP 500` 은 **다른 사람이 다른 일을 해야 하는** 상황
입니다. 앞은 팀장이 초대해 주면 되고, 뒤는 팀이 고칠 수 없습니다.
그 구분을 화면이 지우면 아무도 못 고칩니다.

**없는 지원 창구는 지어내지 않습니다.** 흔한 빈칸이 "고객센터에
문의하세요" 인데 이 제품에는 고객센터가 없습니다. `help` 는 선택이고,
실제로 갈 곳이 있을 때만 채웁니다. `describeHttpStatus` 는 **모르는
코드에 null 을 돌려줍니다** — 아무 설명이나 붙이면 사람이 그걸 믿고
엉뚱한 데를 고칩니다.

오류는 이제 **목록 자리에** 뜹니다. 예전처럼 화면 맨 아래 한 줄만
남기면 목록은 텅 빈 채고, 실패와 0건이 같은 모양이 됩니다.

## F-6. 결함 58 — 빈 요소가 선만 남긴다

기여도 오류 화면에 **아무것도 없는 가로줄 두 개**가 생겼습니다.
`#notice` 가 `.note`(위쪽 1px 선)인데, 서버 문구가 아직 안 왔거나
오류가 나면 빈 채로 남기 때문입니다. 사람은 그걸 "여기 뭔가 빠졌다"
로 읽습니다.

→ `.note:empty { display: none }`.

전 화면을 훑어 **내용 없이 장식만 그리는 요소**를 다시 셌습니다.
남은 것은 전부 의도된 것입니다 — 입력칸, 트랙 막대(`.tl`), 분류 막대.

## F-7. 되돌려서 확인한 것

| 되돌린 것 | 결과 |
|---|---|
| `whileLoading` 의 `finally` 제거 | **실패해도 지운다** 1개 실패 |
| 지연을 0 으로 | 깜빡임 테스트 1개 실패 |
| `clearSkeleton` 이 진짜 내용도 지우게 | 1개 실패 |

### ⚠️ 두 번 안 깨졌습니다 — 둘 다 **내 검사가 틀린 것**이었습니다

**(1) 스켈레톤 클래스 가드.** `.sk-track` 을 지워도 통과했습니다.
`class="..."` 리터럴만 훑었는데, 막대의 클래스는
`class="sk${kind && \` sk-${kind}\`}"` 로 **조립**됩니다. 조립되는
쪽도 세도록 고쳤습니다. 세는 개수가 6 미만이면 실패하게 해서, 다음에
또 못 세면 그 자체가 드러나게 했습니다.

**(2) 정적 로딩 문구 가드.** `project.html` 에 문구를 되돌려도
통과했습니다. 정규식 끝에 `<` 를 넣어 **다음 요소의 여는 꺾쇠까지
먹었기** 때문입니다 — `<div id="gh-health">` 가 바로 뒤 `<p
id="gh-headline">` 을 통째로 가렸습니다. `<` 를 뺐습니다.

**결함 49·57 에 이어 세 번째입니다.** 되돌림이 아무것도 안 깨뜨리면
"가드가 불필요" 가 아니라 **"내 검사가 다른 이유로 통과 중"** 을 먼저
의심할 것.

# Stage G — 모바일 재점검 · 지역 스타일 흡수 (지시서 §9)

## G-1. 지역 `<style>` 을 끌어올리려다 멈춘 이유

329줄(지금 공용 CSS 의 25%)을 흡수하려고 먼저 **무엇이 겹치는지**
세었습니다. 두 화면 이상에 같은 선택자가 **열둘** 있었습니다.

그리고 **열둘이 전부 뜻이 달랐습니다.**

| 선택자 | 화면마다 무엇인가 |
|---|---|
| `.warnings` | 통화=맨 목록 · 기여도=**색 상자** · 승인=붉은 목록 |
| `.who` | 통화=`flex:1` 레이아웃 · 기여도=**굵은 이름** |
| `.conf` | 기여도=회색 작은 글 · 승인=**낮으면 굵은 경고** |
| `.hint` | 홈=회색 주석 · 승인=옅은 안내 |
| `.blockers` | 로비=**노란 상자** · 승인=붉은 목록 |
| `#result` | 칸반=붉은 오류 · 승인=`flex:1` 레이아웃 |
| `#submit` | 로그인=주 버튼 · 승인=`flex:0 0 auto` |
| `.card header` | 기여도=baseline · 승인=center |
| `li` | 녹음=여백만 · 로비=**2열 격자** |

**끌어올리면 결함 55·56 이 열두 번 반복됩니다.** 그 둘은 공용 CSS 에
넣은 이름을 화면이 이미 다른 뜻으로 쓰고 있어서 생겼습니다.

그래서 **뜻이 같은 것만** 옮겼습니다.

## G-2. `.panel` — 뜻이 정말 같았던 하나

통화·녹음·로비·설정이 똑같은 `section { border … }` 를 **네 벌** 갖고
있었습니다. 반올림값만 조금씩 달랐습니다(`.625rem` ×3, `.75rem` ×1).

⚠️ **요소가 아니라 역할 클래스로** 올렸습니다. 공용 CSS 에
`section { border … }` 를 넣으면 홈의 `<section class="card">` 까지
테두리가 생깁니다 — id·요소로 공용 규칙을 걸었다가 두 번 당했습니다.

카드와 패널을 나눈 근거: **카드는 목록의 한 항목, 패널은 화면의 한
구역**입니다. 그래서 카드는 배경으로, 패널은 선으로 구분합니다.

## G-3. 결함 59 — 사람이 제일 먼저 보는 화면만 다른 색

```
login.html   #submit { background: #2563eb }   ← 파랑
나머지 8화면  class="primary" → --primary       ← 청록 #0d5c63
```

로그인 버튼만 **브랜드 밖**이었습니다. 첫인상을 만드는 화면인데도
아무도 몰랐습니다 — 그 화면만 따로 열어 보면 파란 버튼이 이상하지
않기 때문입니다.

`class="primary"` 를 붙이고 지역 규칙에서 색을 뺐습니다.

## G-4. 결함 60 — 밝은 모드만 보면 절대 안 보이는 것

화면 넷이 `color: #fff` 를 손으로 적어 뒀습니다.

| | 밝은 모드 | 어두운 모드 |
|---|---|---|
| `#fff` on `--ok` | 6.44:1 ✅ | **2.06:1 ❌** |
| `#fff` on `--warn` | 5.91:1 ✅ | **1.91:1 ❌** |
| `#fff` on `--bad` | 7.54:1 ✅ | **2.41:1 ❌** |

어두운 모드에서 의미색이 **밝게 뒤집히는데** 글자만 흰색으로 남습니다.
WCAG AA(4.5:1)는커녕 3:1 도 못 넘습니다.

해법은 **토큰 체계 안에 이미 있었습니다.** `--ink-000` 은 페이지
배경이라 모드마다 이미 뒤집힙니다.

```css
--on-semantic: var(--ink-000);
```

| | 밝은 | 어두운 |
|---|---|---|
| `--ok` | 6.27:1 ✅ | 9.16:1 ✅ |
| `--warn` | 5.75:1 ✅ | 9.89:1 ✅ |
| `--bad` | 7.34:1 ✅ | 7.81:1 ✅ |

**실제로 눌러서 재확인** — 승인/거절 버튼의 선택 상태를 브라우저에서
클릭하고 계산한 값: 밝은 6.27·7.34, 어두운 9.16·7.81.

> ⚠️ 처음 잰 값은 `bg=rgba(0,0,0,0)` 이라 **버튼 배경이 안 칠해지는
> 줄 알았습니다.** 비활성 버튼에 클래스를 손으로 붙이고 전환이 끝나기
> 전에 읽은 것이었습니다. 실제로 눌러서 400ms 기다리니 제대로 나왔습니다.
> 측정 방법이 틀리면 없는 결함이 생깁니다.

## G-5. 결함 61 — Stage D 타이포가 한 번도 화면에 나온 적이 없다

`app.css` 안에서 `h1` 이 **두 번** 정의돼 있었습니다.

```
75줄   h1 { font-size: var(--fs-display); letter-spacing: var(--ls-display); }   ← Stage D
188줄  h1 { font-size: 1.5rem;           letter-spacing: -0.02em; }              ← 옛것
```

특성도가 같으면 **나중 것이 이깁니다.** 그래서 Stage D 에서 만든
`--fs-display`(1.75rem)·`--ls-display`(-0.035em) 는 만들어 놓고 한 번도
쓰인 적이 없었습니다.

브라우저로 봐도 "제목이 좀 작네" 정도라 눈에 안 띕니다. **이 저장소의
대표 실패 방식(만들어 놓고 아무도 안 씀)이 자기 파일 안에서 일어난
것**입니다.

고친 뒤 실측: `h1 = 28px / -0.98px` (= 1.75rem / -0.035em) ✅

`h2` 도 같았습니다. 옛 블록을 지울 때 `margin: 0 0 .5rem` 을 같이
날리면 브라우저 기본 여백(0.83em)이 들어와 제목이 둥둥 뜨므로,
여백만 Stage D 블록으로 옮겼습니다.

## G-6. 가드 — 같은 **속성**을 두 번 정하지 않는다

같은 선택자가 두 번 나오는 것 자체는 정상입니다. `.a, .b` 로
바탕을 깔고 `.b` 에서 높이만 다시 잡는 식이니까요. 문제가 되는 것은
**같은 속성**을 두 번 정하는 것입니다 — 그때만 "어느 값이 이기나" 를
사람이 세어 봐야 합니다.

그래서 가드를 속성 단위로 만들었습니다. 예외 목록이 필요 없습니다.
대신 걸리는 두 곳을 정리했습니다.

- `.num`/`time` — 같은 뜻의 블록 둘 → 하나로 (`dd` 를 합침)
- `.rangebar, .cov` 의 `height` — 공통에서 빼고 **각자** 정하도록
  (⚠️ `.cov` 는 나중에 통째로 지웠습니다 — 결함 75. 그리는 화면이 0곳이었습니다)

가드 셋을 새로 넣었습니다.

| 가드 | 막는 것 |
|---|---|
| 지역 `<style>` 에 날 색 금지 | 결함 59·60 (토큰 우회 0건, §11-A 2번) |
| `--on-semantic` 이 Layer 1 참조 | 결함 60 (고정값이면 어두운 모드가 깨짐) |
| 공용 CSS 가 같은 속성을 두 번 | 결함 61 |

**되돌려서 확인했습니다** — 로그인을 파랑으로, `#fff` 를 되살리고,
`--on-semantic` 을 고정값으로, 옛 `h1` 블록을 복원. 넷 다 잡혔습니다.

`classList.toggle('primary', 조건)` 두 줄로 고쳤습니다. 동의한 뒤에도
동의 버튼이 청록인 채로 남아 있으면 **또 눌러야 하나** 싶게 만듭니다.

실측: 보이는 주 버튼이 전 화면 **1개**.

## H-5. 이모지 넷 → 직접 그린 아이콘

`🏠📋📊⚙️` 를 24×24 격자 위에서 좌표를 **계산해** 그린 SVG 로 바꿨습니다.

이모지가 못 하는 것 셋:
1. **기기마다 다른 그림**이 나옵니다 (Apple·Google·Windows 각각)
2. 색이 박혀 있어 **어두운 모드에서 그대로**고, 선택된 탭이 진해질 때
   아이콘만 안 따라옵니다
3. 크기·베이스라인이 서체에 딸려 있어 세로 정렬이 틀어집니다

⚠️ **lucide 가 아닙니다.** 규격(24×24 · stroke 2 · round)만 같습니다.
네트워크가 없어 실제 path 를 받을 수 없었고, **받은 척하면 다음 사람이
그걸 믿고 원본과 대조하지 않습니다.**

⭐ 기여도 아이콘은 **시그니처가 아이콘이 된 것**입니다 — 시간축 위의
평행 트랙 셋, 그리고 **가운데 줄이 끊겨 있습니다.** 그 구멍이 이 화면의
값어치입니다 (지시서 §11-B 4번 — 반복 모티프가 최소 3곳: 트랙 막대 ·
운행도표 · 탭 아이콘).

테스트가 좌표를 고정합니다 — 안전 영역(3~21) 안, 정수 또는 .5,
색 박아 넣기 금지, 그리고 **`PATHS` 안에 템플릿 구멍이 없을 것**
(이 마크업은 이스케이프 없이 화면에 들어갑니다).

칸반의 `🗣` 도 말풍선 아이콘으로 바꿨습니다. 그 자리는 **이 제품의
대표 주장이 카드에 보이는 곳**이라 기기마다 다른 그림이 나오면 안 됩니다.

⚠️ **흑백 기호(`⚠` `✓` `⚑` `→` `①`)는 그대로 둡니다.** 본문 서체로
그려지고 `color` 를 따라가므로 위 세 문제 중 어느 것도 해당하지
않습니다. 목록 글머리에 SVG 를 넣는 것은 과합니다.

가드는 **변이 선택자 U+FE0F 도** 잡습니다 — 그게 붙으면 `⚠` 같은
흑백 기호가 색 이모지로 강제됩니다. 실제로 `⚠️ 화면이 가려짐` 이
그랬습니다.

# 그다음 — 백필의 남은 구멍 (결함 62)

디자인 Stage A~H 를 끝내고, PR 본문 C 절에 적어 둔 **"백필은 병합된 PR 만 —
커밋·리뷰는 아직"** 을 처리하려고 열었습니다. **두 가지가 다 틀린 기록이었습니다.**

## 커밋 백필은 **할 일이 아니었다**

`contribution/events.py` 의 `EventType` 주석:

> 주의: COMMIT 이벤트는 의도적으로 존재하지 않는다.
> 커밋은 쪼개기가 너무 쉬워서 지표로 쓸 수 없다 (docs/05 §2.1).
> 코드 기여는 병합된 PR 단위로만 집계한다.

**설계 결정입니다.** 제가 PR 본문에 "커밋 백필이 아직" 이라고 적어 둔 것은
**없는 할 일을 만들어 둔 것**이고, 그대로 뒀으면 다음 사람이 그 설계를
모른 채 되돌렸을 것입니다.

## 리뷰 백필은 **이미 되고 있었다**

백필은 웹훅과 같은 모양의 행을 저장하고, `ingest_github_event` 가 그 행의
PR 번호만 읽어 **상세를 다시 조회**합니다. 그 상세에 리뷰가 들어 있으므로
`REVIEW_GIVEN` 이벤트까지 이미 나옵니다.

"백필은 병합된 PR 만" 은 **목록 단계**에 대해서만 맞는 말이었는데, 저는 그걸
"리뷰가 안 들어온다" 로 읽히게 적었습니다.

## ⭐ 그런데 진짜 구멍이 하나 있었다 — 결함 62

```python
pull = mapping.to_pull_request(...)
if pull is None:
    return {"status": "skipped", "reason": "unmapped_author_or_not_merged"}
```

`to_pull_request` 는 **작성자를 팀원에게 못 붙이면 `None`** 을 돌려줍니다.
외부 기여자나 봇의 PR 이 그렇습니다. 그 판단 자체는 맞습니다 — 아무에게나
붙이면 그게 곧 잘못된 기여도니까요.

문제는 그다음입니다. **거기서 끝냅니다.** 그 PR 에 달린 **우리 팀원의
리뷰까지 같이 버려집니다.**

```
dependabot 의 PR  ← 작성자를 못 붙임
  └ 이하늘의 리뷰 "이 버전 올리면 로그인 화면이 깨집니다"   ← 통째로 사라짐
```

오류는 어디에도 안 납니다. 그 사람의 기여도만 조용히 빕니다 — 이 저장소가
반복해 당한 부류 그대로입니다.

**흔한 상황입니다.** 봇 PR 리뷰, 외부 기여자 PR 리뷰, 그리고 **팀원이 GitHub
로그인을 아직 등록 안 한 동안**에도 같은 일이 벌어집니다.

### 고친 방식

리뷰는 작성자가 누구든 **리뷰어 자신의 기여**입니다. 남의 PR 을 읽고 문제를
짚는 것이 그 사람이 한 일이지, 작성자가 누구인지와는 상관이 없습니다.

- `mapping.to_reviews()` 를 `to_pull_request` 밖으로 꺼냈습니다
- `github_ingest.reviews_to_events()` 를 `pr_to_events` 밖으로 꺼냈습니다
  (`author_id: int | None` — 작성자를 몰라도 부를 수 있게)
- `ingest_merged_pull_request` 가 **두 이유를 가릅니다**

```
병합 안 됨       → skipped(not_merged)      이벤트가 없는 게 맞습니다
작성자 못 붙임    → reviews_only              리뷰는 살립니다
```

⚠️ `source_id` 식(`pr_id * 100_000 + reviewer_id`)을 **두 경로에서 같게**
뒀습니다. 나중에 작성자가 로그인을 등록해 그 PR 이 다시 처리되면 같은
리뷰가 같은 id 로 와서 `persist_events` 가 막아 줍니다.

### ⚠️ 옛 테스트가 결함을 가리고 있었다

`unmapped_author_or_not_merged` — **한 이유에 두 상황**이 묶여 있었습니다.
그래서 `test_an_unmerged_pr_creates_nothing` 이 통과하는 것이
`test_an_unmapped_author_creates_nothing` 도 통과시켰습니다. 둘 다
`"skipped"` 니까요.

이유를 가르고 나서야 리뷰가 사라지는 경우를 테스트로 쓸 수 있었습니다.
되돌려서 셋 다 깨지는 것을 확인했습니다.

## 남은 것

**커밋 백필은 목록에서 지웁니다** — 할 일이 아니라 설계 결정입니다.
백필에 실제로 남은 한계는 하나뿐입니다: **네트워크가 없어 실제 GitHub
조회를 한 번도 못 돌려 봤습니다.** 배선·멱등·범위 제한·잘림 표시는 전부
테스트했지만, `HttpGitHubClient` 가 실제 응답을 받는 것은 확인 못 했습니다.

# 감사 #8 — 진행률을 쓰기만 하고 읽는 곳이 0곳이었다

`pipeline/steps.py` 의 `RedisProgress` 는 처음부터 있었고, docstring 은
이렇게 적혀 있었습니다.

> "Redis 해시에 진행률을 쓴다. **API가 SSE로 프런트에 흘린다.**"

**그 API 가 없었습니다.** 1시간 회의는 처리에 10분이 걸릴 수 있는데, 그
10분 동안 화면이 할 수 있는 말은 "처리 중입니다" 뿐이었습니다 — 멈춘
건지 도는 건지도 몰랐습니다.

## ⚠️ SSE 로 안 만들었습니다

감사는 "SSE 엔드포인트가 존재하지 않는다" 고 적었지만, **SSE 는 이
저장소가 이미 거부한 방식**입니다. `lobby.ts` 의 주석이 그 근거입니다 —
*"SSE·WebSocket 을 붙이면 서버에 상태가 생기고, 그건 이 화면 하나 때문에
지불하기엔 비쌉니다. 3초 폴링이면 충분합니다."*

로비는 이미 3초마다 폴링합니다. **읽기 엔드포인트 하나**면 새 연결도 새
상태도 필요 없습니다. 감사가 제안한 해법이 아니라 **감사가 지적한 문제**를
고쳤습니다.

## ⚠️ 모르는 것을 0% 로 답하지 않는다

진행률이 없는 이유는 셋입니다 — 아직 시작 안 함 · 이미 끝남 · Redis 가
없음. 전부 "0%" 로 답하면 사람은 **멈춰 있다**고 읽습니다.

`stage` 가 `None` 이면 모르는 것이고, 문구는 **회의 상태를 함께 봐서**
정합니다.

```
처리 중 + 진행률 없음  →  "처리 중입니다 — 진행 상황은 아직 알 수 없습니다"
처리 끝 + 진행률 없음  →  (아무 말도 안 함. 기다릴 필요가 없다)
```

## ⭐ 키가 어긋나면 조용히 빈 값이 온다

`teamflow:meeting:{id}:progress` 가 **두 파일에 손으로** 적혀 있습니다.
한쪽만 바꾸면 읽는 쪽이 빈 값을 받고, 화면은 영원히 "알 수 없습니다"
라고 말합니다. 오류는 어디에도 안 납니다.

그래서 테스트가 **실제로 쓰고 실제로 읽습니다** — `RedisProgress` 로
쓰고 `read_progress` 로 읽어 같은 값이 나오는지 봅니다. 키를 한 글자
바꿔 봤더니 그 테스트만 정확히 깨졌습니다.

## 브라우저 확인

```
Redis 없음 + 처리 완료  →  ""                      (0% 라고 안 함)
처리 중                →  "말을 글로 옮기는 중 · 60% — 3/5 트랙"
진행률 API 500         →  진행 문구만 빔 · 참가자 3명 그대로
페이지 오류             →  0건
```

`transcribe` 같은 우리 용어는 화면에 안 나갑니다.

## ⚠️ 같은 결함을 한 층 위에서 반복하지 않기

읽기 엔드포인트를 만들어 놓고 **부르는 화면이 없으면** 정확히 같은
결함입니다. 그래서 가드가 엔드포인트의 존재가 아니라 **호출**을 셉니다
(결함 47 교훈). 로비의 호출을 지워 보니 그 가드가 잡았습니다.

- 홈·로그인의 두 번째는 `#install-now` — 브라우저가 `beforeinstallprompt`
  를 쏘기 전까지 **숨어** 있습니다
- 로비의 두 번째는 `#record` — 전원 동의 전까지 **비활성**이고,
  `button.primary:disabled` 규칙이 배경을 투명하게 만들어 회색으로 그려집니다

셋 다 **사람 눈에는 주 버튼이 아닙니다.** 도구를 "보이고 · 비활성이 아니고 ·
배경이 실제로 칠해진 것" 만 세도록 고치니 전 화면 1개 이하였습니다.

⚠️ Stage G 에서도 같은 자리에서 반대 방향으로 틀렸습니다 — 그때는
**비활성 버튼에 클래스를 손으로 붙이고 전환 전에 읽어** "배경이 안
칠해진다" 고 볼 뻔했습니다. 같은 버튼, 같은 상태, 반대 오판입니다.

### 2. "버튼 대비 1.00:1"

`contrast.mjs` 가 `--dim` · `--accent` · `--on-accent` 를 읽고 있었습니다.
**Stage D 에서 이름이 바뀐 토큰들**입니다(`--text-subtle` · `--primary` ·
`--primary-fg`). 없는 이름은 빈 문자열을 돌려주고, 빈 문자열끼리 비교하면
1.00:1 이 나옵니다.

즉 이 도구는 **Stage D 이후로 아무것도 재고 있지 않았습니다.** "대비 미달
0" 은 다행히 `stageH.mjs` 가 **실제로 그려진 글자와 배경**을 재서 나온
값이라 사실이었지만, 토큰 쪽 확인은 반년째 빈 검사였던 셈입니다.

⭐ **도구도 낡습니다.** 코드는 테스트가 지키는데 측정 도구는 아무도 안
지킵니다. 그리고 낡은 도구는 **틀린 값이 아니라 안심하는 값**을 냅니다.
