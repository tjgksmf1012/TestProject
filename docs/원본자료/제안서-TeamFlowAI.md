## 01  프로젝트 개요

TeamFlow AI는 팀 프로젝트의 업무 관리, GitHub 개발 활동, 회의 기록과 분석을 하나의 플랫폼에 통합하는 웹 기반 협업 시스템이다. AI 회의 리뷰는 독립 서비스가 아니라 협업 플랫폼의 핵심 모듈로 동작하며, 회의에서 추출된 결정과 할 일을 칸반 보드·담당자·마감일에 바로 연결한다.

프로젝트 한 줄 소개프로젝트와 팀원을 관리하고, GitHub 활동과 업무 수행 데이터를 수집하며, 회의 음성을 딥러닝으로 분석해 결정·업무·비효율 구간을 추출한 뒤 팀 기여도와 프로젝트 위험을 근거 기반으로 보여주는 AI 협업 플랫폼이다.

## 02  문제 정의 및 개발 필요성

기존 협업 도구는 업무를 등록하고 상태를 변경하는 기능에 집중한다. 그러나 대학생 팀 프로젝트에서는 실제로 다음 문제가 반복된다.

- 회의에서 해야 할 일이 언급되지만 담당자와 마감일이 빠진다.

- 회의 결정이 업무 보드에 반영되지 않아 같은 주제를 다시 논의한다.

- 커밋 횟수만으로는 중요한 기능 개발과 단순 수정의 차이를 알기 어렵다.

- 특정 팀원에게 업무가 집중되어도 제출 직전까지 발견하지 못한다.

- 교수자는 결과물만 보고 팀 내부의 실제 진행 과정과 기여를 파악하기 어렵다.

- 회의록, GitHub, 칸반 보드가 분리되어 있어 프로젝트의 전체 흐름을 연결해서 보기 어렵다.

핵심 해결 방식회의에서 “민수가 금요일까지 로그인 API를 구현한다”는 문장이 나오면 AI가 결정·담당자·마감일을 추출하고, 사용자의 확인 후 실제 업무로 등록한다. 이후 GitHub 커밋과 PR이 해당 업무에 연결되며, 일정 지연과 수행 근거가 대시보드에 함께 표시된다.

## 04  협업 플랫폼 핵심 기능

### 4.1  프로젝트·팀원·역할 관리

프로젝트 생성부터 역할 배정까지 초기 협업 구조를 만든다.

- 팀 생성 및 초대 링크·코드 제공

- 팀원별 기술 스택·선호 역할·가능 시간 등록

- 역할 추천 및 책임 범위 정의

- 제출일·중간 점검일·마일스톤 설정

### 4.2  칸반 보드와 업무 의존관계

단순 할 일 목록이 아니라 선행·후행 작업과 병목을 관리한다.

- 할 일·진행 중·검토·완료 상태 관리

- 담당자·마감일·우선순위·예상 난이도

- 업무 간 선행 관계와 차단 상태

- 지연 업무가 다른 작업에 미치는 영향 표시

### 4.3  GitHub 활동 연동

개발 저장소의 실제 활동을 프로젝트 업무와 연결한다.

- 커밋·Pull Request·Issue·리뷰·병합 기록 수집

- 커밋 메시지와 diff 기반 작업 유형 분류

- 업무 번호 또는 브랜치명으로 관련 작업 자동 연결

- 단순 커밋 수가 아닌 기능·버그 수정·테스트·문서 활동 구분

### 4.4  팀 기여도 분석

점수를 임의로 생성하지 않고 활동 데이터를 항목별로 보여준다.

- 업무 완료율·기한 준수·GitHub 활동·회의 활동·문서 활동 분리

- 항목별 가중치와 산출 근거 공개

- 교수자와 팀원이 원본 활동까지 확인 가능

- 발언량만으로 기여도를 평가하지 않음

### 4.5  프로젝트 위험 및 업무 편중 탐지

제출 직전이 아니라 진행 중에 문제를 발견한다.

- 마감 임박 대비 낮은 완료율

- 특정 팀원에게 과도하게 집중된 업무

- 최근 활동 감소와 장기 미완료 업무

- 선행 작업 지연으로 인한 연쇄 병목

- 근거 기반 재배정 및 일정 조정 제안

### 4.6  주간·최종 보고서 자동 생성

플랫폼에 쌓인 활동을 제출 가능한 기록으로 정리한다.

- 주간 완료·진행·지연 업무 요약

- 주요 회의 결정과 미해결 안건

- 팀원별 역할과 실제 수행 근거

- 문제 발생과 해결 과정

- 최종 프로젝트 타임라인과 회고

## 05  AI 회의 리뷰 모듈의 협업 기능 연동

AI 회의 리뷰는 회의를 따로 분석하고 끝나는 기능이 아니다. 회의에서 나온 결정·업무·질문·미해결 안건을 프로젝트의 기존 업무, GitHub 활동, 일정과 연결하는 것이 핵심이다.

회의에서 감지한 내용

협업 플랫폼에서의 후속 동작

“로그인 API는 민수가 금요일까지 구현한다.”

업무 후보 생성 → 담당자 민수·마감일 금요일 입력 → 확인 후 칸반 등록

“DB 설계가 끝나야 API를 시작할 수 있다.”

DB 설계를 선행 업무로 연결하고 API 작업을 차단 상태로 표시

“지난주에 JWT로 결정했는데 세션으로 바꾸자.”

이전 회의 결정과 충돌 후보 표시 → 최종 결정 변경 여부 확인

“통합 테스트도 해야 합니다.”

담당자·마감일이 없는 불완전 업무로 경고

배포 방식이 10분 동안 반복 논의됨

반복·미결정 구간 표시 → 다음 회의 우선 안건으로 등록

회의에서 맡은 업무와 실제 코드 활동 발생

업무 카드와 커밋·PR을 연결해 수행 근거로 표시

대표 사용자 경험회의 종료 → AI 분석 완료 → 팀장이 결정·업무 후보를 검토 → 승인된 업무가 칸반 보드에 생성 → GitHub 브랜치와 연결 → 다음 회의에서 진행 상태와 이전 결정이 자동으로 제시된다.

## 06  AI 회의 리뷰 세부 기능

### 6.1  음성 인식 및 회의 자막

회의 음성을 검색 가능한 화자별 대본으로 변환한다.

- 실시간 녹음 또는 음성 파일 업로드

- 문장·단어 단위 타임스탬프 생성

- 팀원 이름·프로젝트 용어·기술 용어 사전 보정

- 신뢰도가 낮거나 동시 발언이 발생한 구간 표시

- 자막 클릭 시 해당 음성 위치 재생

- “음”, “어”, “약간” 등 말버릇 통계

### 6.2  화자 구분 및 발언 흐름

누가 언제 말했는지 분리하고 발언 관계를 분석한다.

- SPEAKER_00을 등록된 팀원 이름과 연결

- 팀원별 발언 시간·횟수·평균 길이

- 동시 발언·겹침·장시간 연속 발언 구간

- 질문 후 응답자와 응답까지 걸린 시간

- 제안·질문·결정 등 발언 역할과 함께 참여 흐름 표시

### 6.3  발언 유형 딥러닝 분류

각 발언이 회의에서 수행한 역할을 분류한다.

- 질문·정보 제공·제안·동의·반대·보완 의견

- 결정·업무 요청·일정 약속·확인 요청

- 맞장구·농담·잡담·주제 이탈·미완성 발언

- “제안 → 반대 → 보완 → 결정” 흐름 시각화

- 결정 발언 뒤 담당 업무가 실제 등록됐는지 검증

### 6.4  감정 단정 없는 음성 변화 분석

사람의 감정을 확정하지 않고 개인 기준의 음성 특징 변화만 표시한다.

- 말하기 속도·음량·피치·침묵·발화 리듬

- 개인의 회의 평균 또는 이전 회의 평균과 비교

- 속도와 음량이 동시에 크게 변한 구간 표시

- 회의 전반·후반의 응답 지연과 침묵 변화

- “화남”이 아닌 “음성 변화 가능 구간”으로 표현

### 6.5  비효율적 회의 구간 탐지

회의 시간이 길어지거나 실행 결과가 남지 않는 원인을 찾는다.

- 의미가 유사한 내용이 반복된 구간

- 장시간 논의했지만 결정이 없는 안건

- 회의 목표에서 벗어난 주제 이탈 후보

- 담당자·마감일·산출물이 빠진 불완전 업무

- 질문했지만 관련 응답이 없는 항목

- 이전 결정과 현재 발언의 모순·번복 후보

- 후반부 침묵·이탈률·응답 지연 변화

### 6.6  LLM 회의록 및 AI 코치

딥러닝·통계 결과를 사람이 이해할 수 있는 구조로 정리한다.

- 핵심 요약·결정 사항·미해결 안건

- 팀원별 할 일·담당자·마감일 구조화

- 다음 회의 우선 안건 추천

- 비효율 구간의 원인과 개선 방법 설명

- 모든 리뷰에 시간 구간과 원문 발언을 근거로 연결

- 자연어 질문: “지난 회의에서 배포 관련 결정만 보여줘”

## 07  기여도 분석 설계

1. 업무·GitHub·회의 데이터를 합친 기여도 근거와 프로젝트 위험 원인을 확인한다.

## 19  기대 효과 및 차별성

- 회의록을 생성하는 데서 끝나지 않고 회의 결정이 실제 업무로 실행되는 과정까지 연결한다.

- 커밋 횟수 중심 평가를 피하고 업무·코드·회의·문서 근거를 함께 제공한다.

- 프로젝트가 지연된 뒤가 아니라 업무 편중과 병목을 조기에 발견한다.
