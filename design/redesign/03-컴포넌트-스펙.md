## TrackRibbon ⭐ 시그니처

이 제품에서 가장 중요한 컴포넌트. 하나를 만들어 세 배율로 씁니다.

```ts
interface TrackRibbonProps {
  /** 0~1 사이 구간들. 겹치지 않고 정렬돼 있어야 함 */
  segments: Array<{
    start: number;              // 0~1
    end: number;                // 0~1
    kind: 'known' | 'unknown' | 'empty';
  }>;
  size: 'lg' | 'md' | 'sm';     // 30 / 14 / 6 px
  /** lg에서만: 시간 눈금 표시 */
  axis?: { durationMin: number; ticks?: number };
  /** 스크린리더용 요약. 필수 */
  label: string;                // 예: "박지원 트랙 · 커버리지 42%"
  animateOnMount?: boolean;     // 최초 1회 좌→우 스윕 320ms
}
```

**states**: `empty`(전부 --ribbon-empty, 축은 그림) / `partial` / `complete`

**variants**
| size | 높이 | 쓰는 곳 | 축 |
|---|---:|---|---|
| `lg` | 30px | 회의 로비, 녹음 | 0~40분 눈금 |
| `md` | 14px | 홈 회의 목록 | 없음 |
| `sm` | 6px | 기여도 확신 폭 | 없음 |

**a11y**
- `role="img"` + `aria-label={label}`
- 색만으로 구분 금지 — `unknown` 구간은 **45° 빗금 패턴**을 함께 넣습니다
  (SVG `<pattern>`). 흑백 인쇄·색각 이상에서도 구분돼야 합니다.
- `prefers-reduced-motion`에서 스윕 없음

**🔴 금지**
- 여러 사람의 리본을 같은 축에 정렬해 길이 비교를 유도하지 말 것
- `known` 구간 길이를 **기여도 값**에 비례시키지 말 것 (확신도에 비례)
- `unknown`에 빨강 계열 금지

## StatusChip

회의·업무 상태. 점 하나로 상태를 표현하던 현재 방식을 대체합니다.

```ts
interface StatusChipProps {
  status: 'open' | 'processing' | 'review' | 'done' | 'failed';
  size?: 'sm' | 'md';
}
```

| status | 라벨 | 색 | 형태 |
|---|---|---|---|
| `open` | 녹음 전 | `--c-ink-faint` | 빈 원 |
| `processing` | 처리 중 | `--c-ink-muted` | 회전 호 |
| `review` | 검토 필요 | `--c-evidence` | 채운 원 |
| `done` | 완료 | `--c-ink-muted` | 체크 |
| `failed` | 실패 | `--c-unknown` | 삼각 |

**🔴 금지**: 색만 다르고 라벨·형태가 같은 구현. 실패에 빨강 금지
(트랙이 끊긴 건 사용자 잘못이 아님).

## EvidenceChip

"이건 근거가 있다"를 표시하는 유일한 방법.

```ts
interface EvidenceChipProps {
  utteranceIds: number[];       // 예: [1, 3] → "근거 #1 #3"
  onSelect?: (id: number) => void;
  variant?: 'inline' | 'block';
}
```

- 색 `--c-evidence`, 배경 `--c-evidence-tint`, radius `--r-full`
- 번호는 모노
- 클릭 시 해당 발화로 이동 (검토 화면: 우측 판 + 좌측 전사 스크롤)
- **근거가 없으면 이 컴포넌트를 렌더하지 말고** `NoEvidenceNotice`를 렌더

## NoEvidenceNotice

```
⚠ 근거 없음 — 등록할 수 없습니다
```
- `--c-unknown` + 아이콘. 이게 있으면 등록 버튼은 **영구 비활성**.
- 담당자·마감을 채워도 활성화되지 않습니다. 이 제품의 안전장치입니다.

## CandidateCard

```ts
interface CandidateCardProps {
  candidate: {
    id: string;
    title: string;              // AI가 뽑은 것 — 편집 불가
    confidence: number;         // 0~1
    evidenceIds: number[];
    uncertaintyReasons: string[];
  };
  assignee: string | null;      // 사람이 정하는 것
  dueDate: string | null;
  selected: boolean;
  onSelect / onApprove / onDefer / onReject
}
```

**레이아웃 규칙 — 이게 이 카드의 핵심**
```
┌────────────────────────────────────────┐
│ AI 초안                       확신 92%  │  ← 12px 모노, --c-ink-faint
│ 로그인 API 구현                         │  ← 20px, --c-ink
│ [근거 #1] [근거 #3]                     │  ← EvidenceChip
│ ┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈  │  ← 1px dashed --c-line
│ 담당자 [ ▾ ]   마감 [ ]                 │  ← 사람의 몫
│ [ 업무로 등록 ]  나중에  거절            │
└────────────────────────────────────────┘
```

**states**: `default` / `selected`(좌측 3px 인디고 바) / `no-evidence`(등록 영구 비활성)
/ `incomplete`(담당자·마감 미입력 → 비활성 + 사유 표시) / `approved` / `rejected`

**a11y**: 카드 `role="article"`, 키보드 `J`/`K` 순회, `Enter` 등록, `Esc` 선택 해제

**🔴 금지**
- 확신도를 제목보다 크게 표시
- 확신도를 알약 배경으로 강조 (과의존 유발)
- AI 영역과 사람 영역의 시각적 경계 생략

## RangeValue

기여도 구간 표시.

```ts
interface RangeValueProps {
  low: number; high: number;    // 32, 52
  certainty: number;            // 0~1 → 리본 채움
  dotStep?: number;             // 점 하나당 %p (기본 4)
}
```

```
32~52%   ▓▓▓▓▓▓▓▓░░░░░░
모르는 폭 20%p · 점 하나가 4%p
```
- 값은 `--fs-34` 모노. `~`는 `--c-ink-muted`
- 리본 SM 동반. 총 폭은 모든 사람이 동일
- **🔴 금지**: 단일 숫자로 축약, 여러 사람 값을 같은 축에 배치

## AppShell

```
Rail(72px) │ Header(56px) / Content(flex, overflow-y:auto)
```
- `height: 100dvh; overflow: hidden`
- Rail: 아이콘 24px + 라벨 11px. 활성 항목은 좌측 2px 인디고 바
- Header: 화면 제목 + 주 행동 1개 (최대 2개)
- `<1024px`: Rail → 하단 탭바. Header 유지

**🔴 금지**: `body`에 스크롤 발생. Rail에 회의 목록 넣기.

## Disclosure

이 제품은 설명문이 많습니다. 전부 이걸로 접습니다.

```ts
interface DisclosureProps {
  trigger: string;              // "이건 왜 이런가요"
  children: ReactNode;
  defaultOpen?: boolean;        // 기본 false
}
```
- 트리거: 13px, `--c-ink-muted`, 앞에 `▸` 회전 아이콘

**🔴 금지**: 설명 문구를 **삭제**해서 화면을 줄이기. 접기만 합니다.

## PaneGroup

```ts
interface PaneGroupProps {
  panes: Array<{
    id: string;
```

## 공통 규칙

**버튼**
| variant | 배경 | 글자 | 쓰는 곳 |
|---|---|---|---|
| `primary` | `--c-evidence` | 흰색 | 화면당 1개 |
| `secondary` | `--c-surface` + 테두리 | `--c-ink` | 보조 |
| `ghost` | 없음 | `--c-ink-muted` | 3순위 |
| `danger` | `--c-danger` | 흰색 | 녹음 삭제만 |

높이 32px(기본) / 28px(조밀). radius `--r-sm`.

**비활성 버튼은 반드시 사유를 동반합니다.** 버튼 바로 위 12px `--c-unknown`.
누를 수 없는 이유를 말하지 않는 비활성 버튼 금지.

**입력**: 높이 32px, 배경 `--c-sunken`, 포커스 시 `--c-evidence` 2px 링.

**빈 상태**: 점선 테두리 + 무엇을 하면 되는지 + 행동 버튼. 절대 빈 흰 박스 금지.
