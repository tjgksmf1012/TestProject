## 이 작업이 무엇인가

기존 TeamFlow 웹앱을 **React로 이전하면서 레이아웃을 재구성**합니다.
색만 바꾸는 작업이 아닙니다. 지난 시도가 정확히 그 실패를 했습니다.

**스택**: Vite + React + TypeScript + Tailwind CSS v4 + shadcn/ui + TanStack Query + React Router
백엔드는 FastAPI로 그대로. 프런트만 교체합니다.

## 🔴 절대 규칙 (위반 시 작업 실패)

### R1. `body`는 스크롤하지 않는다
앱 셸은 `height: 100dvh; overflow: hidden`. 스크롤은 안쪽 판이 각자 `overflow-y: auto`로 담당합니다.
페이지 전체가 세로로 길어지는 구조는 **금지**입니다.

### R2. 화면별 스크롤 예산을 지킨다
1280×800 뷰포트에서 측정합니다. **초과하면 레이아웃을 다시 쪼개세요.**

| 화면 | 현재 | 상한 |
|---|---:|---:|
| 로그인 | 1.0 | **1.0** (스크롤 없음) |
| 홈 | 2.1 | **1.0** |
| 프로젝트 설정 | **4.6** | **1.0** (섹션당) |
| 회의 로비 | 1.6 | **1.0** |
| 녹음 | 1.5 | **1.0** |
| 통화 | 1.0 | **1.0** |
| 업무 후보 검토 | **3.7** | **1.0** (판별 내부 스크롤 허용) |
| 칸반 | 1.3 | **1.0** (열 내부 스크롤 허용) |
| 기여도 | 2.1 | **1.0** |

"판 내부 스크롤 허용"은 **페이지가 아니라 특정 판만** 스크롤된다는 뜻입니다.

### R3. 청록(teal)을 전부 제거한다
`#16605e`, `#63c0ba` 및 그 계열 값이 코드베이스에 하나도 남으면 안 됩니다.
새 액센트는 인디고 `--c-evidence`입니다. `grep -ri "16605e\|63c0ba\|teal"` 결과가 0이어야 합니다.

### R4. 색은 의미일 때만 쓴다
- 인디고 = 근거가 있다 / 실행 가능하다
- 황토 = 측정하지 못했다
- 그 외 모든 것은 무채색
- **점수·기여도에 초록/빨강 금지.** 결측에 빨강 금지.
- 정보를 색으로만 전달 금지 — 항상 텍스트 라벨이나 형태를 동반.

### R5. 측정값은 모노, 말한 것은 산세리프
`32~52%` `0:47` `커버리지 42%` `근거 #5` `TASK-3` `2026-09-11` 등 **기계가 잰 모든 값**은
`--font-mono` + `tabular-nums`. 사람이 말한 문장은 `--font-sans`.

### R6. 제품의 4대 불변식을 깨지 않는다
1. 순위·리더보드 없음. 사람 목록은 **이름순 고정**. 여러 사람의 값을 같은 축에 세우지 않음.
2. 단일 점수 없음. 항상 구간.
3. 측정 못 한 것을 0으로 치지 않음.
4. 시스템이 최종 점수를 확정하지 않음.

기존 자동 테스트가 이걸 검사합니다. **테스트를 수정해서 통과시키지 마세요.**

### R7. 내부 개발 언어를 사용자 화면에 노출하지 않는다
현재 위반 사례 — 전부 고칠 것:
- 화면 제목 `녹음 생존율 테스트` → `녹음`
- `docs/09 실험 5 — …`, `모드 A(멀티트랙)의 성립 여부` → 삭제
- `실험 조건: ① 화면 켜둠 ② 화면 잠금 …` → 개발자용 진단 패널로 이동(기본 숨김)

### R8. 도달할 수 없는 화면을 만들지 않는다
`보고서` `채팅` `달력` `알림` `활동` `검색` 6개가 내비게이션에 없습니다.
**신규 기능을 더 만들지 마세요.** 범위 결정은 §범위 참조.

## 🟡 반드시 있어야 하는 구조

### 앱 셸
```
┌──────┬────────────────────────────────────┐
│ 레일 │ 헤더 (제목 + 주 행동)   56px 고정   │
│ 72px ├────────────────────────────────────┤
│      │ 작업 영역 — 여기만 스크롤           │
└──────┴────────────────────────────────────┘
```
- 좌측 레일 72px, 아이콘 + 11px 라벨. `홈 / 칸반 / 기여도 / 설정`
- **회의 목록은 레일에 넣지 마세요.** 홈 화면 안에 둡니다.
- 1024px 미만에서 레일은 하단 탭바로 전환.

### 트랙 리본 (시그니처)
하나의 컴포넌트를 세 배율로 재사용합니다. `03-컴포넌트-스펙.md` 참조.
- LG 30px — 로비, 참가자별 40분 축
- MD 14px — 홈, 회의별 커버리지
- SM 6px — 기여도, 확신 폭

**빈 상태에서도 축과 눈금을 그립니다.** 텍스트 목록으로 대체 금지.

### 설명문은 기본 접힘
현재 카드마다 3~5줄 설명이 항상 펼쳐져 있어 화면의 절반을 차지합니다.
`<details>` 또는 disclosure 컴포넌트로 접고, 트리거는 `▸ 이건 왜 이런가요` 형태.
**문구 자체는 지우지 마세요** — 이 제품의 정직한 톤은 자산입니다. 접기만 하세요.

## 범위 — 무엇을 만들고 무엇을 만들지 않는가

**이번에 다룰 화면은 9개뿐입니다**: 로그인 · 홈 · 프로젝트 설정 · 회의 로비 ·
녹음 · 통화 · 업무 후보 검토 · 칸반 · 기여도

지난 시도에서 추가된 `보고서` `채팅` `달력` `알림` `활동` `검색`은
**이번 범위에서 제외합니다.** 라우트를 남겨두되 내비게이션에 노출하지 말고,
새 기능을 더 붙이지 마세요. 핵심 사슬(회의→후보→승인→칸반→PR→기여도)의
완성도가 먼저입니다.

## 작업 순서

에이전트는 이 순서로 진행하고, **각 단계마다 스크린샷을 찍어 R2를 자로 재세요.**

1. **셸부터** — Vite+React 프로젝트, 토큰 주입, 앱 셸(레일+헤더+판), 라우팅.
   이 시점에 화면 내용은 비어 있어도 됩니다. `body` 스크롤이 없는지 확인.
2. **트랙 리본 컴포넌트** — 세 배율 + 빈 상태. Storybook 없어도 데모 라우트 하나 만들어 확인.
3. **기여도** — 제일 원칙이 많이 걸린 화면. 여기서 토큰과 리본이 검증됩니다.
4. **업무 후보 검토** — 3판 레이아웃. 가장 큰 구조 변경.
5. **프로젝트 설정** — 서브내비 분할. 4.6 → 1.0.
6. **홈 · 칸반 · 로비 · 녹음 · 통화 · 로그인**
7. **다크모드 검증** — 반전이 아닌지 확인 (`01-비주얼-방향.md` §7)
8. **접근성 통과** — §검수 참조

## 검수 (완료 선언 전 전부 확인)

```
□ R2 스크롤 예산: 9개 화면 전부 상한 이하 (1280×800 캡처로 실측)
□ grep -ri "16605e|63c0ba" → 0건
□ body에 스크롤바 없음
□ 측정값이 전부 모노 + tabular-nums
□ 다크모드가 라이트의 단순 반전이 아님 (elevation이 명도로 표현됨)
□ 회의 상태가 점 색깔만으로 구분되지 않음 (라벨 동반)
□ 결측 표시에 빨강 없음
□ 사람 목록이 이름순 고정, 점수순 정렬 없음
□ 키보드만으로 후보 승인 → 칸반 이동 → 기여도 확정까지 도달 가능
□ 포커스 링이 모든 인터랙티브 요소에서 보임
□ 본문 대비 4.5:1 이상 (라이트/다크 양쪽)
□ prefers-reduced-motion에서 애니메이션 정지
□ 320px 폭에서 가로 스크롤 없음
□ 기존 백엔드 테스트 통과 (테스트 수정 금지)
```
