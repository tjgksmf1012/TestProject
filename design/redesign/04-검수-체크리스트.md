## A. 자동으로 잴 수 있는 것 (가장 중요)

아래 스크립트를 돌리면 스크롤 예산이 숫자로 나옵니다.

```bash
pip install playwright --break-system-packages && playwright install chromium
python3 measure.py
```

```python
# measure.py
from playwright.sync_api import sync_playwright

BUDGET = {  # 뷰포트(800px) 배수 상한
    "/login": 1.0, "/": 1.0, "/project/1/settings/role": 1.0,
    "/meeting/1/lobby": 1.0, "/meeting/1/record": 1.0, "/meeting/1/call": 1.0,
    "/meeting/1/review": 1.0, "/project/1/kanban": 1.0,
    "/project/1/contributions": 1.0,
}
BASE = "http://localhost:5173"

with sync_playwright() as p:
    b = p.chromium.launch()
    pg = b.new_page(viewport={"width": 1280, "height": 800})
    fails = []
    for path, budget in BUDGET.items():
        pg.goto(BASE + path); pg.wait_for_timeout(900)
        h = pg.evaluate("document.documentElement.scrollHeight")
        ratio = h / 800
        ok = ratio <= budget + 0.01
        print(f"{'OK ' if ok else 'FAIL'} {path:34} {h:5}px  {ratio:.2f} 화면 (상한 {budget})")
        if not ok: fails.append(path)
    b.close()
    print("\n실패:", fails or "없음")
```

```
□ 9개 경로 전부 OK
□ body에 스크롤바 없음 (document.body.scrollHeight <= window.innerHeight)
□ grep -ri "16605e\|63c0ba" src/ → 0건
□ grep -ri "생존율 테스트\|docs/09\|실험 5\|모드 A" src/ → 0건
□ 기존 백엔드 테스트 전부 통과 (테스트 파일 diff 0)
```

## B. 구조 (리스킨 방지 — 여기가 핵심)

지난번 실패를 잡아내는 항목들입니다.

```
□ 앱 셸이 height:100dvh; overflow:hidden 이고, 스크롤이 안쪽 판에서만 발생
□ 검토 화면이 3판(전사·후보·근거)으로 나뉘어 있음
   → 후보 카드가 스크롤 없이 첫 화면에 보이는가?
□ 설정 화면에 좌측 서브내비가 있고, 섹션 전환이 라우팅으로 됨
   → 카드 9개가 여전히 세로로 쌓여 있으면 실패
□ 기여도에서 세 사람 + 확정 폼이 동시에 보임
□ 칸반 카드 높이 120px 이하, 상시 노출 이동 버튼 없음
□ 홈에서 "검토 필요" 회의가 첫 화면 최상단
□ 회의 목록이 좌측 레일이 아니라 홈 화면 안에 있음
□ 설명 문단이 disclosure로 접혀 있음 (삭제된 게 아니라 접힌 것)
```

**판정 요령**: 스크린샷을 지난 캡처와 나란히 놓고, *색을 흑백으로 만들어* 보세요.
흑백으로 만들었을 때 배치가 예전과 같으면 리스킨입니다.

## C. 시각 언어

```
□ 청록색이 화면 어디에도 없음
□ 측정값(퍼센트·시각·건수·날짜·ID)이 전부 모노 + tabular-nums
□ 사람이 말한 문장은 Pretendard
□ 인디고가 "근거 있음 / 실행 가능"에만 쓰임
□ 황토가 "측정 못 함"에만 쓰임
□ 빨강이 되돌릴 수 없는 삭제에만 쓰임
□ 트랙 리본이 로비(LG)·홈(MD)·기여도(SM) 세 곳에 등장
□ 로비 빈 상태에도 축과 눈금이 그려짐
```

## D. 제품 불변식 (깨지면 이 제품이 아님)

```
□ 사람 목록이 이름순 고정 — 점수순 정렬 코드가 없음
□ 여러 사람의 값이 같은 축에 세로로 정렬돼 있지 않음
□ 기여도가 단일 숫자로 표시되는 곳이 없음 (항상 구간)
□ 리본 채움 길이가 기여도가 아니라 확신도에 비례
□ 결측이 0으로 계산되지 않고, 추정했다는 사실이 표시됨
□ 근거 없는 후보의 등록 버튼이 영구 비활성 (담당자·마감 채워도)
□ 확정 폼에서 시스템 값과 다르면 사유 필수
□ 상단 경고문("이 수치로 서로를 비교하지 마세요")이 삭제되지 않음
□ 사람별 발언 수 비교가 기본 화면에 노출되지 않음
```

## E. 접근성

```
□ 본문 대비 4.5:1 이상 (라이트·다크 양쪽, DevTools로 확인)
□ 큰 텍스트·UI 요소 3:1 이상
□ 모든 인터랙티브 요소에 보이는 포커스 링
□ 키보드만으로: 후보 승인 → 칸반 이동 → 기여도 확정 도달 가능
□ 정보가 색으로만 전달되는 곳 없음 (회의 상태·결측·근거 전부 라벨 동반)
□ 리본의 unknown 구간에 빗금 패턴 (흑백·색각이상 대응)
□ 트랙 리본에 role="img" + 의미 있는 aria-label
□ prefers-reduced-motion에서 애니메이션 정지
□ 320px 폭에서 가로 스크롤 없음
□ 다크모드가 라이트의 반전이 아님 (elevation이 명도 차로 표현)
```

## F. UX 라이팅

```
□ 내부 용어가 사용자 화면에 없음 (생존율 테스트, docs/09, 모드 A, 실험 조건)
```
