# 프로젝트 설정 — 4.6 화면 → 1.0 화면

**현재**: 3665px (뷰포트의 4.6배). 이 패키지에서 가장 심각한 화면.

---

## 무엇이 문제인가

카드 9개가 성격 구분 없이 세로로 쌓여 있습니다.

```
프로젝트 상태 (리포트)      ← 읽을거리
팀원 (목록 + 나가기)        ← 관리
내 역할 (기여도 가중치)      ← 내 개인 설정
내 GitHub 계정              ← 내 개인 설정
팀원 초대 (코드)            ← 관리
회의 열기                   ← 행동!
설정 (이름·저장소·진단)      ← 관리
내 녹음 지우기              ← 위험
각주                        ← 읽을거리
```

세 가지가 동시에 잘못됐습니다.

1. **성격이 다른 것들이 동급으로 나열됨.** 내 개인 설정, 프로젝트 관리, 실행,
   파괴적 작업이 전부 같은 흰 카드 + 같은 테두리 + 같은 여백입니다.
2. **"회의 열기"가 설정 안에 숨어 있음.** 이건 이 제품에서 가장 자주 하는 행동인데
   6번째 카드에 있습니다. 아무도 못 찾습니다.
3. **설명문이 항상 펼쳐져 있음.** 카드마다 3~5줄. 화면의 절반이 설명문입니다.

## 새 구조

**좌측 서브내비 + 우측 판.** 각 섹션이 독립적으로 1화면 안에 들어갑니다.

```
┌──────┬──────────────────────────────────────────────────────┐
│      │ TeamFlow 시연 프로젝트          [회의 열기]  ← 주 행동 │
│ 레일 ├───────────────┬──────────────────────────────────────┤
│      │ 내 설정        │                                      │
│ 홈   │  · 역할과 가중치│   (선택된 섹션만 여기 표시)           │
│ 칸반 │  · GitHub 계정 │                                      │
│ 기여 │               │   섹션 하나는 반드시 1화면 이내        │
│ 설정●│ 프로젝트       │                                      │
│      │  · 팀원        │                                      │
│      │  · 저장소 연결 │                                      │
│      │  · 이름과 초대 │                                      │
│      │               │                                      │
│      │ ─────────────  │                                      │
│      │  · 내 녹음 지우기│ ← 위험 구역, 시각적으로 분리         │
│      │               │                                      │
│      │ 200px         │                                      │
└──────┴───────────────┴──────────────────────────────────────┘
```

### 라우팅
```
/project/:id/settings/role        (기본)
/project/:id/settings/github
/project/:id/settings/members
/project/:id/settings/repo
/project/:id/settings/general
/project/:id/settings/danger
```

### 이동시킬 것

| 지금 위치 | 옮길 곳 | 이유 |
|---|---|---|
| **회의 열기** | 헤더 우측 주 행동 버튼 | 설정이 아니라 행동. 가장 자주 씀 |
| **프로젝트 상태** (리포트) | 홈 화면 프로젝트 카드 안 | 읽을거리지 설정이 아님 |
| **내 정보**(사진·자기소개, 현재 홈에 있음) | `설정 > 내 설정` | 홈에 프로필 편집기가 있을 이유 없음 |

## 섹션별 상세

### 내 설정 > 역할과 가중치

```
역할과 가중치

기여도 계산에 쓰이는 값입니다. 겸직이면 나눠 적으세요.

  개발    [ 1 ]   코드 35% · 업무 30%
  기획    [ 0 ]   문서 30% · 업무 30% · 코드 0%
  디자인  [ 0 ]   문서 35% · 업무 30% · 코드 0%
  ──────────────────────────────────
  합계      1     지금 개발 100%

  [ 저장 ]

  ▸ 왜 나만 바꿀 수 있나요
```

- 숫자 입력·퍼센트 전부 **모노 + tabular-nums**
- 합계가 1이 아니면 저장 버튼 비활성 + 입력칸 옆에 사유 표시
- 기존 설명문(`남이 내 역할을 바꿀 수 있으면 그건 남의 점수를 바꾸는 일입니다…`)은
  **삭제하지 말고** disclosure 안으로

### 내 설정 > GitHub 계정

```
GitHub 계정

이 아이디로 올린 PR·리뷰가 내 기여도로 들어옵니다.

  [ minsu-dev                    ]  [ 저장 ]
  ● 연결됨 · PR 4건 · 마지막 18시간 전     ← --c-ok, 상태 라벨 동반

  ▸ 왜 나만 바꿀 수 있나요
```

### 프로젝트 > 팀원

이름순 고정. 점수 관련 정보 표시 금지.

```
팀원 3명

  김민수 (나)   개발 100%        ● 접속 중
  박지원        개발 60% · 디자인 40%
  이하늘        개발 70% · 기획 30%

  [ 이 프로젝트에서 나가기 ]   ← 보조 버튼, 위험색 아님
```

### 프로젝트 > 저장소 연결

지금 이 부분의 오류 표시는 **내용은 훌륭한데 위치가 나쁩니다.**
(`배달은 오지만 서버가 GitHub API를 부를 수 없습니다` — 이 정직함은 유지)

```
저장소 연결

  [ tjgksmf1012/teamflow-demo         ]  [ 연결 ]

  ┌ ⚠ 배달은 오지만 서버가 GitHub API를 부를 수 없습니다 ────┐
  │ 웹훅 본문만으로는 PR의 변경 파일을 알 수 없어             │
  │ diff 필터를 걸 수 없습니다.                              │
  │                                                          │
  │ 서버 관리자에게 GITHUB_APP_ID 와 개인키 설정을 요청하세요. │
  │                                                          │
  │ 배달 1건 · 마지막 18시간 전                               │
  │ [ 지난 활동 가져오기 ]                                    │
  └──────────────────────────────────────────────────────────┘
```
- 경고 박스는 `--c-unknown` 계열 (빨강 아님 — 사용자 잘못이 아니므로)
- 좌측 3px 세로선 + `--c-unknown-tint` 배경

### 프로젝트 > 위험 구역 (내 녹음 지우기)

서브내비에서 구분선 아래 분리. 유일하게 `--c-danger`를 쓰는 곳.

```
내 녹음 지우기

이 프로젝트에 남아 있는 내 목소리를 지웁니다.
개인정보 삭제 요청권(개인정보보호법 제36조)입니다.

  지워지는 것              남는 것
  · 내 목소리가 녹음된      · 회의록의 발화 텍스트
    원본 파일               · 칸반 업무와 GitHub 활동
  · 내 성문 데이터

  ▸ 기여도는 어떻게 되나요

  [ 내 녹음과 성문 지우기 ]   ← --c-danger, 확인 모달 필수
```
