## 로그인 — 1.0 화면이지만 빈 화면

**문제**: 383px 카드가 1280px 캔버스에 떠 있고 아래로 270px가 죽은 공간.
수직 중앙도 상단 정렬도 아닌 애매한 위치. 설명문이 `기여 / 기록까지`에서
어색하게 끊김(= `word-break: keep-all` 누락). 이 제품이 뭘 하는 물건인지
**아무것도 보여주지 않음.**

**새 구조 — 좌우 분할**

```
┌────────────────────────────┬──────────────────────────┐
│                            │                          │
│  회의에서 한 말이           │   TeamFlow               │
│  누구의 일이 되었는지        │                          │
│  거슬러 올라갑니다.          │   이메일  [           ]  │
│                            │   비밀번호 [           ]  │
│  ┌──────────────────────┐  │                          │
│  │ 0:01 김민수 · 결정    │  │   [ 로그인 ]             │
│  │ "로그인 API는 민수가   │  │   처음이신가요? 가입하기  │
│  │  금요일까지 만들기로"  │  │                          │
│  │        ↓ 근거 #1      │  │   비밀번호는 scrypt로     │
│  │ TASK-3 로그인 API 구현 │  │   해싱해 저장합니다.      │
│  │        ↓              │  │                          │
│  │ PR #17 · 병합됨       │  │                          │
│  └──────────────────────┘  │                          │
│   ↑ 제품의 핵심 사슬을      │                          │
│     정지 화면으로 보여줌     │                          │

        58%                            42%
```

- 좌측이 **히어로 = 이 제품의 주장**. 회의 발화 → 업무 → PR 사슬을 정지 화면으로.
  애니메이션 불필요. 이 그림 하나가 "우리가 뭘 하는 물건인지"를 말합니다.

- `word-break: keep-all` 필수

## 홈 — 2.1 화면 → 1.0

**문제**: 프로젝트 카드 → 시작하기 → 내 정보가 세로로 쌓임. 회의 상태를 4px 점
하나로만 구분. 정작 **녹음이 얼마나 온전한지**가 안 보임.

**변경**
1. **`내 정보`(사진·자기소개) 카드를 설정으로 이동.** 홈에 프로필 편집기가 있을 이유 없음.
2. **`시작하기`(프로젝트 생성/참가)를 헤더 우측 버튼 + 모달로.** 상시 노출 불필요.
3. 회의 행에 **트랙 리본 MD(14px)** 추가 — 이 화면에서 제일 중요한 정보.
4. 상태를 점 색깔이 아니라 **상태 칩(색 + 라벨)** 으로.

```
┌──────┬─────────────────────────────────────────────────────────────┐
│      │ TeamFlow 시연 프로젝트        [+ 새 프로젝트]  [회의 열기]   │
│ 레일 ├─────────────────────────────────────────────────────────────┤
│      │ 팀원 3 · 회의 5 · 검토할 회의 1                              │
│      │                                                             │
│      │ 검토 필요                                                   │
│      │  1주차 정기회의   09-01  ▓▓▓▓▓▓▓▓░░ 80%  [업무 후보 3건 검토]│
│      │                                                             │
│      │ 처리 중                                                     │
│      │  DB 스키마 확정   09-05  ▓▓▓▓▓▓▓▓▓▓ 처리 중…                │
│      │                                                             │
│      │ 실패                                                        │
│      │  중간발표 리허설  09-02  ▓▓▓░░░░░░░ 31%  [트랙 상태 보기]    │
│      │                                                             │
│      │ 완료                                                        │
│      │  제목 없는 회의   09-03  ▓▓▓▓▓▓▓▓▓▓ 100% [칸반 보기]         │
│      │  스프린트 2 계획  09-08  ░░░░░░░░░░ 녹음 전 [회의 로비로]     │
└──────┴─────────────────────────────────────────────────────────────┘
```

- 상태별 그룹핑. `검토 필요`가 항상 맨 위 — "다음에 뭘 해야 하는지"에 대한 답.
- 각 행 1줄. 설명 문장은 행동 버튼 라벨이 대신함.
- 리본 MD가 커버리지를 보여줌. 커버리지 낮으면 황토 구간이 보임.
- 날짜·퍼센트는 모노.

## 회의 로비 — 시그니처를 되살릴 것

**문제**: 참가자 트랙 다이어그램이 빈 상태에서 텍스트 목록으로 대체됨.
`김민수 — 아직 참가하지 않았습니다` × 3. 이 제품의 시각적 시그니처가 사라짐.

**변경**: **빈 상태에서도 축과 눈금을 그립니다.**

```
참가자 상태
       0분      7       13      20      27      33     40분
       ├───────┼───────┼───────┼───────┼───────┼───────┤
김민수 ┃░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░┃  대기 중
이하늘 ┃░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░┃  대기 중
박지원 ┃░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░┃  대기 중

아직 아무도 참가하지 않았습니다
```

빈 리본은 "여기에 곧 기록이 쌓인다"고 말합니다. 텍스트 목록은 아무 말도 안 합니다.

**동의 영역**: 두 개의 별도 동의(원본 음성 보관 / 목소리 특징 저장)는 지금 구조가
옳습니다. 유지하되 카드 높이만 압축.

> ⚠ 문서에 따르면 "목소리 특징 저장" 동의는 **받고 있지만 실제로 쓰는 코드가
> 아직 없습니다.** 쓰지 않는 데이터의 동의를 받는 건 그 자체로 문제입니다.
> 이번에 기능을 붙이지 않을 거라면 **이 동의 항목을 화면에서 빼는 것**을 권합니다.

## 녹음 — 내부 문서 노출 제거

**문제**: 화면 제목이 `녹음 생존율 테스트`. 부제가 `docs/09 실험 5 — …
모드 A(멀티트랙)의 성립 여부가 여기서 결정됩니다.` 하단에 `실험 조건: ① 화면 켜둠
② 화면 잠금 ③ 다른 앱 전환 ④ 통화 수신. 각각 10분씩 돌리세요.`

전부 개발자에게 하는 말이 사용자 화면에 노출된 것입니다.

**변경**
```
제목:  녹음 생존율 테스트  →  녹음
부제:  docs/09 실험 5 …    →  삭제
하단:  실험 조건 ①②③④    →  개발자 진단 패널로 이동 (기본 숨김,
                              ?debug=1 또는 설정의 개발자 옵션으로만 표시)
```

- `상태 / 준비 / 캡처 설정 확인 / 녹음` 4개 카드 → **1개 카드 안의 4단계 체크리스트**로 압축
- `autoGainControl이 안 꺼지면…` 같은 기술 설명은 disclosure로
- 녹음 중에는 **트랙 리본 LG가 실시간으로 자라는 것**을 보여주세요. 이 화면의 주인공.

## 통화 — 미완성 상태 정리

**문제**: 참가자 카드 + 마이크 상태만 있고 실질적으로 빈 화면.
빨간 오류 문구(`마이크를 열지 못했습니다`)가 실패처럼 보임 —
문서에 따르면 캡처 서버에 마이크가 없어서 나는 정상 동작인데도.

**변경**
- 마이크 미허용은 **오류(빨강)가 아니라 대기 상태**로 표현: `--c-unknown` + 행동 버튼
  `마이크 권한 허용하기`
- 참가자 타일을 그리드로 (1명이면 1칸, 3명이면 3칸)
- 각 타일에 실시간 입력 레벨 + **녹음 중 표시**(이 제품에선 통화보다 녹음이 중요)
- 하단 고정 컨트롤 바: `마이크 · 나가기 · 녹음 상태`

## 칸반 — 이번에 **더 나빠진** 화면

**문제**: 카드마다 이동 버튼 4~5개(`진행 중으로` `검토 중으로` `완료로` `지우기`)가
불규칙하게 줄바꿈. 카드 하나가 330px. 화면에 2.4장밖에 안 들어감.

**변경**: 버튼을 전부 없애고 **드래그 + 카드 메뉴 + 키보드**로.

```
┌─────────────────────────────┐
│ DB 스키마 정리          ⋯   │ ← ⋯ 메뉴: 이동/담당자/삭제
│ 박지원 · 2026-09-03         │
│ 💬 1주차 정기회의 · 근거 1   │ ← 인디고, 클릭 시 검토 화면으로
│ ↗ demo#17                   │
└─────────────────────────────┘
      약 96px
```

- 카드 높이 330px → **약 96px**. 화면에 8장 이상.
- 이동은 (1) 드래그, (2) `⋯` 메뉴, (3) 카드 포커스 후 `1`~`4` 키.
  **접근성 경로는 유지하되 버튼을 항상 펼쳐두지 않습니다.**
- 열 헤더에 개수. 열 내부만 스크롤.
- `회의에서 나온 업무 1 · PR로 이어진 업무 1 · 지연 0` 요약 줄은 유지 (모노).
- 회의 출처 칩은 인디고 = "근거 있음". 손으로 만든 업무는 칩 없음.
