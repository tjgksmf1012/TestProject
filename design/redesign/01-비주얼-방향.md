# 01 · 비주얼 방향 — "계측기(Instrument)"

---

## 1. 이 제품은 무엇처럼 생겨야 하는가

TeamFlow는 협업툴이 아닙니다. **측정 장치**입니다.

- 회의를 40분짜리 시간축 위에 기록합니다.
- 트랙이 끊긴 구간을 알고, 그걸 숨기지 않습니다.
- 기여도를 점수가 아니라 **구간**으로 말합니다.
- 모르는 것을 0으로 치지 않고 "모른다"고 말합니다.

그러니까 참고해야 할 물건은 Asana나 Notion이 아니라 **오실로스코프, 지진계,
오디오 편집기, 실험 노트**입니다. 이 제품의 미덕은 예쁨이 아니라 **정직한 계측**이고,
디자인이 그걸 말해야 합니다.

지금 화면은 "덜 만들어진 SaaS 대시보드"처럼 보입니다. 목표는
**"잘 만들어진 계측 기록기"**입니다.

---

## 2. 색 — 색은 오직 의미일 때만 쓴다

이 제품의 규칙은 "근거가 없으면 아무것도 주장하지 않는다"입니다.
그 규칙을 색 시스템에 그대로 옮깁니다.

> **인터페이스의 99%는 무채색 잉크다.
> 색은 "근거가 있다" 또는 "모른다" 두 경우에만 나타난다.**

이게 이번 아이덴티티의 핵심 원칙이고, 동시에 지금 화면의 가장 큰 문제
(청록색이 아무 의미 없이 아무 데나 칠해져 있는 것)에 대한 답입니다.

### 팔레트

| 역할 | 라이트 | 다크 | 언제 쓰나 |
|---|---|---|---|
| 잉크(본문) | `#15171E` | `#E9EBF2` | 사람이 말한 것, 제목, 본문 |
| 잉크 흐림 | `#5B6172` | `#9BA2B5` | 보조 설명, 메타 |
| 잉크 아주흐림 | `#878EA0` | `#6E7688` | 비필수 (여기만 있는 정보 금지) |
| 종이(페이지) | `#FAFAFB` | `#121319` | 페이지 배경 |
| 표면(카드) | `#FFFFFF` | `#191B23` | 올라온 면 |
| 가라앉음 | `#F0F1F4` | `#0E0F14` | 전사·코드·입력 우물 |
| 선 | `#E3E5EA` | `#2A2E3B` | 헤어라인 |
| **근거/행동 (인디고)** | `#3D3AAE` | `#8F8BF2` | **근거가 있는 것, 실행 가능한 것** |
| **모름 (황토)** | `#A8701A` | `#D6A24F` | **측정 못 한 것, 불확실** |
| 위험 | `#B02E2E` | `#E06A6A` | 되돌릴 수 없는 삭제만 |
| 정상 | `#1F6B45` | `#5FBF8C` | 시스템 연결 상태만 |

**청록(teal)은 전면 폐기합니다.** 기존 `#16605e` 계열은 한 곳도 남기지 마세요.

### 색 사용 금지 규칙

- 점수·기여도에 **초록/빨강을 쓰지 않습니다.** 높다고 초록, 낮다고 빨강은
  곧 순위표입니다.
- 결측·미측정은 **절대 빨강이 아닙니다.** 황토(`--unknown`)만 씁니다.
  녹음이 끊긴 건 그 사람 잘못이 아니기 때문입니다.
- 정보를 **색으로만** 전달하지 않습니다. 항상 텍스트 라벨이나 형태를 동반합니다.
  (회의 상태를 점 색깔로만 구분하는 현재 방식은 폐기)

## 3. 타이포 — 측정된 것은 모노, 말해진 것은 산세리프

이것이 이번 디자인의 **규칙이자 서명**입니다.

> **사람이 말한 것 → Pretendard.
> 기계가 잰 것 → 모노스페이스, tabular-nums.**

적용 대상 (전부 모노):
`32~52%` `0:47` `커버리지 42%` `근거 #5` `모르는 폭 20%p` `92%` `TASK-3`
`2026-09-11` `CYJN-7DNF` `#17` `4건` `3.7 화면`

이 규칙 하나로 화면이 즉시 "계측기"처럼 읽힙니다. 그리고 숫자가 세로로
정렬되기 때문에(tabular-nums) 표와 목록이 훨씬 읽기 쉬워집니다.

### 폰트 스택

```css
--font-sans: "Pretendard Variable", Pretendard, -apple-system,
             BlinkMacSystemFont, system-ui, sans-serif;
--font-display: "Wanted Sans Variable", "Wanted Sans",
                var(--font-sans);
--font-mono: "JetBrains Mono", "IBM Plex Mono", ui-monospace,
             "SF Mono", Consolas, monospace;
```

- **Pretendard** (OFL 1.1, 가변) — 본문·UI 전부
- **Wanted Sans** (OFL 1.1, 가변) — 화면 제목과 로고타입에만. 기하학적 형태라
  Pretendard와 대비가 생깁니다. **본문에는 쓰지 마세요.**
- **JetBrains Mono** — 측정값 전용. 숫자는 어차피 라틴 문자라 한글 혼용 문제 없음.

### 스케일

| 토큰 | 크기 | 행간 | 자간 | 용도 |
|---|---:|---:|---:|---|
| `--fs-11` | 11px | 1.4 | +0.06em | 마이크로 라벨 (대문자) |
| `--fs-12` | 12px | 1.5 | -0.005em | 메타, 캡션 |
| `--fs-13` | 13px | 1.55 | -0.005em | **조밀 UI 기본값** |
| `--fs-14` | 14px | 1.6 | -0.01em | 본문 |
| `--fs-16` | 16px | 1.6 | -0.01em | 강조 본문 |
| `--fs-20` | 20px | 1.4 | -0.015em | 섹션 제목 |
| `--fs-26` | 26px | 1.3 | -0.02em | 화면 제목 |
| `--fs-34` | 34px | 1.2 | -0.03em | 큰 수치 (기여도 구간) |
| `--fs-46` | 46px | 1.15 | -0.035em | 로그인 히어로만 |

한글 필수 규칙: `word-break: keep-all;` `overflow-wrap: break-word;`
(어절 단위로 끊어야 한국어가 읽힙니다. 지금 로그인 화면의 `기여 / 기록까지`
줄바꿈이 이걸 안 해서 생긴 문제입니다.)

## 4. 시그니처 — 트랙 리본(Track Ribbon)

문서에서 직접 "이 제품의 시각적 시그니처"라고 쓰신 참가자 트랙 다이어그램을
**제품 전체를 관통하는 구조 장치**로 승격시킵니다. 한 컴포넌트, 세 가지 크기.

```
LG (30px) — 회의 로비, 참가자별
 0분        7        13        20        27        33      40분
 ├─────────┼─────────┼─────────┼─────────┼─────────┼────────┤
 김민수  ████████████████████████████████████████████████  100%
 이하늘  ████████████████████░░░████████████████████████   98%
 박지원  ███████████░░░░░░░░░░░░░░░░████░░░░░░░░░░░█████   42%
                      ↑ 황토 빗금 = 측정 못 한 구간

MD (14px) — 홈의 회의 목록, 각 행 우측
 1주차 정기회의   ▓▓▓▓▓▓▓░░▓▓▓▓▓  80%   [업무 후보 3건 검토]

SM (6px) — 기여도, 각 사람의 확신 폭
 김민수  32~52%  ▓▓▓▓▓▓▓▓▓▓░░░░░
                  ↑ 채워진 만큼이 "아는 것"
```

**왜 이게 시그니처인가**: 다른 어떤 프로젝트 관리 도구도 "우리가 이 사람에 대해
얼마나 아는지"를 화면에 그리지 않습니다. TeamFlow만 그립니다.
그리고 이 리본이 홈·로비·기여도에 반복 등장하면, 사용자는 세 화면이 **같은
하나의 측정 결과**를 다른 배율로 보고 있다는 걸 자연히 이해하게 됩니다.

**빈 상태에서도 축과 눈금은 그립니다.** 지금처럼 텍스트 목록으로 대체하지 마세요.
빈 리본은 "여기에 곧 기록이 쌓인다"고 말하지만, 텍스트 목록은 아무 말도 안 합니다.

## 5. 레이아웃 — 페이지가 아니라 판(pane)

가장 큰 변화입니다.

```
┌──────┬──────────────────────────────────────────────┐
│      │  화면 제목                        [주 행동]   │  ← 고정 헤더
│ 레일 ├──────────────────────────────────────────────┤
│      │                                              │
│ 홈   │                                              │
│ 칸반 │        작업 영역 (여기만 스크롤)              │
│ 기여 │                                              │
│ 설정 │                                              │
│      │                                              │
│      │                                              │
│ ──── │                                              │
│ 회의 │                                              │
│  ○   │                                              │
│  ●   │                                              │
└──────┴──────────────────────────────────────────────┘
   72px                    나머지
```

**핵심 규칙: `body`는 스크롤하지 않습니다.** 앱 셸은 `height: 100dvh`로 고정하고,
스크롤은 안쪽 판이 각자 담당합니다. 이 한 줄이 §00에서 측정한 4.6 화면 문제를
구조적으로 없앱니다.

좌측 레일은 72px 아이콘 레일(라벨은 아이콘 아래 11px)로, 예전 사이드바(256px)보다
좁습니다. 회의 목록은 레일 안이 아니라 **홈 화면 안**에 있어야 합니다 —
모든 화면에서 회의 목록을 볼 이유가 없습니다.

## 6. 밀도와 여백

지금 화면은 **여백은 많은데 정보는 적습니다**. 계측기는 반대여야 합니다.

- 카드 안쪽 여백: `24px` → `16px`
- 목록 행 높이: 최소 `36px`, 조밀 모드 `32px`
- 카드 사이 간격: `24px` → `12px`
- 최대 본문 폭: `72ch` (지금은 카드가 1280px 전폭이라 한 줄이 너무 깁니다)
- 설명문은 **기본 접힘**. `▸ 이건 왜 이런가요` 형태의 disclosure로.
  지금처럼 항상 펼쳐두면 화면의 절반이 설명문이 됩니다.

## 7. 다크모드 — 반전이 아니라 별도 설계

갤러리에 "토큰의 원시값만 뒤집어 만든 다크"라고 적혀 있는데, 이걸 고칩니다.

- 순수 검정(`#000`) 금지. 베이스 명도 **8~12%** (`#121319`).
- 높이(elevation)는 **그림자가 아니라 명도 +4~8%** 로 표현.
  `#121319`(페이지) → `#191B23`(카드) → `#21242E`(팝오버)
- 액센트는 **밝히고 채도를 낮춥니다**: `#3D3AAE` → `#8F8BF2`.
  라이트의 인디고를 그대로 쓰면 어두운 배경에서 탁하게 가라앉습니다.
- 본문 텍스트에 순백(`#FFF`) 금지 — 헤일레이션이 생깁니다. `#E9EBF2`.
- 황토도 재보정: `#A8701A` → `#D6A24F`.

## 8. 모션

계측기는 요란하지 않습니다.

- 지속시간 `120~200ms`, easing `cubic-bezier(0.2, 0, 0, 1)`
- 상태 전환(칸반 카드 이동, 후보 승인)에만 씁니다. 장식 애니메이션 금지.
- 트랙 리본이 처음 그려질 때만 좌→우 `320ms` 스윕 1회. **이게 유일한 연출입니다.**
- `prefers-reduced-motion: reduce`에서 전부 0ms.

## 9. 이 방향이 기존 원칙과 어떻게 맞물리나

| 제품이 지키기로 한 것 | 디자인이 그걸 어떻게 표현하나 |
|---|---|
| 순위·리더보드 없음 | 같은 축에 사람을 세우지 않음. 각자 자기 행의 리본. 이름순 고정 |
| 단일 점수 없음 | 구간을 모노 대형(`--fs-34`)으로, 리본이 확신 폭을 그림 |
| 결측 ≠ 0 | 황토는 **오직** 이 의미로만 존재하는 색. 빨강 아님 |
| 시스템이 확정 안 함 | 확정 폼은 인디고(행동), 시스템 값은 무채색(참고) |
| 근거 없으면 승인 불가 | 근거 칩이 있어야만 승인 버튼이 인디고가 됨. 없으면 무채색 비활성 |

색이 의미를 갖는다는 규칙 덕분에, **화면을 흑백으로 인쇄해도 무엇이 근거 있고
무엇이 미측정인지 구분됩니다** — 형태와 라벨이 색과 함께 가기 때문입니다.
이건 접근성이자, 이 제품의 주장이기도 합니다.
