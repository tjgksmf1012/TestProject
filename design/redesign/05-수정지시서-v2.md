# P0 — 반드시 고칠 것

## F1. 기여도 레인이 막대그래프가 되어 있다 ⚠️ 최우선

### 현상
세 사람의 레인이 **같은 x(347px)에서 시작해, 같은 폭(285px)으로, 세로로 쌓여** 있고
**눈금이 없다.** 눈금 없는 동일 축 막대 3개 = 길이 비교표 = 순위표다.

색도 뒤집혔다. 채운 구간이 `#000`(다크에서 `#fff`)이고 사선은 얇고 옅다.
화면에서 가장 강한 요소가 "측정된 양", 가장 약한 요소가 "모르는 폭"이다. 의도의 정반대.

### 고칠 것

**(1) 색을 되돌린다**

```css
.lane__known   { background: var(--signal); }   /* 검정/흰색 금지 */
.lane__unknown {
  background-color: var(--unknown-tint-2);
  background-image: repeating-linear-gradient(
    -45deg, transparent 0 4px, var(--unknown) 4px 6px);  /* 선을 2px로 굵게 */
}
```

사선 대비를 현재의 약 3배로. 축소 캡처에서도 사선이 보여야 한다.

**(2) 눈금을 반드시 넣는다**

레인 위에 `0 / 25 / 50 / 75 / 100` mono 눈금. 눈금이 없으면 절대값을 못 읽고
상대 비교만 남는다.

**(3) 같은 축 비교를 물리적으로 막는다 — 아래 중 하나 선택**

- **A안(권장)**: 사람마다 개별 카드로 감싸고 카드 사이에 `--sp-6` 간격.
  각 카드가 자기 눈금을 갖는다
- **B안**: 레인의 좌우 여백을 사람마다 다르게 줘서 시작점을 어긋나게 한다

**(4) 하단 확정 바의 단일 점수를 없앤다**

지금 `김민수 42.2 / 박지원 24.9 / 이하늘 33.0`이 입력란에 **미리 채워져** 있다.
구간으로 말하기로 해놓고 마지막에 시스템이 단일 점수를 주는 셈이다.

- 입력란 기본값을 **비운다**
- placeholder에 시스템 **구간**을 표시: `32~52 (시스템 추정)`
- 확정 버튼은 세 칸이 다 채워졌을 때만 활성

### 검수 기준
이 화면을 처음 본 사람이 **"누가 1등이야?"가 아니라 "왜 이렇게 모르는 게 많아?"**라고
물으면 통과다.

## F2. 셸이 두 개다

### 현상
- `11-녹음`, `12-통화` → **옛날 중앙 상단 내비** (홈/칸반/기여도/설정이 화면 중앙에)

같은 앱인데 껍데기가 두 종류다. 이 두 화면이 리디자인에서 누락됐다.

**통화 화면은 추가로**: 참가자 1명일 때 500px가 비어 있다.
참가자 타일을 크게 키우고 하단 중앙에 고정 컨트롤 바(마이크 토글 / 녹음 인디케이터 / 나가기)를 둔다.

# P1 — 눈에 띄는 것

## F3. 값 없는 레인을 그리지 않는다

### 현상
- 홈: 회의 5개 중 **4개가 빈 회색 막대 + `–`**
- 로비: 3명 전부 빈 회색 막대 (아직 아무도 참가 안 함)

레인은 "아는 것 / 모르는 것"을 말하는 문법이다. 잴 게 없을 때 빈 막대를 그리면
문법이 무너지고, 값 없는 요소가 목록의 시각적 무게중심을 차지한다.

### 고칠 것
```
if (coverage == null) → 레인을 렌더하지 않는다
                        그 자리에 상태 텍스트만: "녹음 전" / "처리 중"
```
로비도 동일. 참가 전에는 레인 대신 `아직 참가하지 않았습니다`만.

## F4. 홈의 그룹 헤더가 항목보다 많다

### 현상
`검토 필요 1 / 처리 중 1 / 처리 실패 1 / 녹음 전 1 / 검토 완료 1`
— 그룹당 항목이 1개면 그룹핑이 아니다. 헤더 5개가 목록 높이의 절반을 먹는다.

게다가 날짜가 `09-01 → 09-05 → 09-02 → 09-08 → 09-03`으로 뒤죽박죽이라
시간 감각이 사라졌다.

### 고칠 것
- **"검토 필요"만** 상단에 별도 블록으로 분리 (사람이 할 일이 남은 유일한 상태)
- 나머지는 **그룹 없이 날짜 내림차순 한 덩어리**
- 그룹 헤더는 항목이 2개 이상일 때만 렌더

# P2 — 마감

## F6. 홈 우측 정렬이 깨짐
"처리 중입니다 — 끝나면…" 텍스트가 x=1264까지 뻗어 버튼 열을 침범한다.
버튼 우측 끝도 1264~1268px로 제각각.

→ 그리드를 `[상태 120px] [제목 1fr] [날짜 100px] [레인 260px] [수치 60px] [액션 140px]`로
고정하고, 설명 텍스트는 액션 열을 침범하지 못하게 `overflow: hidden` + 말줄임.

## F7. 날짜 입력이 미국식
`mm/dd/yyyy` 네이티브 date input. 한국 서비스인데 형식이 미국식이다.
→ shadcn `DatePicker` 또는 `Calendar` 컴포넌트. 표시는 `2026-09-04` 또는 `9월 4일`.

## F8. 네이티브 `<select>`
담당자 드롭다운이 브라우저 기본 select다. 나머지 UI와 톤이 안 맞는다.
→ shadcn `Select`.

## F9. primary 버튼이 두 개 나란히
홈 우상단 `+ 새 프로젝트`(secondary처럼 보이지만 흰 배경 강조) + `회의 열기`(인디고).
→ `회의 열기`만 primary. `+ 새 프로젝트`는 ghost 또는 secondary.

## F10. "3건 모두 처리하고 제출" 일괄 버튼
검토 화면 우상단. **"사람이 하나씩 승인한다"는 제품의 안전장치와 정면으로 충돌한다.**
심사에서 "이러면 사람 검토가 무슨 의미냐"는 질문을 받기 딱 좋은 자리다.

→ 제거하거나, 라벨을 `검토 끝내기`로 바꾸고 **모든 후보가 개별 처리된 뒤에만** 활성화.
   일괄 승인 기능은 만들지 않는다.

## F11. 설정 사이드바가 2겹
앱 사이드바(72px) + 설정 사이드바(200px). 내용 영역이 그만큼 줄어든다.
→ 설정 내비를 상단 탭으로. 폭 200px 회수.

## F12. 다크 모드에서 레인이 가장 밝다
다크 홈에서 커버리지 막대(흰색)가 회의 제목보다 눈에 띈다.
→ F1의 색 수정으로 함께 해결됨. 다크에서 `--signal: #6F5CE8` 사용.

## F13. 로그인 우측 폼이 위로 치우침
폼이 y=250~540에 몰려 있고 아래 250px가 빈다.
→ 수직 중앙 정렬. 좌측 일러스트와 시각 중심을 맞춘다.
